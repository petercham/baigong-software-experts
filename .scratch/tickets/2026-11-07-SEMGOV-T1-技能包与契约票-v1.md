# claim-commitment-governance · 主张—承诺治理

**定位**：本技能只在构建期提供主张—来源—验证—外发语义契约；不替代 deep-research 的调研流程，不替代 object-audit 的审计流程，不执行任何业务判断。

## 触发与不触发

- 触发：产出或修订 PRD、需求解析、工作票、回执、回流件、QA 判词、交付汇总、对外呈报/函件；标注来源权威性、证据标签、承诺状态、假设冻结、异议窗、范围或验收口径、替代实现、验证等级、降级/豁免、QA 完成状态、外发授权。
- 不触发：纯代码调试、纯排版、无主张/承诺的简单事实快答、已由 deep-research 完成的调研本体。

## 契约总则

1. 一句一主张，一句一 `claim` 行。
2. 每行必须写明 `claim_type`、`source_kind`、`evidence_tag`、`authority`、`status`、`external_effect`。
3. `linked_artifacts` 至少包含一个可解析来源引用或关联工件引用。
4. 内部接受不等于外部确认。
5. 内部冻结只限内部，带时效，不得外溢为默认认可。
6. 替代实现、占位、降级必须写明要求等级、实际等级、豁免与回退判据。
7. 外发件必须先过事实审查、承诺审查与人类授权。
8. 机器只校验结构、闭集与引用；不判业务真伪，不作法律/合同解释。
9. 状态只增不改，历史不回写。
10. 本技能不建完整催办台账；需要完整台账时另案立项。

**可照录文本块**

```markdown
# 10-contract · 主张—来源—验证—外发契约

## 1. 主张行八字段＋可选二字段

| 字段 | 闭集／要求 |
|---|---|
| `claim_id` | 稳定标识；同一主张跨件复用同一 ID |
| `claim` | 一句一主张，不得复合 |
| `claim_type` | `fact` / `requirement` / `commitment` / `assumption` / `authorization` / `measurement` / `risk` |
| `source_kind` | `external_authoritative` / `external_input` / `baseline` / `research` / `measurement` / `internal_assumption` |
| `evidence_tag` | `FACT` / `INFERENCE` / `JUDGMENT` / `UNKNOWN` / `STALE` |
| `authority` | `binding` / `consultative` / `internal_only` / `unverified` |
| `status` | `draft` / `accepted` / `frozen_assumption` / `external_pending` / `external_confirmed` / `superseded` / `rejected` |
| `external_effect` | `none` / `internal_only` / `outbound_pending` / `outbound_authorized` |
| `approver` | 批准人或批准记录引用；无批准写 `none` |
| `expiry` | 时效；无时效写 `none` |
| `linked_artifacts` | 至少一个可解析来源引用或关联工件引用 |
| `metric_key`（可选） | 跨表一致性键 |
| `metric_value`（可选） | 与 `metric_key` 配套的值 |

`linked_artifacts` 同时承载来源引用与关联工件引用；每条主张至少一个可解析来源引用。`source_kind=measurement` 时，`evidence_tag` 使用 `FACT`，并在 `linked_artifacts` 指向实测读数件。

## 2. 验证块

| 字段 | 闭集／要求 |
|---|---|
| `required_level` | `mock` / `contract` / `integration` / `production` / `nonfunctional` |
| `actual_level` | 同上，另允许 `unverified` |
| `exemption` | `none` / `partial` / `full`；非 `none` 时必填 `approver`、`reason`、`scope`、`expiry` |
| `qa_result` | `pending` / `passed_at_actual` / `passed_with_exemption` / `failed` / `blocked` |

降级必须带：`original_requirement`、`difference`、`approver`、`fallback_criterion`、`reopen_trigger`。

## 3. 外发门

| 字段 | 闭集／要求 |
|---|---|
| `outbound_type` | `clarification_request` / `commitment` / `acceptance` / `risk_notice` / `report` |
| `claims` | 引用本件主张的 `claim_id` 列表 |
| `fact_review` | 事实审查结论与审查人 |
| `commitment_review` | 承诺审查结论与审查人 |
| `authorization` | 人类授权记录引用 |
| `send_channel` | `draft_only` / `approved_send` |

`send_channel=approved_send` 只表示人类已授权发送，不表示系统执行发送；实际发送动作在系统外，由人类执行。

## 4. 状态语义硬规则

1. `accepted` ≠ `external_confirmed`；内部接受不得写成外部确认。
2. `frozen_assumption` 只限内部、带时效，不得外溢为默认认可。
3. `external_pending` 超时只触发复核／升级，**不自动**变 `external_confirmed`。
4. `outbound_authorized` **只能**由人类闸设置。
5. `superseded` 保留旧行，不删除、不改写。
6. QA 按 `actual_level` 通过，**不回写** `required_level`。

## 5. 人工闸七类

以下事项必须人类拍板：

1. 外部权威来源确认。
2. 外发授权。
3. 需求降级／豁免批准。
4. 范围或验收口径变更。
5. 法律／合同／责任解释。
6. 外发动作本身。
7. 是否将沉默视为认可；**默认一律不算**。

## 6. 禁止工具自决八条

1. 不得从文本自行推断权威性。
2. 不得把 `UNKNOWN`／`INFERENCE` 自动升格为 `FACT`。
3. 不得把内部冻结自动转为外部确认。
4. 不得自动降级验证等级。
5. 不得自动发送任何外发件。
6. 不得自动生成对外承诺。
7. 不得自动判定业务事实真伪。
8. 不得自动改写历史主张状态。

## 7. deep-research 标签消费映射

| deep-research 标签 | 本契约 `evidence_tag` |
|---|---|
| `FACT` | `FACT` |
| `INFERENCE` | `INFERENCE` |
| `JUDGMENT` | `JUDGMENT` |
| `UNKNOWN` | `UNKNOWN` |
| `STALE` | `STALE` |

本技能只消费 deep-research 的标签与来源池，不重做检索，不把研究结论升格为承诺。
```

## 1. 人工闸七类

以下事项必须人类拍板：

2. 外发授权。
3. 需求降级／豁免批准。

## 2. 脚本闸 R1–R12

| 编号 | 判据 |
|---|---|
| R1 | 字段闭集合规：`claim_type`、`source_kind`、`evidence_tag`、`authority`、`status`、`external_effect`、`required_level`、`actual_level`、`exemption`、`qa_result`、`outbound_type`、`send_channel` 均在闭集内。 |
| R2 | 引用闭合：`linked_artifacts` 至少一项可解析；来源引用不存在即失败。 |
| R3 | 跨件 `claim_id` 一致：PRD／票／回流／QA／外发件引用的 `claim_id` 集合一致，不得出现未登记主张。 |
| R4 | 验证等级对账：`actual_level` 不低于 `required_level`，或有已批准豁免。 |
| R5 | 豁免批准完整：非 `none` 的 `exemption` 必须有 `approver`、`reason`、`scope`、`expiry`。 |
| R6 | 外发授权在位：`external_effect=outbound_authorized` 或 `send_channel=approved_send` 必须有人类授权记录。 |
| R7 | 证据强度匹配：外发承重主张不得为 `UNKNOWN`／`STALE` 配 `authority=binding`。 |
| R8 | 内外防火墙：外发件不得引用 `status=frozen_assumption` 的主张作为外部确认。 |
| R9 | 占位／强断言 lint：外发件不得有未登记占位词；强断言必须挂 `claim_id`。 |
| R10 | 历史不可回写：`superseded` 旧行保留，不得覆盖或删除。 |
| R11 | 跨表 metric 一致：同一 `metric_key` 在不同工件的 `metric_value` 必须相同；时点类 metric 同时比对时点。 |
| R12 | 完备性断言有计数：出现“清零／全部／无遗漏／完备”类断言时，必须附计数与枚举依据；计数不为零或枚举不闭合即失败。 |

## 3. `semantic-governance.py` 三子命令调用契约

脚本本体、闭集配置与夹具属 SEMGOV-T2；本文件只定义调用契约与判据归属。

- `validate --artifact <file> --kind <artifact-kind>`
  - 用途：单件字段闭集、必填面、状态语义、引用闭合。
  - 通过：exit 0；任一结构违例：exit≠0 并输出违例字段与规则号。
- `reconcile --artifacts <file-list>`
  - 用途：跨件 `claim_id`、`metric_key`、状态一致性。
  - 通过：exit 0；跨件不一致：exit≠0 并输出差异集。
- `gate-outbound --artifact <file>`
  - 用途：外发前事实、承诺、授权、证据强度、内外防火墙总检。
  - 通过：exit 0；任一外发门条件不满足：exit≠0，且不得把工件标为可外发。

## 4. 负样本闸七类

1. `required_level=production`／`actual_level=mock`／`exemption=none`。
2. 子集实现被声明为全量。
3. 有书面批准但无实测读数。
4. 降级无 `fallback_criterion`／无 `reopen_trigger`。
5. 外发件把 `UNKNOWN` 写成 `authority=binding`。
6. 内部 `frozen_assumption` 进入外部验收。
7. 完备性／清零断言无计数与枚举支撑。
