# 沿革（v1.0 → v3.2）

> 史实锚：版本史实只增不改；主文件不载沿革（省常驻体量）。

- **v1.0（2026-10-13）**＝三方（执行者／审计者／决策者）。
- **v2.0（2026-10-20，决策者认可）**＝增设接口人席，三方条款全量保留重排。
- **v2.1（2026-10-20，决策者纠正）**＝增设部署形态：跨后端下接口是「总线协议」不是 Agent；帽子制降级为形态 C 兜底。
- **v2.2（2026-10-20，决策者再纠）**＝接口不是第三席位，是两个职能：主理人＝轮间接口（横向），审计者＝执行端接口（纵向）；可合并。不可合并＝生产↔判定；不可穿透＝讨论↔执行。隔离实质＝信息暴露面。
- **v2.3（2026-10-20，决策者三纠）**＝主理人决策权非绝对：只有 L2 执行面决策权；L0 本体层人类独占；口诀「改值域＝人类·改取值＝提案·改落点＝AI」。
- **v2.4（2026-10-22，决策者拍）**＝单写者原则：执行者＝唯一落盘出口，其余席位永无写盘权（无例外）；内容交主理人分发；执行者落盘前自读治理规范。
- **v3.0（2026-10-22，皮总令）**＝三处改：①席位模型从"四席"改**权限分级**（实践中读权席位 ≥6 类：主理人/审计者/执行者/顾问/研究席/QA 子代理——席位表改开放清单，新增席位声明三件：读域/产出形态/对谁）；②新增**文档交接机制**（需要交接的上下文转成自包含 md 交接件＝跨权限角色协作介质；两盘区分：治理盘唯一写不变，交接区各席可写自己的件·append-only）；③体量瘦身（34.7 KB 单文件 → 主文件骨架＋references/ 六分件平铺一层；沿革移入本件）。执行者唯一写盘（v2.4）不变且仍独立成席。
- **v3.1（2026-10-22，皮总论定）**＝部署架构原则成文：①**席位不绑模型**——席位＝权限与读域定义，逐席独立配后端模型是目标形态（性价比＋避免同模缺陷；RouteMoA arXiv:2601.18130 成本 −89.8% 印证方向；generator-and-judge："a model is a poor critic of its own blind spots"）；当前 UI 不支持逐席配模型，按写盘权限最小化拆分＝过渡妥协而非目标；②**交接只认盘面不认智能体内部**——上下文是模型内部状态，跨模型传不过去；盘面 md 交接＝异质模型时代唯一模型无关的协作介质（不是形态 A 的妥协，是前提条件）。
- **v3.2（2026-10-22，皮总令）**＝**改名 `tri-collab` → `multi-collab`**：数数的名字必过时（"tri" 自 v2.0 即失实；v3.0 后席位＝开放清单）；"multi" 与项目名 multi-agent-collab-skillpack 对齐。旧名作废；外部指针（object-audit）与技能包 deliverables 同步改向；本沿革与过程记录中的旧名＝史实锚不改。
