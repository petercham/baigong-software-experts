# 审计骨架（四问的操作定义·取证纪律）

> 出处：本地约定（本器归纳）。通用部分与业界范式对齐处在文末标注。

## 一、四问的操作化

### 问净（干净度）
1. 列对象内的「专有名词清单」：项目名／号段／票号／判词号／日期／人名／项目路径。
2. 逐个 grep 计数（`grep -oE` 逐模式，不用肉眼估）。
3. 命中＞0 → 判「不干净」，并给出三路处置：删（违反流水类）／改写（保道理去编号·标「本地约定」）／移出到项目绑定层（项目值类）。
4. 再查重复真源：同一规则是否在多处各写一遍（指针可以，正文重复不行）。

### 问实（契约闭环）
1. 把对象声明的能力逐条列成主张表。
2. 每条主张找一个「它能被验的产物」：命令／文件／输出／判据。
3. 找不到＝未落地（声明的能力不能落地）。指向不存在的文件＝悬空指针（比缺失更坏：看起来有）。
4. 抽一条做**负样本**：故意违反该约束，看防线是否真会咬（不咬＝防线不存在）。

### 问测（可测性）
1. 每条验收判据问：能不能写出一个「退出码 0/1」或一条可逐项打勾的核验动作。
2. 出现「良好／合理／完善／大幅提升／基本可用」→ 判不可测。
3. 判据须成对：正样本＋负样本；只写正样本的判据等于没有防线。
4. 判据面须含**本体面**（对象本身达没达标），不能只有治理面（计数/指针/体量）——治理面全绿而本体失败是最常见的假绿。

### 问界（边界与容量）
1. 越权：生产方是否兼判定方；AI 角色是否被授予了本应人类独占的拍板权；审计是否可自行放宽判据。
2. 容量：行数/字节/条目数是否有上限且当前未超；无上限＝单向棘轮（只增不减）。
3. 指针：所有引用对象存在（悬空＝缺陷）；引用方向单向（A 指 B 则 B 不再指 A 的正文）。

## 二、取证纪律

- **逐模式计数，不估计**：报告里的每个数带命令与口径（字符 vs 字节、含不含 self）。
- **数字与语义分栏**：可复算的放「复算」栏，不可复算的写清理由放「采信」栏。
- **宣称时点晚于产物终态**：说「零标记/首跑即绿」须附复跑时点与命令。
- **只认指向本对象的证据**：别的检查器 PASS 不能移植（嫁接＝假绿）。
- **哈希复算用 bytes 口径**：文本模式读会把 CRLF 归一，hash 必歪。
- **比对基准要申报来源与提取方式**：截行首、过滤条件写清，防「假绿根因」。

### 引证失效的七个类型（多席交叉核实证·修法不同·缺一即漏）

| 类型 | 长什么样 | 能否靠逻辑自查 |
|---|---|---|
| 漏查 | 该有的出处没有 | 能（对照覆盖清单） |
| **局部代全** | 把「我查过的那几页没有」说成「官方／业界没有」；把「我见过的证据」当成「该问题的全部证据」。结论必须限定在「我查过的那几页」 | **不能** |
| **用漏** | 证据**读到了却没进论证**（「我读过但没用」）；文件里无痕迹，覆盖清单也显示"已查"，只有交叉核验能撞出 | **不能** |
| **升格** | `SHOULD` 写成 `MUST`；「多数」写成「一律」；「建议」写成「官方规定」；「有条件成立」写成「无条件成立」 | **不能** |
| **归属错** | A 的判据挂到 B 头上 | **不能** |
| 越证 | 一条证据同时撑两件不同的事（证据载体里根本没有那一维） | 能（问「载体里有没有那一维」） |
| 并列错 | 反向证据并列成同向（如「过粗」与「过细」两种反模式） | 能（方向相反即塌） |

**最要命的一条**：局部代全、用漏、升格、归属错**逻辑自查查不出来**——错的那句往往比对的更强、更顺、更自洽。**「读一遍觉得通顺」不构成证据；通顺恰恰是升格错的典型特征。**

**但大部分可以机检（双向强词扫描·本轮 4/4 命中）**：

| 扫法 | 判法 | 抓什么 |
|---|---|---|
| **强词法** | 正文出现 一律／所有／全部／唯一／不得／必须／只能 → 原文须有对应强度；找不到即判**升格** | 升格，**且它同时是一致性扫描器**（曾命中「一律选五维」与「PMBOK 走全矩阵」的跨段自相矛盾） |
| **弱词法**（强词法的另一半） | 原文有 generally／often／SHOULD 等 hedge，引用时把 hedge 丢了 → **也是升格**，但一个强词都没有，**强词法抓不到** | 隐性升格 |
| **URL 反查** | 同一 URL 支撑**分属不同对象**的结论 → 归属错嫌疑（按「对象」判，不按「主体」判，否则会漏） | 归属错 |

**扫不到的只剩两种**：**用漏**（证据在文件里但没进论证）、**跨段矛盾**（需人工对照语义）——这两类只能靠交叉核验。

**结论句的强度必须与所查范围对齐**：「业界一律如此」须穷举到业界；只核了 N 家就写「所核 N 家均如此」。**宁可写窄，不可写满**——写满了对方只要举一个反例就整句作废，写窄了反例只是补充。

**跨基准不借背书**：A 处的实测不能为 B 处的数字作证（如「上下文变长会降精度」的实测不为「5k 这个具体阈值」背书）。只支持方向，就是只支持方向。

**页序也是证据**：先立前提、后认代价，与先认代价、后找补，说服力不同。引多段同源原文时保留原书顺序，不要按论证需要重排。

**消息层污染（文件级审计的盲区）**：升格错可能只发生在**席间传话**里，交付文件零命中——错的引文在传播链上走过一遭却没落进任何交付物，日后被人「记住」再写进文件时已无迹可查。**治法是机制不是自觉**：**跨人传递的判据句，要么落盘（可回查），要么显式标「未落盘」**。不要落成"要求自觉报备"——**自觉不可审计，落盘可以**；报备只能让损失可追，双向核验才让它被抓到。

## 三、业界对齐声明

| 本器条款 | 出处档位 | 业界对应 |
|---|---|---|
| 生产方不得兼判定方 | 业界通识 | 职责分离（separation of duties）·审计独立性 |
| 正负样本成对 | 业界范式 | 测试驱动／property-based testing 的负样本思想 |
| 指针不复制正文 | 业界范式 | 单一真源（SSOT）·DRY |
| 可测判据 | 业界范式 | 验收测试／Definition of Done |
| 本体面＋治理面双面 | 本地约定 | 与「vanity metrics」批判同构 |
| 逐条可退＋总量有顶 | 本地约定 | 与规则集生命周期管理（sunset/expiry）同构 |
