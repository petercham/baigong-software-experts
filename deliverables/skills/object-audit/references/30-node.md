# 节点对象审计（流程/工序节点）

> 出处：N1–N6＝本地约定（节点契约归纳）；「输入输出 schema＋契约先行」＝业界范式（interface contract／schema-first）；「死端检测」＝业界范式（dead-end/可达性分析）。

## N1 契约完整（缺一即不合格）

| 要素 | 判法 |
|---|---|
| 输入 | 显式列出字段与 schema；无 schema＝下游只能猜 |
| 输出 | 同上；输出字段必须覆盖下游节点的输入需求（拆链＝断链） |
| 判据 | 节点自带的「什么算做完」——须可判真假（N3） |
| 门禁 | 什么条件拦住（fail-closed/clamp/放行），拦住后谁处理 |

## N2 拓扑完整

| # | 测项 | 判法 |
|---|---|---|
| N2-1 | 无死端 | 每节点至少一条出边（终节点除外）；无出边且非终＝阻塞 |
| N2-2 | 无孤儿 | 每节点至少一条入边（入口节点除外） |
| N2-3 | 无环（或显式声明为环） | 非迭代节点成环＝跑不完 |
| N2-4 | 依赖可解析 | 引用的共享件/上游字段存在；跨层引用方向单向 |

## N3 判据可测性

- 每条判据能落成：字段校验／计数阈值／枚举比较／一段可复跑检查。
- 「合格/优秀/自然/流畅」类词＝不可测（除非附可操作定义：谁来判、判几档、样例）。
- 判据成对：正例＋反例各至少一个。

## N4 运行成本与失败语义

| # | 测项 | 判法 |
|---|---|---|
| N4-1 | 成本可见 | 每节点的模型调用/外部依赖列明；无上限的循环/重试＝缺陷 |
| N4-2 | 失败语义分层 | 失败三分：可重试（网络）／须改输入（契约不满足）／须人判（质量）。三合一＝排障黑洞 |
| N4-3 | 幂等或可续 | 重跑是否产生重复副作用；不幂等须写清恢复方式 |

## N5 体量红线

- 单节点判据条数有上限（超限＝该拆）；节点总数有上限（超限＝图该分层）。
- 上限值由项目 profile 注入（本器不写死数字）。

## N6 节点命名与语义

- 节点名＝动作（产出什么），不是名词堆积；名不副实＝下游误用。
- 同一语义不得两个节点（重复真源）；同节点不得两套判据。

## 判定要点

- N1（契约缺输出/判据）＝**阻断**：节点产不出可判的产物。
- N2-1/N2-3（死端/非声明成环）＝**阻断**：图跑不完。
- N3 不可测＝**关注**（必带「补可操作定义」核验动作）。
- N4 缺成本上限＝**关注**；N5 超限＝**可延后**（带拆分触发条件）。
