# 装配段（索引件 → 装配面）

> **归属**：`bundle-assembly-registration` 的第 1–4 步细则（入口条件·取源·产物核对·幂等与漂移停）。
> **边界**：复制实现、同步账本键集、状态对账、准入闸、退出码闭集的真源＝`object-build/references/60-publish.md`。本件只指路径，不复述其正文。

## 一、装配是什么，为什么要自研

平台侧的组件清单不支持**组件层跨仓取源**——三条限制各自独立堵死：

| 限制 | 堵的是什么 |
|---|---|
| 市场根包含约束（marketplace-root containment） | 组件必须活在包根目录树内，跨仓引用出界 |
| 缓存整包快照 | 平台按整包取快照，不按组件分别解析 ref |
| 符号链接防逃逸 | 用软链把外部仓挂进包内会被判逃逸并拒绝 |

结论：**装配在仓外自己做**，产物是一个「组件已就位、可直接注册」的完整包目录。这是本地约定（显式标注）——平台限制为实测，自研装配是本工序的应对。

## 二、索引件字段（五键＋元信息）

| 键 | 含义 | 取值约束 |
|---|---|---|
| `bundle.name` | 包名 | 非空；与装配面目录名同源 |
| `bundle.version` | 包版本 | 每次变必 bump；与包主文件同源 |
| `component` | 组件名 | 非空、包内唯一 |
| `repo` | 组件源仓 | **相对 bundle 源仓根**的并列目录路径 |
| `ref` | 锁定的版本引用 | 不可变 tag 或 commit；**不得**用分支名或 HEAD |
| `ref_kind` | 引用种类 | `tag` 或 `commit`，须与 `ref` 形态一致 |
| `path` | 组件在源仓内的路径 | 相对源仓根 |
| `target` | 组件在装配面内的落点 | 相对装配面根；与包主文件的组件引用对齐 |

缺任一键 ⇒ 装配器按用法错停（先于任何写）。

## 三、五条取源纪律

| # | 纪律 | 机检／违约后果 |
|---|---|---|
| ① | **semver bump**：包内容一变，版本号必 bump | 版本值与包主文件比对；未 bump ⇒ 第 5 步停手 |
| ② | **不可变 tag**：消费者锁版本，不用 HEAD／分支名 | `ref_kind` 与 `ref` 形态比对；tag 被移动＝发布方违纪，装配面只如实记解析结果 |
| ③ | **产物不入库、不可手改** | 装配面路径前缀不得落在任何源仓内；越界 ⇒ 用法错停 |
| ④ | **按 ref 取 committed blob**（不是工作区字节） | 取件走 `git archive`；避掉工作区换行转换污染 |
| ⑤ | **发布前源一致性校验** | 各源仓已跟踪文件零改动；不然 ⇒ 前提不成立停手 |

纪律④ 的理由（实证级）：工作区取件会带上本平台换行转换，指纹全部走歪；`git archive` 取的是 ref 时刻的仓内原字节，这是「逐字零变换」唯一可靠的取源形态。

## 四、取件与落盘（顺序不可换）

1. 前置校验全绿（源仓 clean、ref 可解析）—**先于任何写**。
2. 按 ref 取源，算出本次装配面的完整文件计划（bundle 本体 ＋ 各组件子树）。
3. 路径冲突检测：两个组件写同一目标 ⇒ 索引件写坏，立即停。
4. 漂移停：装配面已有同步账本时，先比对装配面现字节与末块记录；不等 ⇒ 产物被手改／半写，停（**不得就地覆盖记账**）。
5. 幂等短路：新账与末块账完全一致 ⇒ 零写入、不追加空块，直接返回成。
6. 落盘（逐文件写后即断言字节一致）→ 块级摘要双侧相等断言 → **通过后才追加账本块**。
7. 写装配全账（组件→仓→ref→解析 commit 的全账）。

第 6 步的「先断言、后记账」与发布器同款顺序，理由见 `object-build/references/60-publish.md`（指针）——反序会在复制中途失败时留下「账说做过了、实际没做」的假账。

## 五、产物核对（第 3 步怎么做）

| 查 | 命令口径 | 期望 |
|---|---|---|
| 三件套齐 | 列装配面根 | 装配全账、同步账本、包主文件均在 |
| 文件数 | 装配全账的文件计数值 vs 装配面非元数据文件计数 | 相等 |
| 账本末块 | 末块文件行数 vs 装配全账文件计数值 | 相等 |
| 组件解析 | 每个组件的解析 commit | 40 位十六进制；ref 种类与索引件一致 |
| 组件落点 | 每个组件的装配目标路径 | 存在且非空目录 |
| 越界 | 装配面路径 vs 各源仓根 | 不在任何源仓目录树内 |

元数据三件（索引件、同步账本、装配全账）**不进文件计数的对账基数**——它们不是注册态包成员。

## 六、幂等与漂移停（第 4 步）

| 现象 | 输出形态 | 处置 |
|---|---|---|
| 源未变、装配面未动 | 含「零写入」，退出码 0 | 通过（幂等） |
| 源变了 | 新块追加，文件数变化 | 通过（属正常重装配） |
| 装配面被手改 | 报漂移，退出码非 0 | 停；**删装配面重跑**，不得就地覆盖记账 |

「删装配面重跑」是唯一处置：就地重跑会把漂移洗成合法账（把「被改过」记成「本来就这样」）。

## 七、失败处置（触发点 → 码 → 做什么）

码值与处置人的权威定义见 `object-build/references/60-publish.md` 的退出码闭集（指针·本件不定义码、不列码义）。本件只给**本工序特有的触发点 → 处置动作**：

| 触发点 | 停手后做什么 |
|---|---|
| 索引件不存在／不是合法 JSON／缺键 | 修索引件，不得猜组件清单 |
| 组件源仓不存在 | 修并列目录前提 |
| 源仓已跟踪文件有未提交改动 | 回源仓提交或回退 |
| ref 不存在／不可解析 | 修 ref 或重打不可变 tag |
| 取源路径下无文件 | 修 `path`，或确认该 ref 上确有此组件 |
| 装配面被手改 | 删装配面重跑，不得就地覆盖记账 |
| 落盘字节断言不过／块级摘要不等／写账失败 | 上报装配器维护方；重跑可补账 |
| 输出目录落在源仓内 | 改 `--out` 或改用缺省的仓外同级目录 |

## 八、本段的边界

- **不定义复制怎么做**：字节复制、权限位、摘要算法、状态判定式 → `object-build/references/60-publish.md`（指针）。
- **不管组件内容对不对**：组件的专业判据在组件自带真源。
- **不管门禁**：门禁跑法与升级判据 → `multi-collab/references/60-gates.md`（指针）。
