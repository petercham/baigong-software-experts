# fuxi-skill · 失败模式契约（failure-modes）

> 性质＝交付件本体（自包含成文·双纪律＝节闭集〔恰五节，多节/缺节/改名＝diff 非空即 fail〕＋字段名闭集〔本文件声明字段名与断言工具注册位双向 diff＝∅，未注册字段零容忍〕）。
> 记法：FM-<n>＝本文件节号；FM-<S|P|M>-<nn>＝条目编号；ST/FC/BW/GS-<n>＝断言目录编号（`gates/assertion-catalog.md`）；R<n>＝决策清单条款。条目框架入基座，具体条目分轨（护栏方向反向者不入共享节）。

## FM-1 表结构

每条失败模式＝五元组闭集：`编号`／`轨别`／`触发`／`检出`／`处置`。

```json
{"字段注册": ["编号", "轨别", "触发", "检出", "处置"]}
```

- `编号` 形态＝`FM-S-<nn>`（共享）／`FM-P-<nn>`（person 轨）／`FM-M-<nn>`（method 轨），前缀与 `轨别` 取值一一对应。
- `轨别` 取值闭集＝`共享`／`person`／`method`。
- 分轨硬纪律：person 轨节与 method 轨节条目不得互挂轨别（`轨别` 字段与所在节不匹配＝diff 非空即 fail，机检）；护栏方向反向的条目不入共享节。
- 条目数量基线：共享 5／person 4／method 3（少于基线＝断言咬）。

## FM-2 分流语义

`处置` 字段取值围绕三态词（词表闭集）＝`降级`／`阻断`／`转人工闸`。

无逃逸路径硬条款（写入正文、机检扫描，扫条目表 `处置` 列）：

1. `处置` 不得为空，不得含「视情况」「酌情」「后续再定」类不确定措辞（检出＝子串扫描，命中即 fail）——失败时无逃逸路径；每条 `处置` 至少含一个三态词。
2. 每条 `检出` 字段必须非空且可指向一个机械或清单化动作（含「人工闸」本身是合法处置去向，但 `触发` 与 `检出` 仍须具体）。

|---|---|---|---|---|
