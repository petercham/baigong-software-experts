# 交付物规格（干净指令·议题包·回执矩阵·报告体例）

> 出处：M055② 优先＝决策者拍（拍板日期见 changelog）；报告体例＝规则 11 甲/戊压缩形态；来源帽＝决策者拍。

## 一、干净执行指令（审计者 → 执行者·七要素·缺一不算指令）

**M055② 优先**：审计不重述范围、不预写方案——范围细目、断言面、预估改动面统归执行者票卡三行（标准双署）。指令只给「要达成什么」与「什么算完成」，不给「怎么做」。违此即越界（实证 BM-08：指令写了范围三动作＋断言面 8 条＝替执行者立票卡，"验可测性"退化成自己验自己）。

```
目标：一句话，可验收（做完能被判真假）
边界：只划禁区（明确不做什么）——不写范围细目
验收要求：什么算完成（一句话）——断言面＋负样本由执行者票卡立，审计只验可测性
约束：要遵守的规范与纪律条款号（如 M011 / M056）＋「六道硬约束·第 1／5／6 条」（缺此串＝不合规派遣）
输入件：路径逐件列（不含讨论件、不含未定方案）
交付形态：文件 / 格式 / 落点
截止：日期
```

**不得出现**：讨论过程、方案比较、他人质疑、「可能／建议考虑／另一方案」、未定事项。
**唯一例外**：确有未定事项单列一行「未定：遇此停手上报」，不混入正文。
**干净度自检（可 grep）**：出现「讨论／可能／建议考虑／另一方案／某某认为」→ 逐条确认或删除。

**派遣合规判据（可 grep·缺一不算指令）**：`约束：` 行**必含「六道硬约束」串**——这是**唯一必要条件**。同时给出真源路径（如 `multi-collab/SKILL.md`）更好，但**路径不能替代该串**：本仓路径与项目名本身含 `multi-collab`（本仓根绝对路径、`deliverables/multi-collab/`），若以路径为等价物，任何提到本仓的指令都会"顺带过检"——判据等于没立。缺该串 ⇒ **不算合规派遣**，收件方**直接退回**，退回理由写「约束行缺纪律指针」（与「七要素缺一不算指令」同构）。机检：`grep -E '^约束：.*六道硬约束' <指令文件>`，命中即过、零命中即退。

**不卡的一项（只作建议）**：同时标出适用条号（如「第 1／5／6 条」）便于收件方自查；**未标不退回**——判据只卡"指针在不在"，不卡"指针细不细"。

**适用范围**：只对**有盘面载体**的派遣生效（A／B 形态：指令是一份文件或一条可存档的会话消息）；C 形态单会话帽子制无独立通道，本条不适用，其自审风险另由 `40-deployment.md` 形态表标注承担。

## 二、议题包（主理人 → 顾问·五要素·缺一不算议题）

```
议题：一句话问题（边界清楚，能回答"这算不算答完了"）
要什么产出：形态 / 长度 / 判据
背景件：路径（最小集——只给回答本议题必需的）
规范约束：要遵守哪几条
下一步：拿到产出后主理人会做什么
```

另附一句「**不需要你知道的**」：显式写明越界范围。不写这句，顾问会自己去找；找不到就自己猜。

## 三、回执矩阵（审计者 → 主理人·形态 A 由总线产出）

表头：`件号｜发件｜收件｜主题｜投递｜截止｜状态（已签收／待签收／超期 N 天）`。
三件用途：①主理人一眼看「谁欠我什么」②审计者据此催办 ③超期是**算出来的**，不靠谁记得报。

## 四、易混四处，归谁定死

| 事 | 归谁 | 不归谁 |
|---|---|---|
| 讨论结论收敛成下一轮输入 | 主理人 | 审计者（它只判，不编排轮次） |
| 任务意图转成干净指令 | 审计者 | 主理人（否则双头指挥） |
| 催办／记回执／算超期 | 审计者 | 执行者（自己催自己＝假回执） |
| 决定哪些件要落盘 | 主理人 | 审计者、顾问、研究席（可建议，不可自派） |
| 物理写治理盘 | 执行者（唯一） | 任何其他席位（含审计者的证据件） |

## 五、审计报告体例（一页卡·写报告前必读）

> 立卡缘由：能用上的纪律＝恰好记得的纪律——细则放远处等于没有，本卡把检索成本压到零。

**形态锚＋来源帽**（两行都要，缺一不算报告）：
- 第 1 行＝来源帽：纯文本不加粗，`【来源】<执行体>（<角色>）· <文件号＋标题>`。执行体在前、角色在后。**转述保留原【来源】，不重标。**
- 第 2 行＝形态锚：`**底稿 BM-NN**`。管「这是哪一份」。

**头部六要素**：来源帽／审计者（含边界声明）／被审对象（commit＋批次）／时点（含盘态基准 sha）／判据（规则号＋条款号）／方法（读证纪律三条）。

**骨架四段**（顺序固定）：
1. 上半场·答当问——`【知悉】`／`【待拍】`（待拍带批次指针；无则写「无」）。
2. 下半场·三行式总记——读了什么／读到什么（关键读数原文）／判定何据（指向判定表）。
3. 四态判定表——`#／对象／判定／依据（证据指针）`。四态＝阻塞（红）／关注（黄·必带核验动作）／可延后（必带触发条件）／通过（可因新证重开）。
4. 验真结论／边界——不出整改令、不预写方案。只答两问：每条可算否？负样本齐否？结论三选一：可启（附验真意见）／退回重立卡（只说哪条不可算）／无票。边界段写「只读核验·零写操作」。

**五条硬规矩**：
- 「通过」后必须跟证据位；无底稿的判定＝未判定。
- 依据分栏：〔复算〕可重跑／〔采信〕写不可复算理由／〔拆面〕数字与语义分列。
- 标签分侧：核验·判定·结论＝审计侧；自检·在案·待核＝执行侧。
- 落盘走誊录通道：内容在报告里，物理落盘由执行者逐字誊录；审计者不写治理盘。
- 身份切换复述：一人兼两身份时，切换后第一句写明「本席＝X｜写盘权限＝有/无｜写盘域＝Y」（实证 BM-07 首稿以验证方惯性写盘）。写盘权只有一档：执行者有，其余全无。

**三个高频漏项**：①上半场二态漏；②三行式退化成自造骨架；③四态退化成绿/未绿（绿未绿是执行者报态口径，不是审计判定级别）。
