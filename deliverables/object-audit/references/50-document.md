# 文档对象审计（治理文档/台账/规范）

> 出处：D1–D6＝本地约定（文档治理归纳）；「append-only 与可精炼两制」＝业界范式（ADR supersede-not-edit／Git 不可变历史）；「指针不复制」＝业界范式（SSOT）；「归属声明」＝业界范式（provenance）。

## D1 归属可溯（缺一即不合格）

| # | 测项 | 判法 |
|---|---|---|
| D1-1 | 归属声明随身 | 文档头部一行：归属＋依据＋判据指针——文件离开目录树仍可溯源 |
| D1-2 | 头部＝内容 | 文件头的版本/状态声明与正文一致（抽验，不只看头） |
| D1-3 | 版本账对齐 | 头部版本＝版本史末条目；机检比对 |

## D2 单一真源

| # | 测项 | 判法 |
|---|---|---|
| D2-1 | 指针只指不搬 | 同一内容只在一处有正文，其余位置只放指针；复制正文＝新债 |
| D2-2 | 退役件注头 | 被取代的件头部写明「已被 X 取代」＋派生回指；正文不改（历史可读） |
| D2-3 | 无第二真源 | 同一规则不得在两份现行件里各写一遍（退役件不算） |

## D3 修订两制

| 制 | 适用 | 规则 |
|---|---|---|
| append-only | 台账/拍板记录/事实流水 | 不改写原句；勘误＝原文后注；正文不回改 |
| 可精炼 | 通用规则/方法论 | 正文可直接改写＋修订注记行留痕；实质变更走否决通道 |

- 勘误≠修订：事实性转录勘误走修订日志；实质变更须异议期。
- 归档件＝禁编辑·可读可链可恢复（业界范式：归档即冻结）。

## D4 准入四判据（防文档增殖）

新文档落盘前四问：①谁会读它（无人读＝不写）？②它驱动什么门/动作（零驱动＝进背景记录不进版本库）？③和既有哪份重叠（重叠＝并入不新开）？④交接物是闭集内哪一项（闭集外＝不产）？

## D5 体量与层

| # | 测项 | 判法 |
|---|---|---|
| D5-1 | 单件体量 | 常驻件＜上限、按需件＜上限（上限由项目 profile 注入） |
| D5-2 | 层级正确 | 方法论与项目值分层：通用方法论在通用层，项目取值在项目层；错层＝可移走性违例 |
| D5-3 | 索引路由 | 每层有索引；索引只路由不复写 |

## D6 引用完整性

- 所有内部指针所指目标存在（机检：指针悬空检查）。
- 引用史实件时标注「史实待核」桶，桶只减不增（shrink-only）。

## 判定要点

- D1-1 归属缺、D2-1 正文复制、D2-3 第二真源 ＝ **阻断**（文档失去可溯性或产生双真源）。
- D3 归档件被编辑＝**阻断**（历史被改写）。
- D5-2 错层＝**关注**（可移走性受损，必带迁移动作）。
- D4 准入未过仍在写＝**可延后**（带「并入/撤销」触发条件）。
