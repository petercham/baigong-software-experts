# 图对象审计（整图/拓扑）

> 出处：G1–G6＝本地约定（图治理归纳）；「分层／上界／依赖单向」＝业界范式（layered architecture／bounded context）；「机制与内容分离」＝业界范式（framework vs. instance）。

## G1 分层正确

| # | 测项 | 判法 |
|---|---|---|
| G1-1 | 层不混 | 每个节点有明确层归属（内核/形式/题材/受众等，按项目定义）；一个节点两层＝缺陷 |
| G1-2 | 依赖单向 | 上层可依赖下层；反向依赖（下层指上层）＝拆不开 |
| G1-3 | 变体不升层 | 同层变体不新建层；新层须有「被第二个使用方需要」的理由 |

## G2 上界与容量

| # | 测项 | 判法 |
|---|---|---|
| G2-1 | 节点数上界 | 有明确上限且当前计数入档；超限先合并/退役，不加节点 |
| G2-2 | 边数上界 | 同上（边比节点更易失控） |
| G2-3 | 共享件引用 | 共享件被多个图引用时，引用由加载时解析（不复制）；复制＝分叉风险 |

## G3 完整性

| # | 测项 | 判法 |
|---|---|---|
| G3-1 | 无孤儿节点 | 每个节点在至少一条通路上（入口→终点的可达性检查） |
| G3-2 | 无不可达终点 | 每个终点有至少一条到达路径 |
| G3-3 | 门禁节点有出口 | 拦截节点必须有「谁处理/回哪」的出口，否则＝死路 |

## G4 机制与内容分离

- 图＝机制（结构与判据），题材内容填充节点字段、**不新开节点**。
- 判据文本里出现「具体题材词」当规则＝内容混入机制（换题材即失效）。
- 项目专属值（路径/成员/计数）由项目 profile 注入，图件本身保持可复用。

## G5 可验证性

| # | 测项 | 判法 |
|---|---|---|
| G5-1 | 图级判据 | 整图有「什么算跑完」的判据（不只节点级） |
| G5-2 | 机检可跑 | 层完整性/上界/引用可解析 三项须有可跑检查器（非人工目检） |
| G5-3 | 计数动态 | 图数/节点数断言从注册表动态读，不写死（写死＝漂移源） |

## G6 演化纪律

- 新增节点/层须带「什么条件下退役」一句；只增不减＝图会腐化。
- 图与实例的差异须可枚举（同图多实例时，实例差异进 profile，不进图）。

## 判定要点

- G1-1 层混、G2-1 无上界、G3-1 孤儿 ＝ **阻断**。
- G4 内容混入机制＝**关注**（换题材即失效，必带抽取动作）。
- G5-3 计数写死＝**关注**（漂移源）。
- G6 缺退役条件＝**可延后**（带「下轮复核」触发）。
