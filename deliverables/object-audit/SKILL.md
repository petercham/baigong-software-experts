# object-audit · 对象审计总入口

**定位**：本器只持「审计骨架」与「对象路由」。各对象的具体测项在 references/ 分件；已有真源的只给指针、不复写细则（单一真源）。项目值（真源文件、机检清单、对象注册表）由项目 profile 注入，本器不写项目名、号段、日期、人名。

**本器＝审计期（verification），不是构建期（construction）**。判别式：审计期用**问句**写（「审：缺 X 判何态」），构建期用**指令**写（「造：必须 X」）。本器 description 只在"审"时触发 → **构建规范写在本器里，构建时根本不会加载，等于不存在**（同款教训：纪律写在远处＝没有）。因此本器内的构建规范一律只留指针，不复写：

| 想造什么 | 去哪（构建期 skill） |
|---|---|
| skill（D/T/M/F 任一型） | `object-build/references/10-skill.md`（四型必填字段／混装拆法／四道尺／升版纪律）＋`skill-creator`（通用流程） |
| 专家角色 | `object-build/references/20-expert-role.md`（三栏／权限四类／隔离／升级路径） |
| 装订（节点×专家×技能×经验） | `object-build/references/15-binding.md`（三层两态／装订链／无命中三态） |
| 节点／图 | `skyline-graph-constructor`（本器只补期别判据） |
| 票／批次 | `object-build/references/40-ticket.md`（构建真源·本器只补期别判据） |
| 文档／治理件 | `doc-governance`（载体/分层/修订制/准入判据的真源）。**命名约定表现于本器 §命名约定，落点不对（审计器不持规范），待迁**——迁移前它就是唯一真源，不得再声称在别处 |

> **本器与 `object-build` 的分工**：构建侧写「造：必须 X」（指令式），本器写「审：缺 X 判何态」（问句式）。两器**不互抄正文**，只互指路径。拆件理由：本器 description 只在"审"时触发，构建规范写在这里等于不存在。

**总律：审计只验，不改判据。** 判据属被审方与拍板人；审计若需放宽标准才可通过 → 停手上报（自发行医执照是审计最隐蔽的失守）。

## 审计范围：只审规范件（normative），不审记录件（informative）

> 出处：normative／informative 之分＝业界标准术语（RFC 2026／W3C／ISO 通用）；「只审指导生产的文档」＝本地约定（拍板）。

| 类 | 定义 | 要不要干净 | 例 |
|---|---|---|---|
| **规范件**（normative） | **指导生产**：规则、纪律、机制、标准、模板——被当作依据来执行 | **必须干净**：过五测·英文标识·无历史债 | 元机制层的规则件、skill 包、判据集 |
| **记录件**（informative） | **记录生产**：判词、审计底稿、呈拍简报、票卡、台账、健康账、归档 | **不要求**：它们是项目史，脏是正常形态（写着「我们又违反了某条」正是其职责） | 判词归档、过程记录、历史件 |

**判据一句话**：这份文档是拿来**照着做**的，还是拿来**查当时发生了什么**的？照着做→规范件，审；查历史→记录件，不审。

**越界警报**：去审判词/台账「为什么有历史债」＝审错了对象（它们的存在就是为了记录债）。审计范围错定，比审得不准更糟。

## 审计四问（任何对象都先过这四问）

| 问 | 查什么 | 判不合格的典型 |
|---|---|---|
| **问净** | 有没有不该有的：历史债（项目名/号段/票号/日期/人名/项目路径）·重复真源·本地约定冒充业界标准 | 干净度五测（见下）任一命中＞0 |
| **问实** | 声明的能不能落地：每条能力主张有对应产物/命令/判据（契约闭环） | 声称有检查实际没有；指针指向不存在的文件 |
| **问测** | 判据能不能判真假：可机检优先；「良好/合理/完善/大幅」类词即缺陷 | 验收标准无法写出退出码或逐条核验动作 |
| **问界** | 边界与容量：越权（生产兼判定·本体层权力下放给 AI）·容量红线·指针悬空 | 角色既生产又自证；无体量上限 |

## 判定四态＋证据三态（两层，不得混用）

- **判定四态**：阻塞（红·不解决当前批不能前进）／关注（黄·已执行但证据未闭合·必带核验动作）／可延后（必带触发条件·无限期挂起＝黑洞）／通过（可因新证重开）。
- **证据三态**：绿（有证据）／未绿（无证据）／不适用·已移出（须注明移到哪一步、谁拍的）。**「已移出」不计入绿**；计数式＝绿 x ＋未绿 y ＋移出 z ＝判据总数。

## 干净度五测（所有对象通用·可机检）

| # | 测项 | 干净标准 | 机检方式 |
|---|---|---|---|
| T1 | 换项目测试 | 项目专属实体命中＝0。**豁免（裁-21）：协议强制日期不算实体**——`spec-provenance` 块 `spec_effective` 行、changelog 文件全部日期、全角括注内的版本/决策注日期；正文裸叙述日期仍算 | grep 实体模式计数（项目名/号段/票号/日期/人名/路径） |
| T2 | 触发描述 | description 不含项目名、含 when | 文本正则 |
| T3 | 出处测试 | 每条规则带三档出处之一：业界出处（URL/标准）｜命名范式（如 ADR·Diátaxis·SSOT）｜**本地约定（显式标注）** | 搜 URL/框架词；无标注即缺陷 |
| T4 | 真源方向 | 方法论真源在本层；项目值走绑定层注入——不声明「项目文档为真源」 | 读真源声明段 |
| T5 | 体量披露 | 主文件＜200 行（常驻容量红线·业界对照实验）＋references/ 渐进披露存在 | 行数＋目录列 |

> 出处标注：T1–T5 与四问骨架＝**本地约定**（本器归纳）；「生产方不得兼判定方」＝业界通识（职责分离）；「description 含 when＋渐进披露」＝业界范式（Agent Skills 官方模式）；「常驻面＜200 行」＝业界实证（上下文文件对照研究）。

## 对象路由

| 对象 | 期 | 标准件 | 已有真源（指针·不复写） |
|---|---|---|---|
| 全部对象（通用骨架） | **编译期** | `references/00-skeleton.md`（四问的操作定义·取证纪律·先于对象路由读） | 无（本器持真源） |
| Skill（技能/规范/技法库） | 声明编译期·**挂载运行时** | `references/10-skill.md`（**内含 S0 判型：D 纪律／T 步骤／M 思维／F 查表**） | `skill-contract-audit`（契约闭环）——真源件须自身过五测方可作标准 |
| 专家角色（专家包/席位定义） | **编译期** | `references/20-expert-role.md` | 无（本器持真源）。**＝D 型 skill 的深化测项**：判型为 D 的 skill 直接走这件的 E 系列，不必两套都跑 |
| 节点（流程/工序节点） | **编译期** | `references/30-node.md` | 项目图 skill（由项目 profile 指定） |
| 分票（票卡/批次） | 票卡编译期·执行记录运行时 | `references/40-ticket.md` | `object-build/references/40-ticket.md`（构建真源：形状·八件·入账·治理防线） |
| 文档（治理文档/台账/规范） | 规范件编译期·**记录件运行时** | `references/50-document.md` | `doc-governance`（三层域·指针·准入四判据） |
| 图（整图/拓扑） | **编译期** | `references/60-graph.md` | 项目图 skill（由项目 profile 指定） |
| **规范来源（`spec-provenance` 块）** | **编译期** | `references/70-provenance.md`（P-1 块与七键闭集／P-2 锚唯一／P-3 条款摘要·缺则判 exit 1） | 无（本器持真源） |
| **案例库／经验库** | **运行时**（不可穷举·允许"查不到"） | `references/15-binding.md`（判据：**检索有效性＋更新纪律**，不查干净度） | CBR（Aamodt & Plaza 1994）／Soar episodic memory／RAG |

**编译期 vs 运行时的判据差异（审前必读·否则会用错尺子）**：编译期对象**必须过五测、可以且应当穷举、封闭稳定**，审契约＋负样本；运行时对象**不要求干净（脏是职责）、不可穷举、开放增长**，审**检索有效性**（该命中时命中吗）＋**更新纪律**（过期案例淘汰吗）。完整模型与出处见 `references/15-binding.md`。

**路由规则**：先定对象类型 → **再定期（编译期/运行时）** → 取标准件 → **若对象是 skill，先过 S0 判型再选测项**（D 型走 E 系列；T/M/F 型走 S 系列＋该型必填字段）→ 若该对象另有真源 skill，标准以真源为准、本器件只补增量测项（多源冲突时真源胜，并按 T3 记出处）。

## 内容级深查三招（文档域·皮总 2026-10-22 点名·机检只给信号，判定须读正文）

| 招 | 测项 | 一句话判法 |
|---|---|---|
| **题目—内容吻合** | `50-document.md` D7 | 先只读标题盲预测正文应有物，再对照——无落点＝空题；正文成段越题＝换题 |
| **归位正确** | D8 | 内容域对撞所在子包 README 边界声明；方法论/项目、规范/记录两判据定层定性质 |
| **冗余扫描** | D9 | 空壳件/无读者件/重复目录/内容重复——D4 是事前门，D9 是事后核 |

> 本器按**领域**挂判据标准：文档域＝D7–D9（已建）；**代码分层域、Agent 分层域＝空白候办**（判据须研究后立，不现编——无出处的判据违反 T3）。build 侧对应关系：构建＝统一方法论（object-build），审计＝领域判据（本器各分件）——方法论统一、判据分域，不对称是**应该的**。

## 命名约定（文件与目录）

| 类 | 判据 | 规则 | 依据 |
|---|---|---|---|
| **元机制件**（规则/机制/方法论——可跨项目复用、会被工具链与路径碰到） | 换个项目还成立吗？ | **目录名＝层号＋大写 META**（如 `L0_META`，一眼标识「可整包移走的元机制层」）；**文件名＝ASCII 小写 kebab-case**；skill 的 name 字段只允许小写字母数字连字符 | 规范硬约束＋跨平台文件系统／URL 编码／命令行转义（业界通识）；大写目录名＝边界标记（本地约定） |
| **执行件**（设计/过程/台账/拍板/归档——本项目内给操作者读） | 只在本项目内给人读 | **不强制规范**：随操作者习惯，中文名可以；标题语言自由 | 命名服务读者，不服务整齐（本地约定·拍板） |
| 存量元机制件改名 | — | 随结构性重建**一次整批迁移**（git mv＋活指针同步＋检查器复跑）；不零敲碎打 | 零敲碎打＝中间态断链（本地约定） |
| 存量执行件 | — | **永不改名**：改名＝史实锚失效（判词/台账/归档里的路径引用） | 历史不可改写（本地约定） |

判据一句话：**这是机制，还是项目里的一件事？** 机制→英文（标识符）；一件事→随人（中文即可）。内容层（正文/标题/判据文本）任何件都语言自由。

## 报告最小契约（五件·缺一不算报告）

1. **对象与版本**：路径＋版本/commit/字节/行数（可复读的标识，非「最新版」）。
2. **标准与出处**：用了哪套测项、每条测项的三档出处。
3. **逐条证据**：文件:行／命令输出／计数；**逐模式计数，不估计**；数字与语义分栏。
4. **判定＋三态计数**：四态逐条＋绿/未绿/移出计数（三者相加＝判据总数）。
5. **边界声明与落盘归属**：多席协作下**审计方永无治理盘写权**（单写者·见 `multi-collab` 六道硬约束·6＋`multi-collab/references/20-handoff.md` 两盘区分）——报告正文即交付物，**物理落盘由执行席按项目治理规范誊录**，落点与命名由执行席定，审计只核「誊录是否逐字」；独席场景写域**只限审计产物目录（交接区），不写业务目录**。边界须写「只读·零写操作」。

## 反模式（出现即停手）

| 反模式 | 正解 |
|---|---|
| 拿别器的 PASS 充当本对象的自证（嫁接） | 每个对象只认指向它的证据 |
| 用「首跑即绿/零标记」当结论而不附复跑时点与命令 | 宣称时点须晚于产物终态 |
| 审计顺手提高/放宽标准以便放行 | 判据不可自调；停手上报 |
| 只审文本不验本体（票面全绿≠本体达标） | 判据集须含对象本体面的尺，不只治理面计数 |
| 把「已移出」算成「绿」 | 三态取值域写死，移出单列 |
| 审完不出判定（只描述现象） | 每条给四态之一＋依据指针 |
| 审计顺手把证据件落盘（「反正要留档」） | 报告正文即交付物；落盘交执行席誊录（单写者） |

## 自检（本器每版发布前）

过五测（T1–T5）＋主文件＜200 行＋description 含 when＋references 齐 ＋ 无项目实体命中。
