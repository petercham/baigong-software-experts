# object-build · 对象构建总入口

**本器＝构建期（construction）。审计期是 `object-audit`，两器不互抄。**

判别式：**构建期用指令写**（「造：必须 X」），**审计期用问句写**（「审：缺 X 判何态」）。

为什么必须分器：`object-audit` 的 description 只在"审/验收/体检"时触发 → **构建规范写进审计器，构建时根本不会加载，等于不存在**。同款教训：纪律写在远处＝没有。反向同理：把"审"的问句写进本器，构建时读到会以为自己在被审，动作变形。

## 构建三问（任何对象都先过）

| 问 | 定什么 | 定不下来会怎样 |
|---|---|---|
| **① 造什么对象** | 对象类型（skill／角色／节点／票／文档／图／装订） | 选错字段表，全部白写 |
| **② 哪个期** | 编译期固化 / 运行时挂载 | 编译期对象烧运行时预算；运行时对象被按编译期标准写成死的（不可增长） |
| **③ 哪一型**（仅 skill） | D 纪律／T 步骤／M 思维／F 查表 | 型别不明 → 必填字段不明 → **无法判"写完了"** |

## 构建顺序（六步·不可跳步）

1. **判期**（编译期 or 运行时）——判据见 `references/15-binding.md`
2. **判型**（仅 skill·D/T/M/F）
3. **套字段表**（该型/该对象的必填项，缺一即未写完）
4. **定判据**（写出"什么算做完"——这是构建期唯一的完工标准）
5. **过自检**（该型的测法；型别不是标签，是测试用例的分组依据）
6. **交审计器**（构建方不自证；自证＝生产方兼判定方）

## 一条退出口铁律

**构建期的退出口不是「文件写完了」，是「每条判据都能被审计器判真假」。**

写的时候边写边问一句：**这条审计器怎么咬？** 咬不住的判据（"合格/合理/自然/完善"）＝没写完，不是"写得简洁"。
