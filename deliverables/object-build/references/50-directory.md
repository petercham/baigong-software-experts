# 目录治理构建（仓库/文档目录结构·子包边界·索引）

> 期别：**编译期**（结构定下即固化，迁移成本高）。
> 出处标注：依据 R5（业界无跨语言"目录总规范"，事实分三层）与 R6（README 选型），底稿见技能包 `docs/research/`；「索引路由」＝本地约定。
> 审计侧不另立分件：结构违例走 object-audit 通用测项（指针悬空＝问实、越界＝问界）。

## 〇、先定规范主体强度（写判据前先分层，写错档＝假硬或假软）

| 层 | 例 | 违反后果 | 判据写法 |
|---|---|---|---|
| 工具硬强制 | go `internal/` 不可导入；README 三处查找优先级（`.github`→root→`docs`）；CODEOWNERS 同 | 报错/静默失效 | **必须**（可机检） |
| 工具软契约 | cargo `src/tests/benches` 自动发现；MkDocs 默认 `docs/` | 不报错但失去自动化 | **应当**（存在性＋命名可机检） |
| 声明式配置 | mkdocs nav / toctree / sidebars.js：目录管存放、导航进配置 | 配置与磁盘不一致→死链 | **必须对账**（nav 路径↔磁盘） |
| 官方建议 | Python src layout；ADR `NNNN` 编号 | 可复现的坑 | **推荐＋失败模式**（建议式） |
| 纯惯例 | `cmd/`、`apps/` vs `packages/`、ADR 目录名 | 无 | **选项＋各自背书**，禁写"必须" |

**铁律：判据强度跟着规范主体走。** 把纯惯例写成"必须"＝自造宗教；把硬契约写成"建议"＝假软。

## 一、造目录结构（六步）

1. **先问工具**：项目用了什么工具链（cargo/go/MkDocs/Docusaurus…），其契约目录名**不得自造**——放对零配置，放错全手写。
2. **分区按性质，不按 actor、不按工序**：交付件／规范文档／治理史实／过程流水各一区（判据一句话：拿来**照着做**的／查**当时发生了什么**的／**用完可弃**的）。
3. **一级目录＝边界声明**：每个一级子包根放**一份 README.md**（见下节）；有 owner 要求的项目，新增一级目录须先有 owner 声明（Google subtree owners／GitHub CODEOWNERS 同构）。
4. **深度 ≤2**（索引层＋细节层，progressive disclosure 反"深套娃"）；所有细节文件必须被索引指到——**孤儿文件＝违例**。
5. **决策记录独立子目录**：与文档同区不同目录（MADR `docs/decisions/`），连续编号或动词短语命名（二选一，选定后不混用）。
6. **进库与否由 `.gitignore` 显式声明**，不由目录名前缀表达（实测 git 无点前缀忽略规则）。

## 二、子包根文档：README.md（边界＋索引二合一·薄写）

- **用 `README.md`，不用 `INDEX.md`**：GitHub 目录级自动渲染（事实特性）；MkDocs/Docusaurus 认 `README.md`/`index.md`，**均不认 `INDEX.md`**；Google 风格指南明文"每个顶层包目录应有 README.md"。INDEX.md 仅 agent 导航圈新兴用法、零工具支持。
- **内容三件**（Google 包级 README 规范）：①这个包是什么、给谁用（边界一句话）②状态 ③指路链接（索引）。可加 **Non-goals** 数行——"不是什么"与"是什么"同权。
- **薄写铁律**：README 只放入口信息＋索引，**不复写正文**（GitHub 官方："Longer documentation is best suited for wikis"；README rot 研究：腐烂的根因＝README 里写了第二真源）。索引只路由不复写＝指针只指不搬。
- **索引路由**：一级子包根**只放这一份 README.md**，正文一律住子包并在索引登记一行；根目录出现正文＝违例。

## 三、出口判据（结构算做完）

①工具契约目录名零自造；②每个一级子包根恰有一份 README.md 且薄（边界＋状态＋索引，无正文复写）；③索引指针全部指向存在的文件、无孤儿文件（可机检：nav/索引路径 ↔ 磁盘对账）；④决策记录独立子目录＋命名体系唯一；⑤git 归属由 `.gitignore` 显式声明；⑥深度 ≤2。
