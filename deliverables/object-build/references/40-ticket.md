# 票构建（形状·票卡·入账·执行·治理防线）

> 期别：**票卡＝编译期**（立卡后固化，执行中判据不增不减）；**执行记录＝运行时**（每票收口追加，不要求干净）。
> 出处标注：tracer bullet／expand–contract／INVEST＝业界范式（上游 `to-tickets`·Bill Wake）；八件票卡／两类边／三态报告／治理防线＝本地约定（原 `plan-tickets`·`ticket-flow` 收敛，两器已退役并入本件）；「票面全绿≠做完」＝本项目治理教训（T-027 实证）。
> 审计侧判据（K1–K6）在 `object-audit/references/40-ticket.md`，本件只写构建指令，两不互抄。

## 〇、先判要不要票（免票直做）

单点小改动（一文件、判据显然）＝**免票直做**——分票本身有成本，别给小事上仪式。
需要票的判据（INVEST 全过，任一不满足＝拆或并）：Independent／Negotiable／Valuable／Estimable／Small（一批可闭）／Testable。
分票成本 ≤ 执行成本：票卡里「负样本/停止条件/回滚」各一行短语即可，不许写成小作文。

## 一、票的形状：tracer bullet（垂直切片）

一票交付一条**端到端可验证的行为**——从入口到出口都接通，只是窄。做完能对使用者演示「现在能做一件以前做不到的事」；演示不出＝按层切了。

**例外一：宽改动（wide refactor）＝ expand–contract**。一次机械改动（重命名、改类型）波及全库，任何单票无法落绿。序列：expand（新旧并存）→ migrate（按爆炸半径分批，每批一票）→ contract（删旧）。分批也无法各自落绿时允许共享集成分支，但最终必须有一票「集成并验证」，绿只在那里承诺。

**例外二：原子业务闭环**。构成一次原子决策回路的操作（如「挑战＋同笔罚分」）归一票，拆开会产生中间不一致态。共享基础结构（类型/常量/工具）单独成票、排在消费票之前，否则各票自造一份。

## 二、两类边（缺一不可）

| 边 | 记法 | 语义 | 违规后果 |
|---|---|---|---|
| 逻辑依赖 | `blocked by: 03, 05` | 需要对方产出的接口/数据/文件 | import 失败、字段不存在、返工 |
| 写冲突 | `conflict-with: 07` | 改同一文件/同一目录 | 覆盖、半合并（**逻辑独立 ≠ 可并行**） |

建边三条检查：①每个文件至少归属一票（出现两次＝连写冲突边）；②共享结构单独成票排前；③边方向单向（互指＝切分没切干净）。
依赖链要查全：这张票要读/要调的东西从哪来？dataclass、helper、基础设施各由哪票定义？只写直接依赖＝漏项。
状态机有显式时序时，依赖链**照时序逐节点连**，不许把中间节点拍扁合并。

## 三、预算（超预算＝拆）

每票标三项预估：**改文件数**（>5 拆）／**改行数量级**（>一个会话能安全审阅的量拆）／**步骤数**（>会话步数预算拆，或先做探路票）。
上下文预算：一票＝一个 agent 会话能装下（目标＋输入＋约束＋验收 ≤1 页；必读文件 ≤5）。估不出来＝范围没定清，回计划阶段。

## 四、票卡模板（八件·缺一不算可执行）

```
# <票号> · <标题：一个动词短语>

## 目标（一句话）
做完之后，使用者能做什么以前做不到的事。

## 边界
做什么：<一句>
不做什么：<一句；含禁改文件/目录清单>

## 输入件（路径逐件，缺一不可执行）
- <文件路径>（读什么：<用途一句话>）

## 产出件（写域：新建/修改的文件清单，缺一不可对账）
- 新建/修改：<路径>（一句话）
汇总：产出文件数 = N；与预算一致，超出即停手（不是「尽量不超过」）

## 验收判据（每条可跑·可机检优先·含本体面尺）
1. [机检] <命令> → 期望 <输出/退出码/计数>
2. [人验] <看什么、判什么档>

## 负样本（每条判据配一句）
1. 若未做到 → 会看到 <具体现象>

## 停止条件（遇此停手上报，不自行处理）
歧义：<哪种解读冲突>；越界：需改 <票外/禁改清单>；依赖缺失：<接口/字段>不存在或与描述不符

## 回滚
git 层面＋数据/配置层面怎么撤；不可回滚的步骤必须提前声明。

## 预算
改文件 ≤N｜改行 ≤M｜步骤 ≤K（超出即停手报告，不硬做）
```

**产出件为什么必须单列**：同时充当写域（连写冲突边）、预算基准（文件数）、越界对账基准（落地后 `git diff --name-only` vs 产出件清单，清单外文件＝未绿）。

**判据写法**：不可测退回（「完善错误处理」），可测接受（「非法输入返回 400 且不写库：`curl …` → 400，DB 行数不变」）。每条判据三要件：**可观测**（文件:行/命令输出/计数）＋**负样本**＋**证据位**。判据必须含**本体面尺**（对象本身达没达标），只有计数/指针/体量＝票面全绿本体没做。

## 五、入账三落点（票不许只活在对话里）

| 落点 | 存什么 | 缺省（项目 profile 可覆盖） |
|---|---|---|
| 票清单 index | 每票一行：票号｜标题｜状态｜blocked by｜conflict-with｜产出件摘要 | `<tracker>/index.md` |
| 票卡 | 每票一文件（八件） | `<tracker>/<票号>-<slug>.md` |
| 执行记录 | 每票收口一段：三态计数＋证据位＋时点 | `<tracker>/<票号>-<slug>.log.md` |

命名：票号沿用项目既有体系，**绝不新开第二套**（多套编号并存＝已实证的返工源）；文件名 `<票号>-<kebab-slug>.md`。
**项目钩子接驳（不新造一套）**：门禁命令（GATES）＝票卡机检判据直接引用项目检查器；记录落点（RECORD_SINK）＝执行记录进项目台账不另建；临时层（SCRATCH）＝draft 票可落临时层，ready 后必须进正式落点；进度通道（PROGRESS_CHANNEL）＝每票 done 时更新，供零进度报警。四者由项目 profile 注入，本件零机构锚。
状态机五态：`draft → ready → in-progress → done`（`blocked` 旁路）。规则：**done 无证据位＝未完成**；状态只相邻移动，不许跳级（draft 直接 done＝假完成的结构性来源）。
多席场景：「内容责任方」≠「谁能写盘」——物理落盘一律唯一写者出口，其余席位只产内容。
归档：done 不删移 `done/`；撤销标 `cancelled`＋原因，**不物理删除**（史实锚）。

## 六、执行与验收

- **frontier**：只做 blockers 全清且写域不冲突的票；优先取解锁下游最多的，同级取预算最小的；**一次一票**，并行只在写域完全不相交时开放。
- **清上下文**：票间不继承会话记忆——票必须自包含，换一个空会话也能执行。
- **判据不增不减**：执行中新增判据＝范围漂移，须重立卡；自加项单列质量报告，不计绿。
- **自证与复核两道不可合并**：执行者逐条跑命令贴证据报三态；独立方不采信自报、重跑机检。生产方不得自证。
- **三态收口**：报「完成/收口/通过」前同一条列出①判据（立卡原样）②逐条证据③三态计数（绿＋未绿＋移出＝总数，移出写「移到哪·谁拍」）。任一缺 → 只能报「部分完成：X 已做 / Y 未做」。
- **停手格式**：一句话说「卡在哪＋需要谁定什么」，不写长篇分析、不预写方案（那是越权）。

## 七、治理防线（防「治理票挤占开发票」）

> 病灶：连续多批主件全是治理件、产品零产出。治理件零失败风险，排程笔在激励上必然偏向安全件——**结构问题，不是品德问题**。

1. **预算封顶**：治理件每批增量 ≤1；未闭治理件超上限 → 冻结新开只许闭。
2. **进度报警**：每批必填开发进度通道；连续三批零进度 → 排程冻结、治理件降级。
3. **防繁殖**：治理件分收敛件（闭案/勘误/对账）与增生件（新律/新标准）；**增生件须指认一条旧律退役或并入**（只增不减＝单向棘轮）。
4. **排程分权**：开发票直达批次不经审计排程；拍板人可点名主件。兜底：每十批一次开发对账（只答「离可交付近了多少」）。

批次纪律：一票一批（批号＝票号）；候办池只减不增（进一件同批关一件，到期未关＝升阻塞或撤销）；每票带死亡条件（「什么情况下撤销/并票」一句），无死亡条件＝永久挂账的种子。

**启动纪律（静默即过）**：票卡发出当批无异议即启动，一异议即改；禁等会签、等仪式、票卡滞留。审计只验可测性（每条可算·负样本齐），不重述范围、不预写方案。防闸门自警：预审一旦写成必经仪式就要砍——滞留窗定期实测，超窗即砍预审为抽验。

## 八、发布前检查与高频坑

**发布前**：
1. 跨 spec 一致性扫描（概念命名/共享数据结构字段/写责任归属/接口签名/阶段边界）——细则见 `to-tickets/references/spec-cross-audit.md`（10 检·只读引用，本件不复写）。
2. 对照代码库实况：报「缺 X」前先搜——代码已有＝改「集成票」不是「从零实现票」；有代码无票＝按孤儿工作上报补票。
3. 票面**避免具体文件路径与代码片段**（会过期）；例外：原型产出的决策件片段（状态机/schema/类型形状）可内联并注明。
4. 禁删可能含已完成票据的目录（先 ls 对账、备份、验证，再动）。

**高频坑**（各配一句自检问）：
| 坑 | 自检问 |
|---|---|
| 字段名漂移（spec 叫 `brand_rules` 票里叫 `rules`） | 共享结构每个字段名在 spec 和票里逐字一致吗？ |
| 依赖链漏项 | 它要读/要调的东西从哪来、哪票定义？ |
