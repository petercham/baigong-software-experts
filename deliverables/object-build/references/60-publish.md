# 发布（产地 → 部署面·单向·逐字·可判）

> 期别：**编译期**（发布形态一经定下即固化；改判据＝L0，改取值＝提案）。
> 出处：本地约定（显式标注）——决策者对部署面的定性「部署面是落地点，不是工作空间」，落盘见 `.collab/decisions/`；「退出码可当门禁」「生产方不兼判定方」沿用本包既有条款；不可变副本＋按内容寻址（sha256 记账）＝业界范式。
> 与另两件的关系（**只指路径，不复写正文**）：审计侧问法见 `object-audit/references/70-provenance.md`；出口、退出码闭集与升级条件见 `multi-collab/references/60-gates.md`。

## 〇、三条定义性约束（缺一即不是本件说的"发布"）

| # | 约束 | 判据 |
|---|---|---|
| 1 | **逐字复制，零变换** | 两侧 sha256 相等＋权限位相等。不做变量替换、不注入头部、不裁剪、**不做换行转换、不动 BOM** |
| 2 | **单向** | 仓 → 部署面。发布器**没有**合并功能，只有复制与比对；"采纳目标"不是选项 |
| 3 | **先算块、再复制、断言通过、才追加** | 这个顺序本身是判据的一部分（§三-3、§五-3） |

## 一、在册（identity）与状态（integrity）分开，不许混成一个问题

| 问题 | 靠什么回答 | 读哪边 |
|---|---|---|
| 这件是不是我方的 | **在册**：`deliverables/<pkg>/COPY.state` 存在，且其最后一块 `copy:` 指向该目标路径 | **只读仓侧**，不读部署面字节 |
| 这件现在对不对 | **状态**：逐文件 sha256 ＋ 权限位比对 | 读两侧 |

**在册的完整表述（首次入库前该件不属于任何类，须走引导路径）**：`COPY.state` 存在 **且** 最后一块 `copy:` 指向该路径 ⇒ 在册。二者缺一都不是"在册"，而是"尚未在册"——不得当作"已发布但内容不符"处理。

**版本号不进任何判定，也不进任何提示**：版本号是人写给人看的标签，同一"版本差"背后可能是零内容差、也可能是若干行差。`--check` 的输出只允许出现 `relpath ＋ 态`，版本号只允许出现在 `--verbose` 的人读摘要里并标注「描述性，不参与判定」。

## 二、两个阶段（阶段判定写死，不许"看情况"）

| 判定 | 条件 | 命令 | 白名单从哪来 |
|---|---|---|---|
| **阶段 0｜基线建立** | `deliverables/<pkg>/COPY.state` **不存在** | `publish.py --init <pkg> --files <relpath>…` | **命令行显式清单**（唯一来源） |
| **阶段 n｜常规发布** | 存在，且最后一块 `copy:` 指向本次目标 | `publish.py <pkg> [--files <relpath>…]` | 最后一块 `files:` 的 relpath 集 ∪ 本次 `--files` |
| **异常** | 存在，但 `copy:` 指向别处 | **拒绝**（exit 3） | — |

**为什么必须有显式的阶段判定**：两个阶段的前置不同（一个无基线、一个有基线），若靠"文件存不存在"隐式分支，报错信息会含糊到无法定位（"发布失败"可能是没基线，也可能是基线过期）。

### 二-1 引导路径修的是**两处**循环，不是一处

| 循环 | 形态 | 修法 |
|---|---|---|
| **A** | `COPY.state` 由发布动作产生，而发布又要求它已存在 ⇒ 首次永远跑不通 | 阶段 0 由 `--init` 直接落第 1 块 |
| **B** | 白名单／目标路径／现行态**全部从最后一块派生**，首次没有"最后一块" ⇒ 派生规则自己把自己锁死 | **第 1 块同时是「首次清单」与「首次基线」**，一步完成；此后才有"最后一块"可派生 |

## 三、阶段 0 的三条硬约束

1. **清单必须显式给，禁止目录枚举**。枚举会把 `scripts/` 一起发出去，与本件"白名单制、默认不发"自相矛盾。清单项＝相对 `deliverables/<pkg>/` 的 relpath，禁通配符、禁目录、禁 `..`；给到目录或不存在的文件 ⇒ exit 2。
2. **`--init` 与常规发布走同一套断言**，不得有「初始化所以跳过校验」的例外。例外一旦存在，就会被人当作后门；**同一套断言是指纹，不是流程**。
3. **顺序定死：先在内存算出待写的块 → 复制 → 断言通过 → 才追加块**。反序（先写块后复制）在复制中途失败时会留下"块说发过了、实际没发"的**假基线**——那正是把「副本被静默改」与「合法同步」重新混成一团的开法。

## 四、`COPY.state`（每包一份，块追加；六键名不变）

```
[sync n=1]
source: deliverables/<pkg>/SKILL.md
source_sha256: <64 hex>                 ← 清单摘要（源侧）
copy: ${SKILLS_ROOT}/<pkg>/SKILL.md   ← 变量式（裁-25：账本在 S-03 扫描域内，绝对盘符路径必咬 drive-path——消灭实体而非豁免；归属判定②/在册比对时以 env SKILLS_ROOT 展开）
copy_sha256_at_sync: <64 hex>           ← 清单摘要（副本侧·同步当时实测）
synced_at: <ISO 8601 带时区偏移>
source_commit: <40 hex | none>
files:                                  ← 四元组，逐文件一行
<repo_sha256>  <copy_sha256>  <mode>  <relpath>
<repo_sha256>  <copy_sha256>  <mode>  <relpath>

[sync n=2]
…同结构…
```

| 规则 | 内容 |
|---|---|
| **只可追加** | 新块只能在文件末尾追加；**禁止修改任何既有块**（改＝改写历史事实＝把漂移洗成合法） |
| **六键保留** | `source`／`source_sha256`／`copy`／`copy_sha256_at_sync`／`synced_at`／`source_commit`。键名不变，故只认单块的旧解析器读最后一块仍工作 |
| **两块级摘要的算法** | 按 `relpath` 升序（字节序）取 `"<sha256>  <mode>  <relpath>"` 以 `\n` 连接、UTF-8 编码、**不含末尾换行**，取 sha256。源侧用 `repo_sha256`，副本侧用 `copy_sha256`。逐字复制下两者恒等——**这个恒等是断言的断言，不是判据的判据**（§五-2） |
| **`files:` 是四元组** | `repo_sha256`（期望）／`copy_sha256`（同步当时副本实测）／`mode`（期望权限位）／`relpath`。此清单**即发布白名单** |
| **`mode` 记法** | `stat.S_IMODE(st_mode) & 0o777` 的四位八进制（如 `0644`／`0755`），**不带文件类型位**。判定只用「可执行位（`0o111`）有无」与「只读位」，其余位只记录不判定（避免 umask 与平台噪声变成误报） |
| **最后一块＝现行值** | 当前态、白名单、目标路径**全部从最后一块派生**，不另存一份（另存＝两处可打架） |
| **`COPY.state` 存在＝在册** | 只看「存在且最后一块 `copy:` 指向该路径」，**不看内容一致与否** |

**为什么留两列 hash 而不压成一列**：判据只需要一个独立值（逐字复制下 `copy ≡ repo`，四态用同一个值就能判）；两列的用途是**运行时断言**——两者不等即说明复制实现走歪了（编码、换行、BOM）。**判据一个值够，存储两列有用**。

**为什么是白名单，不是排除清单（本席推断，不挂任何既有条款名下）**：两条推断链——①**默认值方向决定错误代价**：白名单漏写一条 ⇒ 少发一个文件（缺件，`--check` 与集合对账都会报，可见可修）；排除清单漏写一条 ⇒ 多发一个不该发的文件（**不可见**：没有"多出来的东西"这条判据，发了就是发了）。②**默认值要稳定**：包内文件集合会持续变（脚本、临时件、未来的子目录），排除清单要为每个新增项做一次判断，白名单不需要——新增项默认不发，直到被写进清单。**代价不对称＋默认值稳定 ⇒ 选白名单。**

## 五、复制实现与运行时断言

### 五-1 复制必须二进制、无编码参数、无换行转换

| 允许 | 禁止 |
|---|---|
| `shutil.copy2`（**首选**：连权限位一起复制） | `Path.write_text`（文本模式，默认会把 `\n` 写成本平台换行） |
| `shutil.copyfile` ＋ 显式 `shutil.copymode` | 文本模式 `open(..., 'w')` 读写 |
| `open(src,'rb')` + `open(dst,'wb')` 手动分块 | shell 管道拷内容（`cat`／`echo`／重定向） |
| — | 任何 `newline=` 参数、任何 BOM 增删、任何字符集转码 |

**为什么首选 `copy2` 而不是 `copyfile`**：`copyfile` **不复制权限位**。用 `copyfile` 发布一个 shell 脚本，会出现"部署侧 hash 全绿、可执行位却留在仓内"，即本仓最忌的**票面全绿、本体没做**——而 **hash 判据在结构上就看不见权限位**，这类假绿只能靠 §五-3 的第三项断言咬住。

**依据**：`object-audit/references/00-skeleton.md「二、取证纪律·哈希复算用 bytes 口径」` 已写明"文本模式读会把 CRLF 归一，hash 必歪"。本件只是把同一条纪律用到**写**这一侧。

### 五-2 "恒等"必须写成运行时断言，不能写成设计恒等式

复制完成后**立刻**逐文件做三项断言，任一不过即 **exit 4**，且**不写块**：

| # | 断言 | 不过的含义 |
|---|---|---|
| 1 | `sha256(副本) == sha256(源)` | 复制实现走歪（编码/换行/BOM/半写） |
| 2 | 副本清单摘要 == 源清单摘要 | 同上，按块级再核一次 |
| 3 | `S_IMODE(副本) & 0o111 == S_IMODE(源) & 0o111` | 权限位没跟着走（`copyfile` 的典型后果） |

**写成断言而非恒等式，理由是**：写成"恒等"是一个**声明**，后人把实现换成文本模式时没有任何东西会报警；写成断言是一道**防线**，换实现当场咬住。这与"未定义退出码不得计绿"是同一种思路——**不可执行的保证等于没有保证**。

### 五-3 异常不得吞

复制阶段的异常（路径过长、无权限、磁盘满、目标被独占）**必须 exit 4，禁止写块**。实现里出现 `try/except: pass` 之后照常回写 hash 的，产出的是**假记录**——比 hash 不等更坏：hash 不等还能被发现，假记录把"没做"记成"做了"。

## 六、准入闸（五条·全绿才发）

> 闸门问的不是"这个件好不好"，而是"**它有没有资格离开仓**"。

| # | 条件 | 机检 | 不过 |
|---|---|---|---|
| **A1** | **有产地**：`deliverables/<pkg>/SKILL.md` 存在 | 文件存在 | 拒发。部署面不得成为唯一载体——"只存在于部署面"正是"临时性"最本质的特征 |
| **A2** | **过审计**：门禁脚本 S-01/S-02/S-03 当期全绿（exit 0）＋审计席判词无「阻塞」 | 证据件里的当期记录＋判词指针 | 拒发（exit 3：前置不成立），回执行者 |
| **A3** | **出处齐**：`SKILL.md` 正文首块带 `spec-provenance` 七字段，且 P-1/P-2/P-3 全过 | 见 `object-audit/references/70-provenance.md` | 拒发（exit 1：产物侧缺件） |
| **A4** | **不撞外部件**：目标路径非目录联接；若已存在，其现行内容必须能在流水里找到（＝"这串字节是我们发的"） | 联接判定＋§七 状态判定 | 拒发。向联接复制＝改别人仓；覆盖不能溯源的同名目录＝吞掉别人的件 |
| **A5** | **形态合规**：`name` 与目录名一致且为小写 kebab；主文件＜200 行；`references/` 平铺一层（不套娃） | 门禁脚本 S-01 | 拒发 |

**只有 A1 与 A3 直接防「临时件复发」**：临时件的两个可观察特征是"只活在部署面"与"说不出这条规矩谁给的"，A1／A3 分别把它们变成不可发布。A2／A4／A5 管质量与安全，不防复发。

**A2 的一处已知后果（须与"证据件是否入库"一并裁）**：若证据件不入版本库，则新克隆的环境里 A2 判"未绿"⇒ 首次发布会因 A2 被拒一次。这不是 bug，是"证据不随仓走"的直接推论；裁定时须一并决定，不许在实现里悄悄给 A2 开例外。

## 七、`--check`：五态（逐文件；四态语义＋权限态）

`H_k` ＝第 k 块里该文件的 `copy_sha256`；`R_k`／`M_k` ＝第 k 块里的 `repo_sha256`／`mode`；`C1`／`mode_now` ＝副本现值。

| # | 条件 | 态 | 动作 |
|---|---|---|---|
| 1 | `C1 == H_L` 且 `R1 == R_L` 且 `mode_now == M_L` | **一致** | 无 |
| 2 | `C1 == H_L` 且 `R1 != R_L` | **陈旧**（仓内先进） | 重同步 |
| 3 | 取最大 k 使 `C1 == H_k`（k＜L） | **滞后于第 k 次同步** | 重同步，报告写明 k |
| 4 | `C1 ∉ {H_1 … H_L}` | **漂移（违例）** | 停手；先查改动来源；以源覆盖；记一条证据 |
| 5 | `C1 == H_L` 且 `R1 == R_L` 但 `mode_now != M_L` | **不一致（权限）** | **不得算作"一致"**；按漂移同款处置（先查来源，再以源覆盖） |

**判定顺序**：先按 1→4 定 hash 态；只有落到态 1 时才继续判权限（态 5）。hash 不同时权限差不单列——更严重的那一项吃掉它。

**"冲突"这一格为什么不存在了**：仓内进了、副本也变了——副本要么等于最后一块（落 2）、要么等于某个历史块（落 3）、要么谁都不等于（落 4）。**三个分支穷尽了取值域，死角是被穷尽掉的，不是被特殊处理的。**

**「滞后于第 k 次同步」这一态能成立的前提是"块可以追加"**：只留一块时，`C1 != H_L` 就无法区分"停在旧同步点"（处置＝重同步）与"被手改"（处置＝先查来源）——两种处置正好相反。**块的数量是判据的一部分，不是冗余。**

## 八、集合对账（白名单↔磁盘；不递归、不扫 `scripts/`）

发布前扫**白名单涉及的目录**（由 `files:` 里的 relpath 取父目录集合，得 `D`；`D` 内只取**一层**、不递归），得集合 `S`；白名单集合 `W`。两项不参与对账：**`COPY.state` 自身**（它是产地的账，不是产物）与 **`.` 开头的条目**（约定：隐藏＝本机或工具状态，不可发布）。

| 差集 | 含义 | 处置 |
|---|---|---|
| `S \ W` | 有文件未纳管（可能漏发） | **拒发**（exit 1），逐条打印 `未纳管: <relpath>` |
| `W \ S` | 白名单指向不存在的文件（源侧删了/改名了） | **拒发**（exit 1），逐条打印 `缺件: <relpath>` |
| 两侧相等 | — | 通过 |

**为什么"只扫白名单涉及的目录"而不是整个包目录**：`scripts/` 按设计就是不发的（它不属于任何白名单目录），全目录扫描会把它算成"未纳管"⇒ 天天误报 ⇒ 门禁被关掉。**扫描域必须与判据的射程一致**，否则误报会替你把门禁拆了。

## 九、退出码（同一闭集；本器侧的映射）

闭集与"未定义码一律按 4"见 `multi-collab/references/60-gates.md`。本器侧的语义与处置人：

| 码 | 本器语义 | 处置人 | 写块？ |
|---|---|---|---|
| 0 | 通过 | — | 是（常规发布成功必写） |
| 1 | **产物侧不合规**：白名单过期、集合对账不过、A3/A5 不过、`--check` 判出需重同步/漂移/权限不符 | 产物作者 | 否 |
| 2 | **用法错**：参数缺、包名不存在、清单项非法、`SKILLS_ROOT` 未设 | 调用方 | 否 |
| 3 | **前提不成立**：未在册（无 `COPY.state` 且未带 `--init`）、`copy:` 指向别处、A2 未绿、规范件锚不到 | 在册状态/提供者 | 否 |
| 4 | **发布器自身或环境错**：§五-2 断言不符、复制异常、写块失败 | 发布器维护方 | **否** |
| 其他 | 未定义 | 按 4 | 否 |

**为什么"未在册"归 3 而不是 1**：1 的处置人是产物作者，而"未在册"改文件改不出来——它要动的是产地的登记状态（先走引导路径）。**码值必须与处置人一一对应，否则退出码就只是"失败"的同义词。**

**`SKILLS_ROOT` 无默认值**：目标根一律由环境变量显式给出，规范件不写任何具体盘符路径（写了就是把某台机器的取值当判据）。未设 ⇒ exit 2，不得猜、不得回落到当前目录。

## 十、发布器能力禁令（写进代码注释，防后人"顺手加一个"）

| 禁止 | 为什么 |
|---|---|
| 删除目标目录、递归清理、按目录枚举删除 | 部署面混着我方件与别人件，按枚举删必然误删 |
| 合并、反向同步、"采纳目标" | 单向是定义性约束；反向＝把部署面变成第二产地 |
| 文本模式复制、换行转换、BOM 处理 | §五-1 |
| 吞异常后照常记账 | §五-3 |
| 修改既有块 | §四·只可追加 |
| 在输出里出现版本号 | §一 |

**唯一允许的删除**：前任块的 `files:` 有、本次 `files:` 没有的文件（＝我们自己发过、现在不发了）。判据是**前任清单差集，不是目录枚举**——这样永远不会误删别人的件。

**唯一允许的写动作**：向部署面复制白名单文件、删上述差集、向 `COPY.state` 追加一块。除此之外发布器是只读的。

## 十一、负样本（发布器的完工判据：不咬＝防线不存在）

| 负样本 | 期望 |
|---|---|
| 未在册且不带 `--init` 直接发布 | exit 3，部署面无任何写入 |
| 目标路径是目录联接 | 拒发（A4），零写入 |
| 白名单缺件（`W \ S` 非空） | exit 1，逐条打印缺件 |
| 源侧多出一个未纳管文件（`S \ W` 非空） | exit 1，逐条打印未纳管 |
| 反向拷贝（把部署面内容改成仓内没有的字节）后跑 `--check` | 判**漂移** |
| 只改副本权限位（hash 不变）后跑 `--check` | 判**不一致（权限）**，不得判一致 |
| 把复制实现换成文本模式 | §五-2 断言 1 不过 ⇒ exit 4，且不写块 |
| 复制中途抛异常 | exit 4，且不写块（不得留半块） |
| 只留一块的 `COPY.state`（把历史块删掉）跑态 3 | 判**漂移**（而非"滞后"）——这条负样本守的是"块数不可删" |

## 十二、本件的边界

- **不定义"什么算干净"**：干净的判据在 `object-audit`（问净）；本件只判"能不能发"。
- **不可机检的部分**：「这个件该不该存在于方法论层」是作者权（L0），本件只管质量与形态。
- **平台边界（诚实记）**：权限位判据在无 POSIX 权限位的文件系统上只能反映只读位，`0o111` 一位不具区分力。故：①`mode` 字段照记（跨平台可比时才有意义，跨平台比对判"不适用"、不计绿不计红）；②脚本与 hook 的调用**一律显式解释器**（如 `bash <script>`），**不依赖可执行位**——在权限位不可靠的平台上，这是唯一能保证"装得上"的写法。
