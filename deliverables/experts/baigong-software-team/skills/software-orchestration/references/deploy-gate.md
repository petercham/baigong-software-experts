# 部署动作硬门（装配／注册／覆盖缓存）

> 本件承载部署类动作的把关纪律（v1.2.2 新增）。触发背景（实证教训 2026-10-27）：某执行链交接件"版本纪律"尾注混入「装配产物重出」半句，被承接会话无鉴别升格为 QA 收口票的写域指令，导致开发批收口后未经用户把关即自行装配。

## 一、硬门范围（闭集）

以下动作一律视为**部署任务**，不得视为开发/验收/收尾的例行组成：

| 动作 | 例 |
|---|---|
| 装配产物生成/重出 | 运行装配器（如 `publish.py --assemble`）产出 `-build` 面 |
| 注册/更新到部署面 | 复制产物进插件缓存、市场源目录，触发平台重装/更新 |
| 覆盖运行中的插件/配置 | 替换宿主插件目录（插件缓存／市场源）下任何被使用路径 |

## 二、执行前置条件（两条缺一不可）

1. **独立部署票**：上述动作只能立为**单独的部署任务票**派发，**禁止**并入开发票、QA 验收票、收口判词票的写域或"版本纪律／收尾／下一步建议"等尾注条款。
2. **呈报用户确认**：主理人须在动作执行前向用户明示（做什么、动哪个路径、影响面），**用户明确批准后才执行**。批准记录随部署票回执落盘。

## 三、各席义务

- **主理人**：拟票、拟交接件、拟版本纪律时，部署动作与版本技术纪律（bump／打 tag／版本号文件同源）**分开书写**，不得同句混排；用户批准前不下发部署票。
- **执行席／QA 席**：收到的票面或交接件中含本闭集动作但**无用户批准记录**→ 停手，回执登记「部署项缺批准」，等主理人补呈报，不得按票面照做。
- **对账席**：收口对账时检查交付链上有无未经上述两条件的闭集动作发生（含仓外 `-build` 面写入）；发现即红项。

## 四、边界

- 用户在同一指令中已明示授权某次具体部署动作（含路径）→ 该次可直做，回执注明授权出处。
- 闭集之外（如常规 commit、测试、文档落盘）不属部署任务，不受本门约束。
- **本门不禁止装配**：装配＝标准部署工序（把相关 skills 装配进专家团），本门约束的是「是否独立立票＋是否获批＋是否走四段链（§五）」，不是装配本身。

## 五、四段部署流程（2026-10-28 皮总定口径：装配 → 预览 → 人类闸 → 部署）

部署＝标准工序，但形态＝**四段闸口链**，每段须上游收口才可进，禁止跳段：

**装配 → 预览 → 人类闸 → 部署**

| 段 | 动作 | 前置 | 平台抓手（本机实证 2026-10-28） |
|---|---|---|---|
| ① 装配 | 运行装配器产出注册态 bundle | QA 终审绿＋独立部署票（§二.1·票面写清目标段＝只到预览） | `publish.py --assemble` → 仓外 `<仓>-build/<bundle>`；产物三件套（manifest/COPY.state）核对＋幂等复跑 |
| ② 预览 | 预览面进**预览态**挂到人类眼前 | ①收口（产物对账绿） | 复制进本地市场源（先备份）→ `register_expert.py <包> --session-id <会话>` → 会话右侧预览卡＋立即测试按钮（`.created-by-session`/`.pending-preview-session`＝平台原生预览标记，非隐藏流程） |
| ③ 人类闸 | 人类跑真实验证并明示结论 | ②预览可见 | 验证要点清单由主理人交（本批可消费面）；结果（过/不过/现象）回报归日志账 |
| ④ 部署 | 预览态转正为部署面正式版本 | ③人类明示通过＋明示批准（含路径）（§二.2） | 已在市场源的＝`register_expert.py` 刷新＋宿主更新进缓存；注册动作回执附批准出处 |

要点：

1. **装配＝工序而非禁区**（§四已校准），但每次装配仍走 §二 两条件（独立票＋获批）；获批范围按段界定——批到②止的票不得顺手动部署面转正动作。
2. **预览不是 `-build` 目录本身**：`-build` 面人类不可召唤，预览的成文形态＝注册进本地市场＋`--session-id` 会话标记挂预览卡。只装配不落预览＝流程停在①。
3. **人类闸不可由代理代跑**：主理人/执行席不得把"我验证过了"充当③；主理人收口总结禁把"刷新部署面"作默认下一步推荐。
4. **验证不过**→ 按现象开票回修，修后重走①②；部署面保持旧版不碰；市场源若已暂放预览内容，备份一键回滚。

实证背景（两案）：① v1.6.3 批（2026-10-28）部署面刷新先行于真实使用验证——本条即其纠偏；② 预览卡"只出现过一次"案（2026-10-28）——归因＝历轮全是纯文件复制、丢失 `register_expert.py` 注册步；据此②段抓手成文。
