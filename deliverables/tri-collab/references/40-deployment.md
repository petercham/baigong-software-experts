# 部署形态与帽子制

> 出处：席位的隔离强度＝模型的隔离强度（非提示词的隔离强度）——本环境实证；「席位与模型解耦·异质模型路由」＝皮总 2026-10-22 论定＋业界印证（RouteMoA arXiv:2601.18130：15 模型池按任务路由，成本 −89.8%·延迟 −63.6%·准确率反升；generator-and-judge 范式："a model is a poor critic of its own blind spots"——判定方须异模型才成立）。

## 架构原则（先于形态表）

1. **席位＝权限与读域的定义，不绑定模型。** 每个席位应可独立配置后端模型——按任务配最有性价比的组合（省钱＋避免同模缺陷）。当前 UI 不支持逐席配模型时，多席共模是**过渡妥协**，不是目标形态；席位表按权限最小化拆分正是为了将来模型可换。
2. **交接只认盘面，不认智能体内部。** 会话上下文是模型内部状态——**跨模型传不过去**，且随会话消亡。凡交接一律落盘面 md 交接件（规格见 `20-handoff.md`）：介质与两端用什么模型无关，席位换模型／换会话／换 UI 交接件照读。**把"盘面交接"当形态 A 的妥协＝看反了：它是异质模型时代唯一模型无关（model-agnostic）的协作介质。**
3. 同一后端换帽子只能隔离职责，不能隔离偏见（自审＝相关失效：同一个模型看不出自己的盲区）。

| 形态 | 通讯方式 | 接口职能落在哪 | 独立性 | 适用 |
|---|---|---|---|---|
| **A 跨后端多会话**（现行·首选） | **文件总线**：磁盘是唯一共享介质，拉模式 | 总线协议只承载投递；轮间接口＝主理人会话，执行端接口＝审计者会话 | 强（不同模型·无共享上下文） | 执行者、审计者各用一个后端会话 |
| B 单后端多子代理 | 会话内直连（子代理／消息／任务列表） | 两个接口分别由主理人 agent／审计 agent 担任 | 中（同模型·共享部分上下文） | 同一后端能起多 agent |
| C 单会话帽子制（降级兜底） | 无独立通道（同一上下文） | 当前 agent 按帽代持·须标注 | 弱（同模型同上下文·自审风险） | 只能开一个会话时 |

## A 形态五条硬规则

1. **只拉不推**：每个会话开场第一动作＝读 inbox；不读＝该会话不算上线。
2. **正文独立成文件**：事件流只记索引＋SHA-256。「不得加工」由哈希执行，不靠自觉。
3. **签收即回执**：ack 只能由收件人落；越权签收直接被拒。
4. **超期是算出来的**：sweep 按截止日＋签收状态机械计算，退出码可当门禁。
5. **投递件必须自包含**：跨会话只能传文件，传不了推理链（＝交接件自包含判据的出处）。

**决策者在 A 形态下仍需做的一件事**：开窗时把「先跑 inbox」送进新会话。跨后端消除不了这个物理动作——**谁承诺"零人工"，谁就在骗人**。

## 帽子制（仅形态 C 用·独立性打折）

> 前置：能开两个会话就别用帽子。帽子解决"职责串味"，解决不了"同一个脑子看不出自己的错"。

1. **首行标帽**：切换席位回复首行写明当前帽（「【帽】审计者」），不标＝缺件。
2. **一响应一帽**：不得同一响应内既判定又执行；转呈须分段声明「以下为转呈，未加工」。
3. **产出分件**：不同帽的产出物理分件。
4. **禁兼（唯一一条）**：执行者帽与审计者帽永不同戴；讨论帽与执行帽永不同戴。其余可兼。
5. **环境限制**：mailbox 型专家代理 spawn 即回收（零输出）时，用 general-purpose 子代理＋席位提示词注入，或主会话帽子制；**不得因席位起不来就取消该席职责**（可代持，须标注代持人与原因）。
