# tri-collab · 协作纪律（四席版）

**沿革**：v1.0（2026-10-13）＝三方（执行者／审计者／决策者）。v2.0（2026-10-20，决策者认可）＝增设**接口人**席，原三方条款全量保留并重排。**v2.1（2026-10-20，决策者纠正）＝增设 §十 部署形态：接口人在跨后端形态下是「总线协议」不是 Agent**——任何 Agent 也只能待在自己的会话里，无法跨后端传话；帽子制降级为形态 C 的兜底。**v2.2（2026-10-20，决策者再纠）＝接口不是第三方席位，是两个职能**：主理人＝**轮间**接口（横向·什么该进入下一轮），审计者＝**执行端**接口（纵向·指令下行／报告上行）。二者同属把关侧、**可以合并**；真正不可合并的是「生产方 ↔ 判定方」。隔离的实质＝**信息暴露面**（执行者只见干净指令·顾问只见议题包），不是「谁不许跟谁说话」。**v2.3（2026-10-20，决策者三纠）＝主理人的决策权不是绝对的**：它只是**计划已定之后的执行面决策权**（L2）；本体层（L0：什么叫做完／合法值域／评估标准）**人类独占、不得下放**，偏好层（L1）提案制。口诀「改值域＝人类·改取值＝提案·改落点＝AI」（真源＝`skill-contract-audit` §决策权边界＋拍板记录）。**v2.4（2026-10-22，决策者拍）＝单写者原则**：执行者＝**唯一落盘出口**，其余席位（主理人·审计者·顾问·研究席）**永无写盘权**——不是「默认无、项目可改」，是无例外。内容一律交主理人，主理人决定哪些件要落盘，分发执行者落；执行者落盘前**自读项目治理规范**（`docs/L0_META/`）确定落盘姿势。目录名 `tri-collab` 保留兼容，内容以四席为准。

**容器非真源**：纪律真源＝项目《开发纪律》M 层；本文件条款逐条带源锚，冲突时真源胜并修本器。**本器不定义专业判据**（票制见 `object-build/references/40-ticket.md`／身份与帽见 `identity-governance`／文档治理见 `doc-governance`）。

**总律（本器其余条款皆由此推出）**

> **消息可以中转，判定不能中转；编制可以合并，利益不能合并。**
> 生产方不能自证（判定独立于执行）；上行只增不改（主理人依据必须是原件），下行只减不加（执行者只该拿到干净指令）。
> 隔离的尺子只有一把：**这条信息对他完成当前那件事，是必需品还是噪音。**

## 一、席位表

| 席位 | 使命 | 手上有 | 手上没有 | 对谁 |
|---|---|---|---|---|
| **主理人**（＝决策者） | 执行面决策·**轮间调度** | **L2 执行决策权**·L1 提案权·进度一票权·轮次编排·唯一对外·**落盘分发权**（决定哪些件要落） | **L0 本体决定权**（判据／验收标准／合法值域／范围边界）·不核细节·不判定·不写执行指令·**无写盘权** | 对上＝人类（L0 只能上）；对下＝审计者 |
| **审计者**（＝执行端接口人） | 取证判定＋指令下沉＋报告上收 | 判定权·干净指令下行权·判词上行权·放行令 | 无执行权·**永无写盘权**（v2.4·含证据落盘） | 对主理人 |
| **执行者** | 产出与自证 | 操盘权·立卡权·**唯一落盘权**·自证义务 | 无判定权·**不看讨论·不看他人质疑·不看未定方案** | 只对审计者 |
| **顾问**（按需） | 供专门判断 | 本议题的专业产物 | **不看全局·不看他人议题·不看判词**·不入回执链·不判定·**无写盘权** | 只对主理人 |

**「主理人」是角色，不是人**：人类本人担任时，L0 拍板权在他手上；由 Agent 代跑轮间调度时，它**只拿到执行面决策权**——L0 事项必须原样上到人类（它只是提案人，不是拍板人）。**角色可以代跑，权力不能顺延。**

**两个接口职能，不是两个席位**（决策者 2026-10-20 原话意）：

- **主理人＝轮间接口（横向）**：把任务轮 N 的产出（讨论结论／拍板／异常）收敛成轮 N+1 的**输入**。管「什么该进入下一轮」。
- **审计者＝执行端接口（纵向）**：把轮输入转成**干净执行指令**下行；把执行者报告转成**判词**上行。管「这一轮干得对不对」。
- 两者同属**把关侧**（目标一致：对的过去、错的挡住），**可以合并**——同一人兼轮间调度与执行端把关，不构成利益冲突。**v2.1 的「接口人不得兼审计」作废**：那条把"中转"误当成了独立利益方。
- 真正不可合并的只有一条：**生产方 ↔ 判定方**（执行者不能自证）；不可穿透的也只剩一条：**讨论 ↔ 执行通道**（见 §三）。

**为什么必须隔离**（决策者给的理由，比"防止串味"硬）：执行者拿到讨论 → **未定事项被当已定**、**质疑被当否定**、产出被半成品污染；顾问拿到全局 → 跑题、上下文浪费、把他人的半成品当输入。所以隔离判据不是亲疏，是「**这条信息对他完成当前那件事，是必需品还是噪音**」。

**人选映射（建议·非强制）**：主理人＝决策者本人（轮间调度可交交付总监代跑，**拍板权不转**）；审计者＝独立席（可由交付总监兼，**不得由执行者兼**）；项目经理＝顾问席，出**需求侧验收判据集**（不给判定权）；QA＝顾问席，做**产品验收**（≠过程审计：QA 的「全绿」本身也是审计对象）。

**跨后端形态下"谁在搬"**：主理人与审计者可能分处不同后端会话，两个接口靠**总线协议**落地（见 §十），不靠某个 Agent 当邮差。

## 二、消息路由（唯一合法路径）

| 发 | 收 | 可发什么 | 禁止 |
|---|---|---|---|
| 主理人 | 审计者 | 任务意图·拍板·纠偏·轮次切换·插单 | 直接对执行者下工序／下判据（双头指挥＝两套真相）。**唯一例外＝落盘分发**（见下一行） |
| 主理人 | 执行者 | **落盘分发**（v2.4）：要落哪些件·原件在哪·落完回执给谁 | 工序指令·验收判据·验收结论·讨论内容 |
| 审计者 | 执行者 | **干净执行指令**（§四·七要素）·整改令·**誊录要求**·回执催办 | 夹带讨论过程·他人质疑·未定方案 |
| 执行者 | 审计者 | 报告·证据件·自证·阻塞上报 | 向主理人直接要结论；打听讨论；找顾问评议 |
| 执行者 | 主理人 | **落盘回执**（落了哪些件·路径·字节数／哈希） | 求判定·要结论·夹带讨论 |
| 审计者 | 主理人 | 判词·三态·呈拍简报·漂移报警·回执矩阵 | 加工上行件·替主理人拍板 |
| 主理人 | 顾问 | **议题包**（§四·五要素） | 给全局上下文·给他人议题·给判词·给未定决策 |
| 顾问 | 主理人 | 本议题意见·依据·反证 | 直接对执行者下指令；外传议题；索取全局状态 |
| 任何席 | 任何席 | 证据原件的路径／哈希／行号 | 转述他人结论（引原文，不引印象）；**写盘**（写盘只此一条出口：执行者） |

**落盘分发 ≠ 工序指令**（v2.4 新增边·两者混同即双头指挥）：落盘分发只回答「**哪些件要落、原件在哪、落完回执给谁**」；**做什么、按什么顺序、什么算做完，仍只能由审计者按 §4.1 下发**。同一份消息里既分发落盘又给工序 → 执行者只执行前一半，后一半按越界上报。

**上行只增不改，下行只减不加**（v2.2 总律补充）：

- **上行**（报告／判词／证据）：只允许追加（补证、勘误注），**不许删改、不许摘要、不许二次排版**——主理人拍板所依据的必须是原件。
- **下行**（指令／议题包）：只允许做减法（去掉讨论、质疑、未定方案），**不许做加法**——传递途中新增的要求没有授权链，等于替主理人下命令。

**投递分件律**：一份文件只有一个收件人。审计件（收件人＝执行者）与讨论件（收件人＝仅主理人）**物理分件**，不得同篇混排；转投时附一行「本文仅投执行者，不含讨论内容」。

## 三、六道硬约束（违反＝协作失败，不是风格问题）

1. **生产方不得兼判定方**——执行者不能做自己的审计。这是唯一绝不能合并的一对；审计者的「全绿」也只是过程指标，结果质量须有系统外判据。
2. **讨论不得进执行通道**——执行者拿到的每份东西里，不得出现讨论过程、未定方案、他人质疑。理由不是保密，是**污染**：未定会被当已定，质疑会被当否定。
3. **上行只增不改，下行只减不加**（见 §二）。
4. **顾问只见议题**——不给全局、不给他人议题、不给判词。顾问一旦有全局观，就会输出"综合建议"；综合建议没有授权链、无法验真、也没人负责。
5. **L0 不下放**——判据、验收标准、合法值域、评估标准、范围边界＝**人类独占**，任何席位（含主理人、审计者）都只能提案。**最要防的一种**：审计者为了放行而放宽判据——那是自己给自己发通行证；主理人也不得代拍、不得"先干起来再补拍"。
6. **唯一落盘出口**（v2.4·2026-10-22 拍）——项目任何盘（docs／代码／测试／数据／证据区）**只有执行者写**。其余席位（主理人·审计者·顾问·研究席）**永无写盘权**：内容交主理人，主理人决定哪些件要落盘（§五-7 落盘分发），分发执行者落；执行者落盘前自读项目治理规范定姿势（§六-7）。审计的命令输出作为报告正文证据段，由执行者誊录（§4.5 戊-4 的一般化）。理由：多席并行写盘＝写冲突＋格式不一＋越权改治理件；**单写者才可对账**（single-writer principle）。

**v2.1 已作废**：「接口人不得兼审计」——中转与判定同属把关侧，可合并。保留其合理内核：**判词正文不得被改**（现由 §二「上行只增不改」＋ §十 哈希校验执行，比编制约束更硬）。

## 四、两个接口的交付物规格（v2.2 重写）

### 4.1 干净执行指令（审计者 → 执行者·七要素·缺一不算指令）

> **M055② 优先**（2026-10-20 皮总拍「执行者先自己计划，你把关，一致了执行者落盘」）：审计**不重述范围、不预写方案**——范围细目、断言面、预估改动面**统归执行者票卡三行**（M055②「标准双署」）。指令只给「要达成什么」与「什么算完成」，**不给「怎么做」**。违此即越界：实证 BM-08 的 T-025 指令写了「范围三动作＋断言面 8 条＋预估改动面逐字」＝替执行者立票卡，致「验可测性」退化为自己验自己。

```
目标：一句话，可验收（做完能被判真假）
边界：只划禁区（明确不做什么）——不写范围细目
验收要求：什么算完成（一句话）——不列断言清单；断言面＋负样本由执行者票卡立，审计只验其可测性
约束：要遵守的规范与纪律条款号（如 M011 / M056）
输入件：路径逐件列（不含讨论件、不含未定方案）
交付形态：文件 / 格式 / 落点
截止：日期
```

**不得出现**：讨论过程、方案比较、他人质疑、「可能／建议考虑／另一方案」、未定事项。
**唯一例外写法**：确有未定事项时单列一行「**未定：遇此停手上报**」，不得混入正文——这是把未定标成红灯，不是把它伪装成已定。
**干净度自检（可 grep）**：指令里出现「讨论／可能／建议考虑／另一方案／某某认为」→ 视为可能污染，作者须逐条确认或删除。

### 4.2 议题包（主理人 → 顾问·五要素·缺一不算议题）

```
议题：一句话问题（边界清楚，能回答"这算不算答完了"）
要什么产出：形态 / 长度 / 判据
背景件：路径（最小集——只给回答本议题必需的）
规范约束：要遵守哪几条
下一步：拿到产出后主理人会做什么（让顾问知道产出将被怎么用）
```

**另附一句「不需要你知道的」**：显式写明越界范围（如「本轮不需要看全局状态与判词」）。不写这句，顾问会自己去找；找不到就自己猜。

### 4.3 回执矩阵（审计者 → 主理人·形态 A 由总线产出）

表头：`件号｜发件｜收件｜主题｜投递｜截止｜状态（已签收／待签收／超期 N 天）`。
三件用途：①主理人一眼看「谁欠我什么」②审计者据此催办 ③**超期是算出来的**，不靠谁记得报。

### 4.4 易混三处，归谁定死

| 事 | 归谁 | 不归谁 |
|---|---|---|
| 把讨论结论收敛成下一轮输入 | 主理人 | 审计者（它只判，不编排轮次） |
| 把任务意图转成干净指令 | 审计者 | 主理人（否则双头指挥） |
| 催办／记回执／算超期 | 审计者（执行端接口） | 执行者（自己催自己＝假回执） |
| 呈拍简报 | 审计者（M050） | 执行者、顾问 |
| **决定哪些件要落盘**（落盘分发） | 主理人 | 审计者、顾问、研究席（可建议，不可自派） |
| **物理写盘**（v2.4） | 执行者（唯一） | 任何其他席位（含审计者的证据件） |

### 4.5 审计报告体例（一页卡·**写报告前必读**·规则 11 甲/戊 的压缩形态）

> 立卡缘由（2026-10-20 主理人问「为什么纪律总记不住」）：规则 11 在 394 行文件第 205–238 行，写报告时不会去翻 → **能用上的纪律＝恰好记得的纪律**。本卡把它压到眼前，把检索成本降到零。

**形态锚＋来源帽**（两行都要，缺一不算报告）：

- **第 1 行＝来源帽**：**纯文本、不加粗**，整行格式＝`【来源】<执行体>（<角色>）· <文件号＋标题>`。例：`【来源】WorkBuddy（审计席）· BM-12 判词（P535 批）`。**执行体在前、角色在后**（与执行侧报告同形——皮总 2026-10-20 拍「和我们一样」；此前写成「审计席（WorkBuddy）」且加粗＝形态不合拍板，连错两版）。管「这话谁说的」；写盘/誊录据此区分来源；**转述他人内容保留原【来源】，不重标。**
- **第 2 行＝形态锚**：`**底稿 BM-NN**`（戊-7 定式）。管「这是哪一份」。

**头部六要素**（缺一不算报告）：来源帽（第 1 行）／审计者（含边界声明）／被审对象（commit＋批次）／时点（含盘态基准 sha）／判据（规则号＋条款号）／方法（读证纪律三条）。

**骨架四段**（顺序固定）：

1. **上半场·答当问**——致主理人面二态：`【知悉】`／`【待拍】`（待拍须带批次指针·创建权在审计；无则写「无」）。
2. **下半场·三行式总记**——`读了什么`（对象＋版本/commit）／`读到什么`（关键读数原文·编号列）／`判定何据`（指向判定表）。
3. **四态判定表**——列＝`#`／`对象`／`判定`／`依据（证据指针）`。四态＝**阻塞（红）**不解决则当前批无法推进／**关注（黄）**已执行但证据未闭合（必带核验动作）／**可延后**（必带触发条件·无限期挂起＝黑洞）／**通过**（可因新证重开）。
4. **验真结论／边界**——**不出整改令、不预写方案**（M055②「审计只验可测性·不重述范围」）。只答两问：**每条可算否？负样本齐否？** 结论三选一：**可启**（附验真意见）／**退回重立卡**（只说哪条不可算，不替他改）／**无票**（未立卡即无票，规划不等于进展）。需执行侧动作时只写这三句之一，**不写做什么**。边界段写「只读核验·零写操作」。

**五条硬规矩**：

- 「通过」二字后**必须跟得出证据位**；无底稿的判定＝未判定（戊-2）。
- 依据列**分栏**：`〔复算〕`可重跑／`〔采信〕`须写不可复算理由／`〔拆面〕`数字与语义分列（戊-6）。
- 标签分侧：**核验·判定·结论**＝审计侧专用；执行者用**自检·在案·待核**。
- 落盘走**誊录通道**（戊-4）：内容在报告里，物理落盘由执行者逐字誊录；**审计者不写盘**（v2.4 起无例外，含证据区）。
- **身份切换复述**：一人兼两身份时（如验证方↔审计者、执行者↔顾问），切换后的第一句必须写明「本席＝X｜写盘权限＝有/无｜写盘域＝Y」。理由：两身份的动作方向常常相反，惯性会把上一个身份的动作带进下一个（实证：BM-07 首稿以验证方惯性写盘）。**v2.4 起写盘权只有一档**：执行者有，其余全无——切换后若「本席」不是执行者，权限栏必填「无」，产出交主理人分发。

**三个高频漏项（均已实证）**：①上半场二态漏 → 只审不答；②三行式退化成自造「一、二、三」骨架；③四态退化成「绿/未绿」三态（绿未绿是 M024 的执行者报态口径，**不是审计判定级别**）。

## 五、【主理人】认领面（＝决策者）

### 5.0 决策权分层：只有「计划已定之后的执行面决策权」

真源＝`skill-contract-audit` §决策权边界＋拍板记录三层制。**口诀：改值域＝人类·改取值＝提案·改落点＝AI。**

| 层 | 管什么 | 谁定 | 主理人（Agent 代跑时） |
|---|---|---|---|
| **L0 本体层** | 有哪些合法值／**什么叫做完**／评估标准／验收判据／范围边界 | **人类独占** | **只能提案，不得拍** |
| **L1 偏好层** | 这一项选哪个值／权重／优先级 | 提案制：填已有值可自主，**新增值须提案** | 可填空，不可造新值 |
| **L2 执行层** | 落到哪个字段／哪一步／什么顺序／怎么实现 | AI 自主＋机检 | **全权** |

三句话记牢：
- 主理人的「拍板」只覆盖 **L2**——计划已定之后怎么落地，**不是计划本身**。
- **判据一旦要改，就是 L0**：停手上报，不许「边干边改」。
- **形式合规不越层**：M004 授权三档管授权**形式**（明确／条件／问句），本节管决策**对象层级**——就算有授权，也不能拍 L0。

**形态 A 下这一条是机检的**：投递时带层级（`--class L0/L1/L2`），L0 只能投「人类」、L1 只能投「人类／主理人」，投执行者直接被拒。所以「主理人悄悄把阈值降一点」这句话**根本发不出去**。

1. **只在 L2 拍、只看异常**；日常介入面收敛到「越权票」一处（M056）。**L0 事项一律原样上人类**，主理人不代拍、不预判。
2. **进度一票权**：任一批点名开发件，该件自动成为下批主件，不经审计排程（M056 排程分权）。
3. 拍板须有**范围＋失效条件**，否则不算拍板。
4. **轮间接口**：每轮收口只做一件事——把本轮产出收敛成下一轮**输入**（已拍→指令意图；未定→挂账**不进下行**；异常→插单或升阻塞）。**不得把讨论原样倒进下一轮。**
5. **不越级取数**：要进度读向审计者要回执矩阵（形态 A 跑 `board`），不逐个问执行者——越级问＝并行两套真相，且会把讨论带进执行通道。
6. **对顾问只发议题包**，不发全局状态（§4.2）。
7. **落盘分发**（v2.4）：所有席位的产出先汇聚到你这里，**由你决定哪些件要落盘**，再按 §二 分发给执行者。判断标准只有一句——「**下一个人要不要照着做／要不要查**」：要，就落（并按治理规范落对位置）；不要，就留在消息里，不制造无主件。分发只给「件／原件在哪／回执给谁」，**不给工序、不给判据**（那是审计者的活；混在一份里就是双头指挥）。

## 六、【执行者】认领面

1. **唯一操盘**：所有落盘动作经执行者；不扩写任务边界（M011：改动边界＝决策者原话所拍）。〔M001/M002〕
2. **先立标准再动手**：主件工作先出验收标准（断言面先于实现），交审计验真。〔M056〕
3. **报告三律**：报状态不得比证据满（M016 结论分级 L1 原话／L2 整理／L3 推演必标）；主获异常须贴行（P414 判例）；引用的数须带名字带口径（P416–P420 族）。
4. **记忆≠事实**：任何断言先读盘核验（M015）；推知不得穿实测的衣服——断言分「实测级／推知级」两级标注（P428 判例）。
5. **收口前自检表跑完才声明收口**（M052·9 条）；谁收口谁自检，审计只核「清单跑没跑完＋结果真不真」。
6. **不给审计席做填空题**：报告里的每个数字自带定位（文件:行／命令＋输出），让审计核数而非找数。
7. **唯一落盘出口**（v2.4·2026-10-22 拍）：**你写盘，其余席位不写**。所有席位的产出——主理人决定要落的件、审计者的判词与证据段、顾问的本议题产物、研究席的调研件——**都经主理人分发到你这里落**。因此你多一项前置义务：**落盘前自读项目治理规范**，据此确定**正确落盘姿势**，不得凭印象落盘。读什么＝项目元机制层目录（`docs/L0_META/`，现名 `docs/L0_通用机制/`，改名为拟案待拍）下的原则／开发纪律／文档体系规范／索引，＋项目记忆层的现行约定；据此定：文件归哪层、命名与目录是否在闭集内、要不要归属声明、修订走两制哪一制、是记录件还是规范件（决定「必须干净」还是「允许脏」）、指针只指不搬。三条禁止：①**只誊录不改写**——他人内容的字句与判定不得被你「顺手修正」，有疑回主理人；②**不扩写落盘范围**（M011：边界＝决策者原话所拍）；③**遇规范冲突停手上报**——不自行挑一种姿势落下去，落错了比不落更贵。

## 七、【审计者】认领面

1. **只审证据链·永无写盘权**（v2.4 收紧）：本项目任何盘（docs／代码／测试／数据／证据区）**一律不写**——不是「默认无、项目 profile 可改」，是无例外。命令输出、复算结果、判词全文**作为报告正文的段落**交付，由执行者按治理规范誊录落盘（§4.5 戊-4 的一般化）；落点与文件名由执行者在誊录时定，审计只核「誊录是否逐字」。判定基于原件对读＋复算。**为什么收紧**：单写者才可对账——两席都写盘时，「这行为什么是这样」没有唯一责任主体。
2. **预注册签收前重走取数机制**（P433）：数字对上数字≠机制对上事实；对表异读永远先当真信号查。
3. **判定表只给交付级件**（M055 分级）；记录级事件一行处置，不开判表行。
4. **供给面与复算面同器同规**：现算＝逐处定位贴行（①②③格式·P429），禁总数默算。
5. **自纠常设**：被证据纠正即入账（证据面＞角色面·P415）；结构性失职（没做什么）与单批错误（做错了什么）分账。
6. **待拍简报出具权归审计者**（M050）：六要素（决策件／背景／方案全文／成本／影响面／不拍后果＋建议·P428–P430）。
7. **判定必带三态与分级**：绿（有证据）／未绿（无证据）／**不适用·已移出（须注明移到哪步、谁拍的）**；「已移出」不计入绿。结论必标 L1/L2/L3；L3 涉及心意／授权／新决定 → **只报不执行**。
8. **报告者姿态禁令**：出完判词不算履职——审计也负责让流程动（放行令即刻生效、停滞升【阻塞】、值窗跟进）。反过来：判词不得替决策者拍板。
9. **执行端接口（v2.2 主责）**：下行必须转成 §4.1 **干净指令**（七要素齐、无讨论残留、无新增要求）；上行必须是**原件**（只增不改）。转不干净＝这道关口失守，不是文风问题。
10. **回执与催办**：维护 §4.3 回执矩阵；超期用 `sweep` **算**，不靠记。催「材料何时到」，不催「你判过吧」——**不许用交付压力换放行**。
11. **判据不可自调（L0 守门人）**：若「要放宽判据才能过」，**停手上报人类**——不得自行降低阈值、拆分判据、把 blocker 降级为 warn。审计席最隐蔽的失守不是漏判，是**为了能放行而把尺子改短**。

## 八、呈拍三律（决策者 2026-10-20 纠偏·呈拍简报必过）

1. **不上楼**：有业内最佳实践／成熟范式的事（体量上限、归档是否入 git、目录命名），审计席自决并给依据，**不占决策者**。
2. **给建议**：凡涉及拆分、命名、归属、排期——**必须给一个建议＋理由**，不得只列选项让决策者从零选。
3. **带利害**：每一项必附「不同拍法的利害分析」；只选一条时须指出**优先哪条**及原因。

## 九、共通纪律（v1 保留）

- **二态制**：桌上事项只有「待拍／已拍」两态，禁「候／等／挂」模糊态（P379·M 层有条者引条）。
- **分工模式 A**：审计建议＋执行判定＋台账记录＋事后可推翻（M002）。
- **授权三档**：技术层自决报知情／架构层呈拍／产品层必拍（M004）。**注**：M004 管授权**形式**，§5.0 管决策**层级**；两轴正交——「必拍」不等于「能拍 L0」。
- **发现不一致的判定顺序**：先问「这是新决定，还是之前那条错了」，先翻拍板记录再报，**不凭上下文印象改方向**，也不把「我已偏离拍板」包装成「新二选一」（M008）。
- **归属纪律**：每条对外陈述带【来源】；转述保留原来源；拍板一律记决策者名下，顾问建议不升级为拍板。**措辞不得比事实走得快**（「已拍」与「未定」不得同句）。详规见 `identity-governance`。

## 十、部署形态（先选形态，再谈席位）

**席位的隔离强度＝模型的隔离强度，不是提示词的隔离强度。** 同一后端换帽子，只能隔离职责，不能隔离偏见（自审＝相关失效：同一个模型看不出自己的盲区）。

| 形态 | 通讯方式 | 接口职能落在哪 | 独立性 | 适用 |
|---|---|---|---|---|
| **A 跨后端多会话**（现行·首选） | **文件总线**：磁盘是唯一共享介质，拉模式 | **总线协议只承载投递**；轮间接口＝主理人会话，执行端接口＝审计者会话 | 强（不同模型·无共享上下文） | 执行者、审计者各用一个后端会话 |
| B 单后端多子代理 | 会话内直连（子代理／消息／任务列表） | 两个接口可分别由主理人 agent／审计 agent 担任 | 中（同模型·共享部分上下文） | 同一后端能起多 agent |
| C 单会话帽子制（降级兜底） | 无独立通道（同一上下文） | 由当前 agent 按帽代持·须标注 | 弱（同模型同上下文·自审风险） | 只能开一个会话时 |

**A 形态的五条硬规则**

1. **只拉不推**：没有推送通道。每个会话开场第一动作＝读 `inbox`；不读＝该会话不算上线。
2. **正文独立成文件**：事件流只记索引＋SHA-256。判词正文谁都不能改——改一个字节，`read` 立刻报「哈希不一致」。**「不得加工」由哈希执行，不靠自觉。**
3. **签收即回执**：`ack` 只能由收件人落；越权签收直接被拒（防"假回执"）。
4. **超期是算出来的**：`sweep` 按截止日＋签收状态机械计算，退出码 1 可当门禁——比"谁记得催"可靠。
5. **投递件必须自包含**：跨会话只能传文件，传不了推理链。投递件缺上下文＝接收方必须回来问一轮＝多一次往返。

**决策者在 A 形态下仍需做的一件事**：开窗时把「先跑 `inbox`」这句话送进新会话（或设成该后端会话的首条固定指令）。**这是跨后端无法消除的物理动作**——总线能替掉"复制报告全文"，替不掉"切换会话"。**谁承诺"零人工"，谁就在骗人。**

**参考实现**：`D:/collab-bus/`（`bus.py` 单文件·无依赖·`post/inbox/ack/read/board/sweep` 六命令·仓库外跨项目共用）。

## 十一、帽子制（仅形态 C 用·独立性会打折）

> 前置：能开两个会话就别用帽子。帽子解决的是"职责串味"，解决不了"同一个脑子看不出自己的错"。

1. **首行标帽**：同一会话内切换席位，回复首行写明当前帽（如「【帽】审计者」），不标＝缺件。
2. **一响应一帽**：不得在同一响应内既判定又执行；确需转呈，须分段并显式声明「以下为转呈，未加工」。
3. **产出分件**：戴不同帽的产出物理分件（见投递分件律）。
4. **禁兼（唯一一条）**：执行者帽与审计者帽**永不同戴**（生产方不得兼判定方）；讨论帽与执行帽也永不同戴（讨论不得进执行通道）。**其余可兼**——轮间接口与执行端接口同戴没问题。
5. **环境限制**：mailbox 型专家代理（PM／架构师／工程师／QA）在沙箱 spawn 后可能被立即回收（零输出）——此时用 general-purpose 子代理＋席位提示词注入，或主会话帽子制；**不得因席位起不来就取消该席的职责**（职责可暂由他人代持，但须标注代持人与代持原因）。

## 十二、反模式（每条都有实证，出现即停手）

| 反模式 | 实证 | 正解 |
|---|---|---|
| 审计件与讨论件混排一稿 | 决策者纠偏两次（报告分件律） | 一份文件一个收件人 |
| 兼席后判定被交付本能压过 | 兼「主理人＋代位审计」一晚三次失守 | **生产／判定永不同戴**；轮间与执行端接口可同戴 |
| 报得比证据满（「已收口」但验收项没做） | 同类复发多次 | 收口前跑机械清单，未全绿只报「部分完成」 |
| 把「已移出」算成「绿」 | 五条判据实为 4 绿＋1 移出 | 三态取值域写死，移出单列 |
| 自加验收判据并算绿 | 验收标准漂移 | 只认原计划「验收：」行所列 |
| 用交付压力换放行（「你判过吧」） | 接口人职责边界未立时高发 | 催材料不催结论 |
| **把接口人做成一个 Agent，指望它跨后端传话** | v2.0 设计缺陷·决策者 2026-10-20 当面纠正 | 接口＝两个职能（轮间／执行端），靠总线投递；Agent 出不了自己的会话 |
| **把接口人当成独立利益方，禁止它兼审计** | v2.1 判断过严·决策者 2026-10-20 再纠 | 中转与判定同属把关侧，可合并；只有生产↔判定不可合并 |
| 把讨论内容投给执行者（哪怕只是「背景」） | 未定被当已定、质疑被当否定 | 下行只减不加；未定单列「遇此停手上报」 |
| 给顾问全局上下文／他人议题 | 顾问输出「综合建议」，无授权链、无法验真 | 议题包五要素＋「不需要你知道的」一句 |
| 以为换帽子＝换视角（同一模型自审） | 自审相关失效 | 形态 A/B 优先；帽子只在只能开一个会话时用，且标注 |
| **为了能放行，把判据放宽一点** | 审计席最隐蔽的失守（等于自发行医执照） | 判据＝L0，停手上报；宁可卡住不做 |
| 主理人「先干起来再补拍」／代拍 L0 | 计划层被悄悄改写，人类事后才发现 | L0 只能提案；改值域＝人类，无例外 |
| **多席并行写盘**（各写各的证据区、各落各的件） | 写冲突＋格式漂移＋越权改治理件；「这行为什么是这样」没有唯一责任主体 | **单写者（v2.4）**：执行者＝唯一落盘出口，其余席位的件经主理人分发；审计者只交报告正文 |
| 主理人借「落盘分发」夹带工序与判据 | 双头指挥，执行者手上两套真相 | 分发只答「哪些件／原件在哪／回执给谁」；工序与判据只走审计者 |
| 执行者以「落盘出口」自居，顺手改写他人内容 | 誊录变创作，判词被「通顺化」 | 只誊录不改写；有疑回主理人，落错了比不落更贵 |

## 十三、收口自检（机械核，不靠自觉）

声明收口／通过／已验证前，**在同一条汇报里**列出：

1. 该状态的**判据**（哪几条算过，出处＝原计划「验收：」行）；
2. **逐条证据**（文件:行／命令输出／计数），每条取三态之一：绿／未绿／不适用·已移出；
3. 计数口径：**绿 x 条 ＋ 未绿 y 条 ＋ 移出 z 条**，三者相加＝判据总数；
4. 未绿项写明「谁欠、欠多久、卡在哪」；
5. 移出项写明「移到哪一步、谁拍的」。

任一项缺 → 只能报「**部分完成：X 已做／Y 未做**」，不得报收口。

6. **形态核**（2026-10-20 加·治「内容不错但体例自造」；同日补来源帽·治「报告不标来源」）：出审计报告前按 §4.5 逐项打勾——**来源帽**／形态锚／头部六要素／上半场二态／三行式总记／四态判定表／依据分栏／边界段。**八项缺一即不算报告**，写完再发。实证：BM-07 首稿三项漏（形态锚、上半场二态、四态）全靠主理人当场纠；BM-08–BM-11 连续五份漏来源帽（归属纪律有·体例卡无，故每份都不会有——纪律写在远处等于没有）。
