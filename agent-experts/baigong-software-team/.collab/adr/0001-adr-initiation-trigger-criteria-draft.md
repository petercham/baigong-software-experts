# ADR-0001：ADR 立项触发判据（判据成文批＝触发批·案 a 自指点火）

终写落位＝`docs/adr/0001-adr-initiation-trigger-criteria.md`（NNNN 四位制）。本件＝会签前草案；终写件＝四方收口草案之逐字照录（条款甲）。

- Status：Accepted
- Deciders：皮总（案 a 裁定）＋产品席＋QA席＋架构席会签
- Date：`2026-11-05`
- Author：架构席（起草）
- Registrar：主理人（誊录）

（`- Supersedes：` 行缺省不设＝首支无取代对象，E-ADR-3″ 对缺省态真空真。）

## 背景

ADR 工序链此前只解决「怎么写」，无「何时写」立项线。两处实锤：其一，ADR 工序票全文「触发」五处全为门禁挂载时序语义，零立项触发语义；其二，首支 ADR 与触发批互为前提成死结——收口双前置要求「首支 ADR 实际落 `docs/adr/`」且「触发批同批实装挂载与校验器」：无判据则无触发批，无首支则双前置永不触发，`docs/adr/` 永不诞生。

决策者裁定（案 a）＝判据成文批即触发批：判据本体命中工序链改动信号，按判据自身立首支 ADR（本件），同批完成 `docs/adr/` 初始化＋门禁挂载＋E-ADR 校验器实装＝双前置合法闭合。本 ADR 即该裁定的记录件。

## 决策

采纳立项触发判据如下（与 `standard-sop.md` ADR 工序节第 6 款落包文本同源对等）：

```
入线（命中任一＝该决策应立 ADR，走决策记录链）：
- T1 真源形态改动：改变任一纪律/配置/条款的「唯一真源」载体或形态（哪卷哪桶哪 config 承载何规则）。
- T2 文件域结构改动：改变目录布局、写域结构、落位规则或三层文件域边界（含 `.scratch` 落位、docs/adr 落位、仓根分层）。
- T3 席位职权改动：改变「谁有权动什么」（写权/拒权/会签设计/工序签核面的新增或换代）。
- T4 工序链本体改动：新增/退役/换代工序环节、票型、门禁挂载机制或签字面。
不入线（命中且入线零命中＝留 decisions 级，不立 ADR）：
- N1 案内程序裁定：单票射程内的放行/候裁落拍/豁免注记/审票修单处置。
- N2 一次性执行处置：换钉、装配、迁移、清理、解冻等随批耗尽的批处置。
- N3 口径数字微调：阈值数值、排程、估算界差等无结构语义的调整。
混合件＝拆分处理：一件决策同时含入线与不入线要素时，ADR 只誊入线句（附 decisions 原件路径引用，不复写正文），原件 append-only 不动。
覆盖链：新口径覆盖旧口径＝终态案立 ADR、旧案留 decisions 史实不回改，ADR 头块标取代关系（E-ADR supersede 双向互链机理）。
申诉线：席位对初筛结果有异议＝候裁呈报，不现场改判据；初筛可机械＝对 decisions 登记件按入线四词的关键词 grep 出候选清单，终判归会签三席。
```

编号形态随定＝四位 NNNN（文件名正断言 `^(\d{4})-`）；E-ADR 族五断言（头块五行／文件名断言／supersede 双向／accepted 不可变＋注记白名单／三桶对账和式）同批进机检面。

## 后果

- 工序入口闸生效：新决策按本判据初筛（机械候选清单）＋会签三席终判；「何时写」与「怎么写」两段工序自此闭合。
- ES2 收口双前置①②随本批闭合：`docs/adr/` 由本批初始化，首支＝本件；挂载与校验器同批实装（同票不同 commit 合法）。
- 初筛机械面依赖 decisions 登记件关键词纪律：登记件标题/正文含结构性关键词者入候选，不改变「终判归会签」职权分配。
- 历史存量决策件是否补录为 ADR（编号 0002 起）不在本 ADR 射程＝另案候裁；本判据只辖生效后的运行时决策，不追溯改写历史件。

## 自指合法性注记

本 ADR 的记录对象＝立项判据自身：「判据立项」这一决策命中 T4（工序链本体改动＝新增工序入口闸）＝按判据自身而立，构成合法自指。自证点＝判据管辖对象＝运行时决策的立项时机，不辖记录件自身的诞生形态；自指不产生循环，因判据文本先于本记录件定稿（判据＝同批 SOP 落包件，本件＝其结果记录），先后关系由同批链序固定。会签三席对本段逐席表态。
