## 目 B·业界最佳实践对照＝黄（黄-1 一条修单）

时效窗口＝近 3 月检索（2026-08 至 2026-11）；权威层级＝行业多源一致（Anthropic 多代理系统实践口径／OpenAI 多代理文档口径／Claude Code 子代理与 fork 身份机制实务）>单站。

**B-1 同席多实例禁令方向与业界一致＝绿。** 业界对重复实例/无界 fan-out 的主流拦截面正是**编排者派发侧**（orchestrator 控并发槽位与分支上限、spawn 前先划定归属；Anthropic 多代理研究系统＝lead 统一指挥子代理；Claude Code 官方对 agent teams 的警告＝同文件双席互覆写应回单席或子代理串行）＋**被派侧拒绝/上报**兜底。票面把拦截重心放主理人派席纪律、席位侧拒产并报为辅防线，与此口径同构；且明确否决机件化（登记表/租约扩展）＝YAGNI 上与「glue 应为最简确定性」的通行取向不冲突（该选择系裁定层拍定，票面忠实照载）。

**B-2 「第二实例停手并报」责任路径闭环性＝绿。** 检出（席位自查同身份重复受派）→ 停手不产出 → 向上报告 → 违例入健康账（§三4）——路径名义闭环，且与前案 §6「违例处置＝登记健康账」衔接。观察点（不构成修单）：无机械面时席位侧自检的检出前提较弱（实例互不可见），但此为终态裁定明示的非机件路线（裁定已作废「应机件化」方向），票面无权自行补闸；拦截实效主要押在主理人侧「派发时该席位存在在途实例」判据——主理人自持派工台账，该判据在主理人侧可操作 ✓。登记观察点 O-1。
