## 一、问一：ADR 是否需要补录？范围边界如何界定？

### 1.1 判定标准（先成文·可机械初筛）

ADR 级判定三信号（命中任一＝候选；全部不命中＝留 decisions 级）：

- **S1 结构信号**：决策改变/新建**文件域结构**（目录布局、写域、落位规则）或**机件形态**（门禁/租约/探针/校验器的存在形态）。机械初筛＝件内含「落位/写域/目录/新增工序/机件化」类词＋决策对象非单票。
- **S2 职权信号**：决策改变**席位职权线**（谁有权动什么）或**工序链形态**（新增票型、节点换代）。
- **S3 跨期信号**：决策效力**跨批长期生效**（纪律/口径类，非当票收口即耗尽）。机械初筛＝后续卷面/条款面存在该决策的**消费引用**（如已沉淀成 standard-sop/dispatch 卷条款）。

排除线（不入 ADR）：
- **程序内处置**：某票射程内的放行/候裁落拍/预算豁免（例：判据7豁免2token、CARD-RENEW 候裁八条）——属史实登记，非架构决策。
- **一次性执行处置**：换钉、装配、迁移执行批（例：EAC ref 换钉 v1.1.2）。
- **判词族**：`verdicts.md` 判词分账＝三族分权独立桶（ES 定标案在册：裁定登记族/ADR 正件族/判词族），永不入 ADR。

### 1.3 补录与否两案对比（只出方案不施工）

**案甲·批量补录**（7±1 支）：
- 工序：每支走 ADR 工序链全链（人类输入→誊录→三席会签→架构终写）＝7 支×全链≈7 次双席审票＋会签轮；批量并行违「同席多实例禁令」＋派席串行口径＝**只能串行**，成本≈7 个批次轮次。
- 收益：docs/adr/ 从 0 到有、STRUCTURE L11 声明与实态对齐、E-ADR 校验器/60-gates 挂载获得首个实装对象。
- 风险：补录件＝事后重构语义，会签对象是既成事实（会签易流于形式）；拆分件（B13）有誊录失真风险。

**案乙·decisions 桶加 ADR 级标记行**（轻量替代）：
- 做法：ADR 级 8 件件首各加一行标记（如 `- adr-candidate: 是（S1S3）`），decisions 桶加一张索引件（`.collab/decisions/ADR-CANDIDATES.md` 名册）。成本＝一次微型批（每件一行＋一名册件），不触工序链。
- 收益：边界判定先落账、可推翻可复议；将来首支真 ADR 落盘时名册即候补清单。
- 代价：STRUCTURE L11 的「声明与实态漂移」（红-2）持续存在。

**架构席倾向**：**案乙＋首支前瞻 ADR 一支**——补录历史 7 支收益低于成本（会签语义失真），但 TMP-DISC 四款口径（2026-11-05 决策者已裁·决策原件尚在未来收口件）属「新鲜决策」，**下一支 ADR 建议留给 TMP-DISC 口径**（走全链、决策原件在手＝会签有实体可签），顺带按候裁③完成 docs/adr 初始化＋E-ADR 校验器＋60-gates 挂载三件实装。案乙标记行随该批同批落，两案并收。此为建议，采否候决策者拍。

### 1.4 ADR vs decisions vs changelog 分工线

- **一句话判据**：decisions＝**决策发生时的逐字史实登记**（主理人誊录权·append-only·决策效力锚）；ADR＝**已收敛架构决策的规范记录**（会签收口＋终写·supersede 链管理·docs/adr 永存面）；changelog（README 版本账）＝**交付面变更的逐版流水账**（改了什么文件面，一行为主）。
- **灰区处置规则**：同一决策三态并存不冲突——原始拍板永远在 decisions（史实层不动）；够 ADR 级的**另立 ADR 记录它**（记录面引用 decisions 路径，不复写正文）；changelog 只记该批交付文件变更。三线锚＝「史实归桶、规范归册、流水归账」；拿不准＝按 §1.1 三信号机械初筛，命中即入 ADR-CANDIDATES 名册候裁，不现场裁。
- **业界锚引**（四件套承重在盘件内，本件不重引）：产品席调研件 `.collab/research/2026-11-04-ADR归属范式调研-产品席-v1.md` L21-31（R1-R8 四件套登记表＋承重标注）、L35-41（Nygard R1 原文：无角色指定/stakeholders 一致即 accepted/落版本库）、L43-49（ThoughtWorks R2 Adopt 无角色表述＋MADR R3 纯程序指引）。其与本仓工序差异点一处值得记录：**业界 accepted 条件＝stakeholders 一致，本仓＝人类输入决策＋三席会签**——本仓把「决策所有权」显式留人类侧（standard-sop.md L52 保留项闭合归位段），比业界更严，不违范式（Nygard 未设角色＝本仓加角色属合法变体）。

### 2.3 审查机制两案
