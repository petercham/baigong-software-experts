## 二、重点问题详述

### 2.1 A01：唯一查无实源的锚点（DS）

DS 将三层模型归于 "agentic-workflow" 并给出「最小 persona 约 3KB」「QA backend persona 很小，引用大的 skill」「五条分离理由」三个可检验细节。已查：GitHub 三个同名仓库（均为其他项目）、agentic-workflows.com（咨询站）、6+ 组中英文检索词含两个精确短语——均无匹配。结论：**来源不可证实**。但需与皮总纠偏令区分——三层分离的**方向**与官方机制兼容（官方 memory 文档即常驻/按需判据），可作为设计约定采纳；不可的是把「3KB」「QA backend persona」当作已验证事实写入呈报。建议 DS 补 URL，或全文改述「社区通行三层约定（如 startmeup.ai 等）」。

### 2.2 A04：CoALA「缓建判据原文」未定位（GLM）

GLM 以引号标注了两句「原文」。三次渠道（arXiv HTML v3 全文、ar5iv 镜像全文、alphaXiv 概览）未定位；最接近的官方原文是 §6 的 "Determine what memory modules are necessary"（零售助手示例）与最小动作空间原则。诚实边界：两次全文抓取均在 §6 后被截断，§7 Discussion 未完整获取，不能断言原文绝对没有。GLM 用该判据支撑的**结论**（Ontology 缓行）与论文总体立场相容，但引文形式（逐字原文）不成立。建议改标「转述」或补章节号。

### 2.3 A12：「CCS 2025」系误标，实为 CHI '25（GLM）

论文存在且主题吻合，但发表于 CHI '25；"CCS" 来自 ACM 参考格式的 "CCS Concepts" 分类索引。另「三件组合」「而非更强的单次生成」为综合转述，论文（N=22 定性研究）未作此对照。建议更正会议名并将结论句改为「与该研究一致」。

### 2.4 A02：版本间数字修订（DS）

DS 引的 75 agents/16GB/12.5MB 与 Zenodo 2026-05 版摘要逐字吻合；论文主页更新版为 139 agents/约 16MB/2.2GB。非引用错误，但呈报时应注明所引版本（DOI 10.5281/zenodo.20098027），避免与其他版本数字打架。

### 2.5 A03：官方依据被拼合成一句（DS）

「源码永不进入上下文」有工程博客逐字依据；「scripts 通过 Bash 执行」散见规范页（Bash 为常用语言）与博客（Bash 读 SKILL.md）。结论成立，措辞系拼合。无需更正事实，呈报时不必加引号当作单句原文。

### 2.6 A06：数字全真，两处限定被转述遗漏（DS）

12.06%、69.13→84.03、多 backbone 提升均逐字属实（这是本轮重点盯号项，全部过关）。遗漏的两个限定改变证据强度：全部增益在 SAGE 模拟环境测得（无真人验证）；增益来自自演化闭环 B*，静态技能库反而更差。「Agent Harness」为论文运行时小节名（DEERFLOW），出品方为苏州大学＋阿里云。

### 2.7 A09：一句「官方原句」查无实引（GLM）

"For task-specific instructions that don't need to be in context all the time, use skills instead" 未在任何渠道检索到。语义对应的官方判据在 Claude Code memory 文档（"If an entry is a multi-step procedure or only matters for one part of the codebase, move it to a skill or a path-scoped rule instead."）。其余 A09 子项（500 行线、what+when、三级披露、eval-first、能力域组织）均与官方文档吻合或一致转述。
