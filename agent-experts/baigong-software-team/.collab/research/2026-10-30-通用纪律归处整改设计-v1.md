### 1.2 条款草案全文（甲稿·engineer 受票照写入）

**A. software-orchestration `references/dev-discipline.md`（新建卷全文）**

```
# 通用开发纪律（写权闭集·代码纯度·回执清单·QA 纯净）

> 出处：本地约定（跨项目·全专家/技能开发通用·四件一体成文）。席位级权限声明真源在各席位 MD
> 「写权边界」节（互指不复写）；机检判据真源见审计器文档域 D6-3 与干净度测 T6（只指不搬）。

## 一 写权闭集

1. 交付物域（`.collab/` 以外一切交付面：deliverables/、bundle 装配体、专家包、技能包、组件包）
   **只有工程师（程序员）席有写权限**。
2. 其他席位（主理人/产品/架构/QA/研究）的一切产出＝过程件，只落 `.collab/` 过程域
   （设计稿、分析、判词、回执、票面）。
3. 派工合规硬门：主理人拟票/派工时，凡含代码性质或交付面写入的任务**只派工程师席**；
   派错＝席位按「拒写权」条款拒绝并回报改派（席位 MD 自带该声明·第二道闸）。
4. 席位拒写权：非工程席受命向交付面写入时，有权且应当**拒绝写入＋报主理人改派工程师席**；
   拒绝不构成违例，执行才构成违例。

## 二 代码纯度

1. 工程师写入交付面的内容不得携带过程件指针：出包路径（仓案面/.collab/*/盘符路径/
   家目录路径）、不可解析编号（案卷实例号）、开发叙事（为什么改/怎么改）一律不入交付件。
2. 交付包内一切指针只准**包内闭环**：非 sources 文件的指针只准指向包内非 sources 文件；
   `sources/` 子包＝唯一允许进交付物的自包含料源，其内部指针同样不得出包。
3. `sources/` 内容闭集＝只含干净的蒸馏/沉淀记录；纠错件、案卷、票面、复盘、拍板指针
   等开发迭代过程物一律不得混入。
4. 判据细则与豁免口径以审计器侧 D6-3/T6 为真源，本节只载纪律不复写机检参数。

## 三 工程师完工回执

1. 工程师每张交付面执行票的完工回执**必须完整包含本次写入/修改的文件清单**
   （路径逐项列出，含新建/修改/删除标记）。
2. 对账口径＝`git show --name-only <commit>` 与回执清单**全等**；缺项/多项＝违例（回执失真）。
3. 回执落 `.collab/` 过程域；commit message 不替代回执。

## 四 QA 纯净职责

1. QA 对回执清单**逐件**检查是否混入过程件或过程件指针（判据＝审计器 T6/D6-3 口径＋人工抽验）。
2. 交付面纯净性责任在 QA：漏检＝QA 未绿项，不回落工程师自证（生产方不兼判定方）。
3. QA 的判词落过程域；判词点名违例文件路径与命中模式，供返工票直接引用。
```

## 二、交付物引用可达性机检设计（㊺闭环判据版）

### 2.1 spec_id 与前缀注册机制（先核后定）

run-gates.sh `SPEC_ID_HOME` 现注册前缀＝{OA, OB, MC, PUB, EAC}；读表规则 5 按前缀反查提供者包规范件解析条款。**禁 EAC-\* 用于通用纪律**→本机检取既有前缀 **OA**（提供者＝object-audit，条款＝本设计 §1.2-B 的 D6-3）：

- 主 spec_id＝**`OA-D6-3`**（指针闭集·每出包指针一条 finding）；
- 可达性子检查＝**`OA-D6-4`**（交付包内反引号 .md 指针须包内解析可达——与 MC-SOT-2 的仓内指针域不同：MC-SOT-2 扫 agents/skills 注册面对仓根解析，本项在**包边界**内解析）；
- 零新增前缀＝SPEC_ID_HOME 一行不动（红线：本票设计不触既有脚本语义；OA-* 天然可解析）。

进表时序循「条款先落盘→机检后进表」铁律：WP-2（B/C 条款落 references/SKILL）先 commit，WP-3/WP-4（脚本＋进表）后 commit，顺序对账。

### 2.2 扫描面

| 面 | 内容 | 口径 |
|---|---|---|
| 缺省 | `deliverables/skills/external-advisor-collab/`（同仓 tag 组件包）＋`workbuddy/**`（bundle 装配体·含注册态 skill 卷） | 仓内可跑 |
| `--pkg <dir>` 参数 | 跨仓组件包（skills 仓 deep-research）与装配预览面（`<仓>-build/<bundle>`） | 交付态面显式指入，不猜路径 |
| **不进扫描面** | `.collab/**`（过程域本体）／`deliverables/` 其余规范件首挂期只给 WATCH 信号（见 2.4 分级） | 扫描面收窄＝主豁免 |

### 2.3 判据与模式（四模式＋可达性）

```
P1 出包案面路径   \.collab/            （含 .collab/qa/ .collab/research/ 等一切仓案面）
P2 盘符路径       (?<![A-Za-z0-9])[A-Za-z]:[\\/]{1,2}…（循 check-entity drive-path 口径）
P3 宿主家目录     ~/ 与 .workbuddy/     （泛指措辞不算：无 ~/ 前缀的中文陈述不触）
P4 案卷标识       2026\d{4}[ab]?-\d{3} / [a-z]?-0\d\d\b(案卷实例段) / \d{3}\.txt / reference-2026
可达性            反引号内 *.md/*.py 相对指针 → 以包根解析；不可达＝OA-D6-4 WATCH
```

每 finding 一行：`<file>:<line>: <SEV> OA-D6-3|OA-D6-4 <一句话>`（SEV 由脚本给 WATCH；拦放由路由表给）。

### 2.4 严重度与分级（首挂）

- 交付包面（缺省扫描面）命中＝**WATCH**（advisory 首挂）——EAC-CLN 人工四模式扫描已实证该面现零命中，advisory→block 升档＝实跑零误报读数入 evidence 后改表（60-gates 配套规则 1/2 通道）。
- `deliverables/` 其余规范件（六件域外）＝仅计数行提示不计 finding（避免「规范件引用仓治理面」的合法形态被误报——如 60-gates.md 指 evidence 路径属仓机制件对仓盘面引用，非交付包）。

### 2.5 豁免三范式沿用（照 check-collab-lint 成文号）

1. **扫描面收窄＝主豁免**：只扫交付包面，过程域/域外规范件天然不入；
2. **行级豁免标记**：行内 `〔史实锚〕` 或 `T-<名>-<n>` 豁免注 ⇒ EXEMPT（循 check-entity L85-89）；
3. **EXEMPT/SUBSTR/VIOLATION 三态分账**：代码围栏/反引号段内示例＝SUBSTR（禁模式引用不被禁模式杀掉·自咬反例必测·循 check-truename L143 口径）。

### 2.6 新脚本与挂载

- 新建 `object-audit/scripts/check-pointer-closure.py`（只读·纯 stdlib·约 180 行·循 check-collab-lint 风格）；provenance 块 spec_file 指 `deliverables/object-audit/references/50-document.md` 锚 D6-3 行（**先落条款后落块**，否则自咬 exit 3）。
- run-gates.sh SCRIPTS 清单尾加 `check-pointer-closure`（一行·与 check-collab-lint 同侪位）。
- 60-gates json per_spec 增 `OA-D6-3`/`OA-D6-4`（advisory）＋§四 对账表两行（依据状态＝足·条款随 WP-2 已落）。
