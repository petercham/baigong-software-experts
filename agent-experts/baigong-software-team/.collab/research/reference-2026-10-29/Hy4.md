蒸馏知名人物（比如导演、作家）的创作、表达技法偏好、品味倾向，蒸馏某一类书籍、著作的理论、思想框架，有没有成熟的方法论或者工程范式？

有，而且已经分化得很清楚——**不是一套方法，是"两层对象 × 三条路线"**。下面按可落地程度排。

## 先说共同骨架

不管蒸馏人还是蒸馏书，成熟工程都是这五段：

**语料清洗归组 → 分层特征提取 → 固化成载体（规则文档/图谱/向量）→ 每次调用前重新加载 + 原文校准 → rubric 评估闭环**

跳掉第四步（"蒸完直接用"）是最常见的失败原因。

## 一、蒸馏人物（导演/作家）

**路线A｜文体计量学** ——最老的硬功夫，管"指纹"
源流是 Mosteller-Wallace 判《联邦党人文集》，主力是 Burrows's Delta 和 FW-PCA（功能词主成分分析，R 的 stylo 包直接可用）。特征是功能词频率、字符/词 n-gram、词性序列、句长方差、标点密度比、Honoré's 词汇丰富度。进阶做法是功能词邻接网络（WANs），把句子内功能词的先后顺序建成马尔可夫链再用相对熵比对——抓的是"虚词怎么排"，不是"用了几个虚词"。中文要先解决无词边界问题，别直接用分词做词频。
**它的能力边界很清楚：能做归属判定和可解释比对，做不了生成。**

**路线B｜Persona Vectors** ——激活空间里的线性方向
Anthropic 2025 的工作（arXiv:2507.21509）把"谄媚/邪恶/幻觉"这类特质变成了可计算的向量：自然语言描述特质 → 自动生成对比 prompt 对 → 判官打分（人机一致性 94.7%）→ 提取残差流激活 → 差分得向量。几个实操要点：取 **response token** 的平均激活比 prompt 层有效；逐层生成候选再选操控最强的层（Qwen 在第 20 层）。最实用的是"投影差 ΔP"——微调前就能预测数据集会把模型带偏多少，等于一个不用真跑的预言机。
同一思路的官方产品化版本是 Anthropic 的 Soul Doc：一万多 token，写的不是"不许做 X"，而是**认知架构**——价值观优先级层次、利益相关者模型、多维目标分解。这对你蒸馏"品味倾向"特别有参考价值：**品味要写成判断框架，不是规则清单。**

**路线C｜上下文蒸馏（当前最实用）** ——改注意力，不改权重
2026 年这批写作/人格蒸馏 Skill 就是这个范式：六层拆解 L1 语言层（词频、句长、标点、节奏）、L2 结构层（开头钩子、转折、分节、收束）、L3–L5 认知层（选题视角、素材偏好、世界观与价值判断）、L6 视觉层。
硬门槛：**≥20 篇完整原文、单篇 >1000 字、体裁必须统一**——日记和论文混着蒸，模型会取中间值，两头都不像。
为什么这里不用微调：几十万字相对预训练的万亿 token，信号太弱，权重几乎不偏移，推理时又无显性提醒，风格会飘。**微调改的是底层记忆，蒸馏改的是此刻的注意力焦点**。

**品味倾向要单独处理**：品味本质是偏好排序，不是风格特征，得走偏好蒸馏（pairwise/DPO）。关键区分是先验偏好（长期稳定）与后验偏好（目标条件化、细粒度），两者互补、单用都有偏。评估也别只看准确率，要加多样性和惊喜度。

## 二、蒸馏书籍/著作的理论框架

**路线A｜知识图谱流水线**（结构化、可推理）
标杆是 K12-KGraph 五阶段：OCR 解析 → 按目录切节 → Schema 约束的 LLM 抽取（要求回带原文证据句和置信度）→ 自下而上合并 + 别名对齐 → 拓扑校验 + 人工复核。
两个比工具清单更值钱的设计决策：**切片要带语境**（块头注入章节位置，否则"他杀了父亲"脱离卷次不可解）；**词典先于图谱**（先抽实体词典、清洗泛称词、再做语义归并，否则同一人物会散成多个节点，图质量从根上就烂）。
铁律：**先定 Ontology/Schema，再让模型抽。** 本体没定义清楚，抽得越多越乱。

**路线B｜扎根理论 + LLM**（适合理论性强、非结构化的书）
三级编码：开放编码（出现了什么）→ 主轴编码（codes 之间什么关系）→ 选择性编码（如何组织成理论解释）。
正确姿势是**研究者先自己编一遍，再让 AI 并行编，然后三角验证差异**——浸入资料这步不能外包，否则会"过早关闭解释"。编码手册要有定义、纳入标准、排除标准、典型与非典型示例，层级最多三层。

**路线C｜概念分层抽取**（做"可调用"的知识资产最省事）
概念按类型分五档：Principle（公理）→ Mechanism（如何运作）→ Pattern（重复结构）→ Strategy（高级方法）→ Tactic（可执行技术）；再配抽象层级 0–4 和关系类型（INFLUENCES / SUPPORTS / CONTRADICTS / COMPOSED_OF / DERIVES_FROM）。书的类型也该决定工作流重心：理论范式型重结构化、操作手册型重步骤固化、思维认知型重批判补全。

## 三、评估——最容易被跳过的一步

通用奖励模型在角色/风格这类主观维度上会严重退化，专用 RM（如 RoleRM）能拉开 24% 以上。中文可参考 CharacterEval 的四维十三指标。风格迁移别用 BLEU，用三项组合：风格准确率、内容相似度（BERTScore）、以及**风格—内容权衡曲线**——画一条曲线比报一个点数诚实得多。另外，模型自生成的 rubric 目前仍显著差于人类专家写的。

## 四、三条硬边界

- **能蒸到"皮"，蒸不到"骨"**：句长、节奏、用词、视角切换频率、爽点节拍可以；伏笔的宏观判断、动机设计、哪里该留白的审美选择、几百章的长程一致性不行。
- **素材质量锁死上限**，聊天记录、口播逐字稿往往比精修稿更接近真实表达系统。
- **校准是活的**：每次产出标"像/不像"，把"哪不像"逐条写回说明书并升版本号，这是个飞轮。

**怎么选**：只想写得像 → 路线C（零算力，一天内能跑通）；要可解释、能验证归属 → 路线A；要可控开关、可监控漂移 → 路线B；语料到几十万字以上且要求长期稳定 → 才考虑 SFT/GRPO 那套（RAIDEN-R1 的可验证奖励思路可借鉴）。

需要的话，我可以按你具体要蒸的对象（某位导演 / 某类书）直接搭一套可执行的蒸馏模板。

那么女娲和仓颉skill 是哪种？

查清楚了，这两个正好是我上一轮框架里的**路线C（上下文蒸馏）**的两个代表实现——都不碰权重、不改模型，产物就是一份可反复读取的 `SKILL.md`，普通电脑就能跑。但一个蒸人、一个蒸书，分工非常清楚。

## 女娲 nuwa-skill：蒸"人"的认知操作系统

**属于人物蒸馏，但注意它蒸的不是文风。** 这是最容易搞混的一点：蒸馏"怎么写"（句长、节奏、用词、文风）是 writing-dna 那一类；女娲蒸的是 **HOW they think**，不是 WHAT they said。

流程是考古队式的：
- **六路并行采集**：著作 / 播客访谈 / 社交媒体 / 批评者视角 / 决策记录 / 人生时间线，六个 Agent 各自独立存档
- **三重验证提炼**：跨域复现（≥2 个领域反复出现）、有生成力（能推断对新问题的立场）、有排他性（不是所有聪明人都这么想）。三条全过才叫"心智模型"，只过一条降级成"决策启发式"，一条不过就扔
- **五层产物**：表达 DNA、心智模型（3–7 个）、决策启发式（5–10 条）、反模式/价值观、诚实边界

它最值得抄的设计有两个：**一是"诚实边界"段**——每个 Skill 必须写明自己做不到什么、哪些是推断；**二是验收方式**——用 3 个此人公开回答过的问题测方向一致性，再用 1 个他没讨论过的问题测它会不会表现出适度不确定，而不是瞎编。这正好补上我上轮说的"评估最容易被跳过的一步"。

## 仓颉 cangjie-skill：蒸"书"的可执行方法论

**属于书籍蒸馏，但注意它不走知识图谱路线。** 它不做概念网络，做的是**Agent 能直接调用的能力卡**——区别在于产物带 trigger（什么时候该调）和判停条件，而不是"这本书讲了什么"。

方法论叫 RIA-TV++：
- **RIA** 来自赵周拆书法，**TV** 是三重验证（跨域佐证 / 预测力 / 独特性，通过率通常只有 25%–50%），**++** 是面向 Agent 的扩展——**E**（可执行步骤，每步带完成标准和判停条件）+ **B**（边界，什么时候不该用）
- 底层先做 **Adler 分析阅读**（《如何阅读一本书》的四层阅读）产出 BOOK_OVERVIEW，再派 5 个专项提取器并行扫框架/原则/案例/反例/术语
- **压力测试含诱饵测试**：故意给不该触发的场景，看 Skill 忍不忍得住

v2.5 之后有个架构变化很关键：**能力和产物解耦**。先维护一份能力卡 Bundle 作为单一事实源，交付时再编译成形态——`single`（一个路由入口 + 卡躺在 references 里按需叫号）或 `compact pack`（少量真正够格的独立技能）。《纳瓦尔宝典》从 19 个平铺技能压成 1 个入口，目录载荷从 3,897 tokens 降到 340。晋级门五条：独立意图、独立契约、独立运行（前三条必过）、独立复用、独立评测（后两条至少过一条）。

## 回到你的框架，它们帮你补了什么

| | 女娲 | 仓颉 |
|---|---|---|
| 蒸馏对象 | 人（思维方式、表达 DNA） | 书/视频/播客（方法论、框架） |
| 在我上轮的位置 | 人物路线 C | 书籍路线 C（不走图谱） |
| 核心机制 | 六路采集 + 三重验证 | Adler + RIA-TV++ + 诱饵测试 |
| 产物 | 人物 Skill + 诚实边界 | Capability Bundle → 编译 |

两个共通、也最该直接抄走的工程纪律：**负例必须写进产物**（女娲的"诚实边界"、仓颉的 B 段和诱饵测试——只写"擅长什么"不写"别拿它干什么"，兄弟技能之间 agent 一定分不清）；**淘汰的候选留档**（仓颉的 `rejected/` 可查，coverage-audit 回答的是"哪些留下了、哪些扔了、为什么"）。

生态里第三个是 **darwin-skill**，负责让已有 Skill 自动进化。三者咬合：女娲蒸人、仓颉蒸书、darwin 持续更新适用边界。

**怎么选**：想借某人的脑子看问题 → 女娲；想让某本书的方法论在遇到场景时自动被调用 → 仓颉；想模仿某人写东西 → 这两个都不合适，该用 writing-dna 那类文风蒸馏。

一个诚实的提醒：这类蒸馏本质是"公开表达的考古学"，是调研时间点的快照，遇到对象从未讨论过的问题时它做的是推断——好的实现会标注置信度，差的会斩钉截铁地编。

我想评估的就是他们的蒸馏方法论扎实吗？科学吗？

直接给结论：**工程上是扎实的，科学上是没被验证的。** 这两个要分开评价，混在一起就会高估它。

## 先说它真做对了什么

不是客套。仓颉和女娲把一件原本靠手感的事，变成了有检查点、有留痕、可复现的流水线，这已经超过绝大多数同类工具。

- **诱饵测试（负例测试）**：不只测"该触发时触不触发"，还测"不该触发时忍不忍得住"。这是从软件工程的 negative testing 借来的，是真东西。有实操记录靠盲测揪出 3 个 description 歧义，修补后触发准确率 88% → 100%
- **产物强制写负例**：B 段"什么时候别用"直接来自批判阶段，没有 B 段的 skill 会被过度调用，反而帮倒忙
- **淘汰留档 + coverage-audit**：回答的不是"这本书讲了什么"，而是"哪些留了、哪些扔了、为什么"。可审计性是科学态度的组成部分。
- **晋级门的可证伪判据**："能不能写出'该触发/不该触发'的断言来测它"——这条本质是在要求可测性，思路正确。
- **源分级补丁**：女娲后来加了一手 > 二手的优先级、要求 primary source ratio > 50%、把知乎公众号列入黑名单。说明它在朝正确方向进化。

还有一个很稀缺的信号：仓颉作者把自己 v1.1 拍脑袋定的阈值（30%/95%/F1 0.85）和"19 份测试报告全是降级自测、100% 通过"写进方案当反面教材，改成基线出来前一律标 TBD、只保留两类硬门。这种元诚实比星数值钱。

## 但"验证"这两个字是被误用的

**所谓"三重验证"，其实是三条收录启发式，不是验证。** 验证要有 held-out 集、对照基线、量化指标、盲评——三条里一条都不满足。

更麻烦的是：整个链条是 LLM 采集 → LLM 提炼 → LLM 三重验证 → LLM 压力测试。**裁判和被评是同一个模型家族。**

这不是我苛责，是有硬数据的：
- AI 评审之间一致率 79.4%，但与人类投票一致率只有 **56.9%**
- 模型偏爱自身答案的程度比人类高 **70%**
- 自我偏好偏差幅度实测在 **-38% 到 +90%** 之间
- 医学评测里 GPT-5.5 自评与人类专家的相关性 Kendall's tau = **-0.200**，是负的

在这种噪声下，一份"100% 通过"的测试报告，信息量接近于零。缓解办法是现成的：位置对调取平均、跨家裁判投票、给明确 rubric、参考答案引导、人工抽检校准——这套流水线一个都没系统采用。

## 六个硬伤

**1. 没有 ablation，这是最致命的。** 有独立评测者直接点破：只验证了"像不像"，没验证"有没有用"——这个 skill 给的建议，和直接问 Claude"如果你是芒格会怎么想"有多大差别？没有 baseline 对比，就无法证明蒸馏过程增加了价值。

**2. 预训练先验问题（比上面那条更深）。** 芒格、纳瓦尔、巴菲特的公开材料早就在模型预训练语料里了。六路采集捞回来的信息，有多少是超出模型已有知识的？从没测过。

更尖锐的是：蒸馏很可能只是在**引导模型调取它参数里已有的记忆**——如果真是这样，它确实有效（这正是上下文锚定机制），但那验证的是"提示工程有效"，不是"蒸馏提取出了新东西"。这两件事完全不同，现在被混为一谈了。

**3. 无信度检验，方差未知。** 实测反馈很一致：同一个 skill，用 GPT-5.4 跑出来的和作者用 Claude Code 展示的明显不同；"效果高度依赖模型"。蒸馏一次就是 N=1，没有重复测量。科学上这叫没有信度。

**4. 那些数字不该当指标看。** 社区流传的"通过率 25%–50%"没有说明统计口径、样本量和评分者一致性。对比一下同一时期 K12-KGraph 用 12 名标注员、报告 Fleiss' κ = 0.84——那才是可核查的信度。没有 kappa 的通过率是修辞。

**5. 信源的选择性偏差无法修复。** 独立评测者说得很准：你拿到的可能只是此人**公关形象的蒸馏**。决策黑箱从未披露，公开表达 ≠ 真实想法。有人实测张雪峰 skill 的评价是"像，但不是"——"能复刻一个人的逻辑，但复刻不了他在那一刻的犹豫"。

**6. 幻觉会固化并放大。** 用户实测发现 AI 会顺着逻辑往下写，写出书里根本没有的观点，而且写得像模像样。中间环节的幻觉一旦被固化进 SKILL.md，会在之后每次调用时被反复放大，且没有人在环校验。

## 我的总评

**定位应该改：这是工程方法论（engineering discipline），不是科学方法论。**

它整套流程能证明的是**内部自洽**，不能证明**接近真人或实际有效**。前者是 self-consistency，后者是 accuracy，差着一个量级。

如果照那位独立评测者的 78/100 来对齐，我的分项是这样的：工程设计 90（top 级）、可审计性 85（留档和诚实边界做得好）、方法论严谨度 65（三重验证名不副实、无基线）、效果验证 40（自评循环 + N=1）、适用边界声明 80（诚实但不够狠）。

## 想补强，有四条能立刻做

**① 把文体计量学当客观评估器。** 这是我最推荐的：把蒸馏产物生成的文本和真人原文混在一起，用 Burrows's Delta 或功能词邻接网络做作者归属判定。**归因准确率是个完全可量化、且不需要 LLM 评委的因变量**——它能把"像不像"从主观打分变成可测量的数。

**② 最小可行 ablation。** 同一个问题，跑三组：有产物 / 无产物 / 打乱的伪产物。让熟悉此人的人盲选哪条更像、更有洞察。成本很低，但第一次能回答"蒸馏到底加了没有"。

**③ 跨模型裁判 + 位置对调。** 至少治掉 self-preference 和 position bias 这两大偏差。

**④ 同一素材蒸 5 次，报 run-to-run 一致性。** 没有方差的效果报告不叫效果报告。

顺带一提两个产品层面的坑，用之前要有预期：仓颉默认你读过原书（没读过的人连术语都不知道，问不对问题），且蒸馏产物停在你蒸馏那一天，用大白话提问经常识别不出来。

一句话收尾：**它是目前最好的"把蒸馏变成流水线"的工程实践，但不是"证明蒸馏有效"的证据。** 用它，值得；信它的验证环节，不值得。

这两个技能合并成一个统一的蒸馏技能合适吗？

不合适——至少不该合并成一个 SKILL。但底下有一层**非常该合并**，只是合的不是技能本身。

## 先看为什么"看起来该合"

共同底盘确实很厚：都是上下文蒸馏、都不碰权重、产物都是 `SKILL.md`、都要写边界、都做淘汰留档、都有压力测试。从用户视角看也都是"丢个名字/丢本书进去，出来个能调用的东西"。

所以直觉上合并是对的。但这个直觉错在把"共享底盘"当成了"共享技能"。

## 四个真实的冲突点

**1. 抽取单元根本不是一类东西**
女娲抽的是**心智模型、决策启发式、价值观张力**——对象是"一个会思考的主体"，产物是常驻人格（你一直穿着它看问题）。
仓颉抽的是**方法论单元、可执行步骤、判停条件**——对象是"一段可执行程序"，产物是按需路由（命中才读那张卡）。
前者是 persona，后者是 procedure。强行塞进同一个 schema，两边都会变形。

**2. 失败模式互斥，无法用同一套护栏**
女娲的素材是**开放网络采集，无边界**——主要风险是幻觉填充和"公关形象蒸馏"（你拿到的是此人对外表演的那层）。
仓颉的素材是**封闭给定文本，有边界**——主要风险是触发不准和术语壁垒（没读过原书的人连问题都问不对）。
一个要防"编"，一个要防"调不出来"。护栏完全反向。

**3. 验证判据的尺度不同**
女娲的"跨域复现"是**≥2 个领域**反复出现，判定是否有排他性。
仓颉的"跨域佐证"是**≥2 个独立段落**能佐证，判定是否有原文支撑。
一个是跨领域，一个是跨段落——合并后这个字段该填什么？

**4. 追溯链会断，这是最要命的**
女娲的"诚实边界"依赖对人物认知的谦逊（区分哪些是本人说过、哪些是我的推断）。
仓颉的"B 段边界"依赖对原文的可追溯性（标章节、标证据句）。
两者蒸进同一个产物后，一句话到底是他本人说的、是书上写的、还是模型推断的？**追溯链断了，边界声明就不可信了**——而边界声明恰恰是这两个工具最值钱的部分。

## 一个现成的反证

仓颉自己踩过这个坑。作者原话："把每个通过验证的知识点都做成独立 Skill，就是在制造安装负担和触发竞争。"他数过自己的库：322 个技能，光名字+描述就 5.8 万字符，每轮对话固定 2 万 token 开销。所以 v2.5 才从 19 个平铺技能收敛成 1 个路由入口，目录载荷从 3,897 tokens 降到 340。

**这是同一技能内部过度膨胀的教训。合并两个不同对象类型，只会把触发竞争和目录载荷问题放大。** 而且会立刻撞上一个真实歧义：用户说"蒸馏芒格"，是蒸他的思维，还是蒸《穷查理宝典》？这两件事产出完全不同，合并后你就得先做一次路由判断——而路由判断本身又是一个新的失败点。

顺带说，生态其实已经划清边界了：仓颉明确写"不做扮演作者，那个方向有 nuwa-skill"。这是用排除法做的功能切分，不是没想到的疏漏。

## 正确的架构是三层，不是合并

```
共享内核（该合的部分）
  语料预处理 / 编码统一 / 切片
  Pipeline 状态机 + 断点恢复
  Rubric 引擎 + 压力测试生成器 + 诱饵用例
  rejected 留档 + coverage-audit
  快照 / 回滚 / 增量更新
      ↓            ↓
人物前端          书籍前端
六路采集          Adler + 五路提取
心智模型 schema   RIA++ 能力卡 schema
三重验证(排他性)  三重验证(佐证性)
常驻人格          按需路由
      ↓            ↓
    统一的 Capability Bundle（卡级互通）
```

关键在最后一层：**让人格卡和方法卡共存于同一个 Bundle，但编译产物分开。** 这正是仓颉 v2.5 已经采用的"能力与产物解耦"——Bundle 是单一事实源，交付时再决定编译成 single 还是 pack。把它往上抬一层就行。

生态其实已经在这么走了：评测用例格式互通、产物可直接接入 darwin 进化。**统一的是接口，不是技能。**

## 真正的红利在"组合"，不在"合并"

女娲蒸的人 + 仓颉蒸的书，组合起来才是完整的：装上芒格的认知操作系统，再注入《穷查理宝典》的 12 个思维模型卡，交给 darwin 持续更新适用边界——这才是"数字先贤"那条路。

**这个 1+1>2 的能力，恰恰要求两者独立存在且 schema 互通。合并成一个，反而把组合的可能性关掉了。**

## 什么时候可以合

只有一种情况：**你的对象本身就是混合的**——比如蒸馏一个团队/组织的决策方式，素材同时包含"关键人物怎么说"和"内部 SOP 怎么写"。这时候确实需要单一入口，但内部仍然要跑两条抽取管线，只是产物合流。

除此之外，建议保持分离，把力气花在共享内核和 Bundle 互通上。

一句收尾：**合引擎，不合产物；合接口，不合 schema。** 这也顺带回应了上一轮的判断——既然验证环节本来就弱，就更不该再叠一层路由歧义上去。
