### 1.3 判定：正交，但不是"干净"的正交（两个必须说清的瑕疵）

**判定：与文章1 正交（不同维度），可做二维矩阵。** 检验方式：随机取一条本包条款，问"它在文章1 的哪一层"与"它在皮总六层里是什么角色"，两个答案**可以任意组合**（例：一条审计判据既可以是 Skill 承载，也可以是 Hook 承载）——可独立取值即为正交。

但有**两处不干净**，必须写出来，否则矩阵会骗人：

**瑕疵一：皮总六层内部不同质。** 拆开看：
- 设计／执行／验收＝**生命周期阶段**（有先后）；
- 审计＝**动作角色**（谁判，与阶段正交——执行中也能审计）；
- 讨论＝**交互形态**（未定态）；
- 元机制＝**层级跃迁**（关于规则的规则）。
⇒ 直接后果：**"验收"这个动作同时满足"审计"的定义**，同一份材料会被记两行。**矩阵的行不是分区，是两个格记一件事。** 这不是命名吹毛求疵，它会让 §1.5 的空格分析失真（某格"空"可能只是被相邻行吸走了）。
**本席建议（不越权裁决）**：把"审计／验收"定义成**判定的两个时点**（过程判定／交付判定），或把六行改述为"元机制／设计／执行／判定（过程）／判定（交付）／讨论"——但这属于 Q2 本体论，须皮总拍。

**瑕疵二：文章1 的 L1／L2 之差不是载体差，是强制力差。** AGENTS.md 与 hooks 的差别不在"放哪"，在"读了会不会照做"。所以文章1 其实是**载体 × 强度**的二维表被压成了"六层"。若只取载体做列，会丢掉它最有价值的那条主线（约定与执法分离）。

### 1.5 空格分析（本任务最重要的一节）

先把"空格"分类，否则会得出"哪里空就补哪里"的错误结论。**四类判定规则（可执行）**：

| 空格类型 | 判据 | 处置 |
|---|---|---|
| **缺口型** | 文章1 在该格有对应机制，且该机制**可迁移**（§1.6） | 判"缺口"，进 Q4 排期 |
| **正确型** | 该格与更上位约束**冲突**（如与"文件即真源／可对账"冲突） | 判"不该有"，并在 Q 里写明**不补的理由** |
| **结构型** | 因本包**缺某类载体**导致整列空 | 判"载体缺位"，须决策者定"补载体 or 降条款强度" |
| **吸收型** | 内容存在，但被邻列承载 | 判"不空"，记账归邻列 |

逐格结论：

**（1）L2（Hooks）整列空 → 缺口型（最硬，且已有实测）**
文章1 的 L2 有四个机制（数据红线拦截／开工契约门／交付报告门／纪律卡片注入），本包一个都没有执行体。**这不是"选择了不做"，是"写了'可机检'却没有机检"**（v2 §A3 L1）。⇒ 缺口型，且与 Q4 合并处理。
**但要注意文章1 自己承认的边界**（原文 §3.3）："fail-open：hook 自身解析失败时一律放行""Bash 是绊线，不是城墙……脚本内部的间接写拦不住"。**别把 hook 当城墙**——这一点对我们尤其重要，因为我们的核心风险是"多席并行写"，而 hook 只能拦工具调用，拦不住"某个席位把内容抄进自己的交接件"。

**（2）L6（Memory）整列空 → 正确型**
本包没有跨会话记忆机制，且**不该有**：记忆是隐式的、不可对账的；本包的对账基础是"文件即真源＋append-only＋路径前缀可判"。引入记忆层会造出**第二真源**（v2 §3.2.5 的三分法已经把"载体归属"定死）。⇒ 判"不该有"，理由写进 Q2 答复里，避免下一轮又有人提"要不要加记忆层"。
**唯一例外**：文章1 的"反馈教训→红线规则"闭环（§6.2）值得保留其**形态**（事故→规则→宪法），但落地介质应是 `.collab/decisions/`（已有），不是 Memory。

**（3）L1（常驻注入）整列空 → 结构型（最该警觉的一条）**
本包没有"每次会话自动注入"的载体。后果很具体：`生产方不兼判定方` 与 `收口自检五项` **同处按需加载**——**不加载就不知道**。文章1 把"数据红线"放进 L1 的理由正是"每一条都短到模型不可能'没看到'"。
⇒ 结构型：本包缺"常驻"这个载体。三条出路（都须拍，本席不选）：
 a. 抄进每个 SKILL.md 开头 → **多副本**，与单真源冲突（不推荐）；
 b. 把 3 条红线压进 SKILL.md 的 `description`／`when_to_use`（会被 1,536 字符截断，见 v2 §A1）；
 c. 承认"本包无 L1"，把红线强度**降级声明**为"按需加载"，并在每个交接件头部要求复述一次（成本是每件多几行）。

**（4）验收行在 L2 空 → 缺口型**

## 二、任务 B：席位溯源怎么做

### 2.0 先把问题问对：这是归因问题，不是计数问题

皮总的原话是"出问题如果经常出在某个席位上，是否就说明需要专门针对某个席位做优化"。这句话里藏着一个默认前提：**问题能被归到席位**。但这个前提在文献里恰恰是最弱的一环（§2.1：agent 级自动归因最好只有 53.5%）。所以本节的顺序是：**先证"能不能归到席位"，再谈"要不要优化席位"**。反过来做（先统计谁错得多、再优化），就是用度量代替因果。

### 2.1 文献核实（四篇，全部 arXiv API 直取摘要）

| 编号 | 标题／ID | 与本任务相关的硬结论 |
|---|---|---|
| P1 | *Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems*，arXiv:**2505.00212**v3（2025-04-30） | 提出 **Who&When** 数据集（**127 个** MAS 的失败日志，标注到"具体 agent + decisive error steps"）；评了三种自动归因方法，**最优 agent 定位 53.5%、步骤定位 14.2%，部分方法低于随机**；"Even SOTA reasoning models, such as OpenAI o1 and DeepSeek R1, fail to achieve practical usability" |
| P2 | *Why Do Multi-Agent LLM Systems Fail?*，arXiv:**2503.13657**v3（2025-03-17） | MAST：**1600+ 条**标注轨迹、**7 个**框架；归纳 **14 种失败模式 / 3 大类**：**(i) system design issues、(ii) inter-agent misalignment、(iii) task verification**；专家标注一致性 **kappa=0.88** |
| P3 | *TRAIL: Trace Reasoning and Agentic Issue Localization*，arXiv:**2505.08638**v3（2025-05-13） | 轨迹错误定位的形式化分类＋**148 条**人工标注轨迹；"the best Gemini-2.5-pro model scoring a mere **11%** on TRAIL" |
| P4 | *Agent-as-a-Judge: Evaluate Agents with Agents*，arXiv:**2410.10934**v2（2024-10-14） | 用 agent 评 agent，可给中间过程反馈（DevAI 测试床）。**注意**：它是"判定器"，不是"归因器"——用它做席位归因会直接踩 §2.2·陷阱三 的自证循环 |

**三条直接可用的推论**：
1. **自动归因只能当线索**（P1 的 53.5%、P3 的 11%）。任何"模型说是 X 席位的错"都必须有人工复核，否则等于抛硬币还带解释。
2. **失败的大头不在单个 agent 身上**（P2 的三大类里，只有"task verification"的一部分与"席位执行"有关；"system design""inter-agent misalignment"都不是某个席位的问题）。⇒ 皮总"经常出在某席位"的观察，**先要排除"其实是交接/判据/设计问题"**。
3. **判据本身可能是病灶**（P2 的第三类就叫"task verification"）。这与本包"判据设计者"这个角色直接对应——**判据写错时，所有席位都会"犯错"**。

> 未采信为证据的：检索命中的多篇第三方解读（如 potatoannotator、fahimfaisal、menuagentic 的指南）。它们概念清楚、可作背景，但均为 C 级二手材料，本报告只在"操作建议"层面参考其思路，不引为 L1（见 §五 引用清单 C 级部分）。

### 2.2 三个陷阱与排除顺序（本任务的核心）

#### 陷阱一：归因混淆——"出问题"≠"席位有问题"

**先给排除顺序（顺序本身就是判据，不可跳步）**。每一档都对应一个"可查的物"，不是靠讨论：

| 序 | 排除项 | 查什么（可执行的物） | 若命中，结论 |
|---|---|---|---|
| **E0** | **判据本身错** | 判据版本号是否与裁决一致；判据是否自相矛盾（同一条要求两个互斥动作）；判据是否不可达（要求了工具/权限做不到的事）；**判据设计者是否同时是被审方** | 改判据，**不计席位错误** |
| **E1** | **输入缺失** | 交接件是否满足 H2 三项（动作／完成判据／输入路径清单 `R:可读`）；是否有 `R:不可读` 未处理 | 补交接件，**不计席位错误** |
| **E2** | **权限／能力不匹配** | 该席位的读域／写域是否覆盖任务所需；所需工具是否在该席位工具集内 | 改权限或换席，**不计"能力差"**（是设计问题） |
| **E3** | **隔离失效（自证）** | 生产方是否兼了判定方；判定方是否用了自己写的判据；判定方是否看过过程材料 | 作废该次判定，**不予采信** |
| **E4** | **席位执行偏差** | 同输入、同判据、同模型，**重复仍错**，且错误模式可命名 | **才进入席位归因**（见 §2.4 判据） |

**为什么是这个顺序**：E0/E1/E2 命中时，"席位犯错"这个说法**没有意义**——任何席位在错判据／缺输入／无权限下都会失败，此时统计到的错误率测的是**系统**，不是席位。E3 命中时，判定本身无效，连统计都不该做。文献侧的支持：P2 的三大类里前两类（system design / inter-agent misalignment）根本不在席位层；P1 的归因单元是 (agent, **decisive step**)，而"决定性步骤"常常是上游的一次信息丢失，不是下游的可见症状——**要归因到"第一个不可恢复的错误"，不是"最后一个看得见的错"**（此判据在 C 级指南中被反复强调，本席采纳为操作纪律，标 L2）。

#### 陷阱二：小样本误判——"错 3 次"什么也证明不了

**反直觉但可算的例子**：某席位连续 3 次全错（3/3）。直觉是"错误率 ≥80%"，但二项比例的 **Wilson 95% 下界只有 43.8%**（3/3 的 n=3）。⇒ **3 次全错只能支持"真实错误率高于约 44%"，不能支持"这个席位不行"**。

**门槛（本席设计·L2）**：同时满足三条才可谈"高于基线"
1. **同条件重复** n ≥ **8**（同一交接件、同一判据、同一模型、同一任务难度档）；
2. **同一类错误** ≥ 3 次（不是"错了 3 次"，是"同一模式错 3 次"——不同模式的错说明是系统问题，不是席位问题）；
3. 该席位错误率的 **Wilson 95% 下界 > 基线**（基线取"该席位历史错误率"或"全席平均"，**必须在看数据前写定**，不许事后挑）。

按此规则算出的**最少错误次数表**（本席实算，见下）：

| 基线 p₀ | n=5 | n=8 | n=10 | n=15 | n=20 | n=30 |
|---|---|---|---|---|---|---|
| **20%** | 3 | **4** | 5 | 7 | 8 | 11 |
| **10%** | 2 | **3** | 3 | 4 | 5 | 7 |

（读法：基线 20%、跑 8 次，要**至少 4 次同模式错误**才能说"高于基线"；只错 3 次不够。）

> 计算口径：Wilson score interval，z=1.96，单侧判据取**下界 > p₀**。算法可复现（`p̂=x/n`；`下界 = (p̂ + z²/2n − z√(p̂(1−p̂)/n + z²/4n²)) / (1 + z²/n)`）。**这是本席自建门槛，不是业界标准**——查不到"席位样本量"的专门标准（见 §四 查不到清单第 2 条）。

#### 陷阱三：自证循环——别用同一个席位判自己

本包已禁"生产方不兼判定方"（`SKILL.md:51`）。溯源机制**不能自己破这条**，所以：

| 环节 | 谁做 | 禁止 |
|---|---|---|
| 填记录（§2.3 的 11 个字段） | **执行席**（生产方） | 不得填"归因结论"列 |
| 排除 E0–E3 | **审计席** | 不得修改判据版本（L0 不下放，`SKILL.md:55`） |
| 判 E4 是否成立 | **审计席** | 不得是被审席位的同一人/同一会话 |
| 复现实验（重跑） | **审计席执行或复核** | 执行席自行重跑后宣布"不是我的问题"＝无效 |
| 基线值 p₀ | **在看数据前**由元机制层写定 | 事后调整基线＝把判据改成结论 |

**特别提醒（针对 P4 Agent-as-a-Judge）**：用 agent 当判定器本身不违反隔离，**但用"和被测席位同一个 agent/同一条提示"去判自己，就是自证**。若要用 agent 判定，必须满足：判定 agent 的输入里**不含**被测席位的自我陈述，且它的判据来自元机制层。

### 2.4 判据：什么时候可以说"这个席位要专门优化"

四条，前两条是**结论**，后两条是**约束**，都可二值判定：

> **J1（可说"该席位需专门优化"）** ⟺ 同时满足：
> ① `exclusion=E4`（E0–E3 全部排除，有据）；
> ② `repro` 满足 **k≥8 且 m≥3**，且同模式；
> ③ 该席位错误率 **Wilson 95% 下界 > 事前写定的基线 p₀**；
> ④ 错误模式**可命名**（能写出"总在同一类判断上错"，不是"什么都错"）。

> **J2（只能说"这个任务这个席位做不了"）** ⟺ 满足任一：
> ① 错误集中在"该席位**无权**做的动作"（E2 的变体）；
> ② 错误集中在"该席位**工具集不支持**的验证方式"（如要求看截图但席位无视觉）；
> ③ 任务档位为 L（长尾/一次性），`k<8` 无法采样，但**错误模式稳定复现于同类任务**。

> **J3（反甩锅·必须做，否则 J1 不成立）**：在给出 J1 之前，必须做一次**廉价反事实检查**——**只补上下文**（E1）或**只改判据**（E0）后，由审计席用**同一席位**重跑一次。若问题消失 ⇒ **不许归因席位**，改归"判据/交接件"。
> 依据：文献把"归因"本质上看作反事实（"若它不这样，结果会更好"），但真反事实在真实任务上跑不起（P1 的步骤定位只有 14.2%）；**所以只做最便宜的那一维反事实**，能翻案就翻案。

> **J4（默认态）**：不满足 J1 也不满足 J2 ⇒ 记 **"未定"**，**不进优化排期**。允许累积证据后再判，但**不许用"未定"当"没问题"**。

**这套判据的用处**：它会**大量产出"未定"和"不是席位问题"**。这不是保守，是让"席位优化"这个动作有门槛——否则每个出问题的任务都会变成"给某个席位加一段提示词"，而 P2 告诉我们多数失败根本不在 agent 身上。

### 2.5 限界（这套机制判不了什么）

1. **一次性长任务无法采样**：k≥8 的前提是可重复；真实项目里很多任务是独一份的 ⇒ 只能到 J2 的描述层，不能到 J1 的统计层。
2. **多席共模时，"席位差异"与"提示词差异"不可分离**：同一模型下，两个席位表现不同只能说明"设定不同"，**不能说明"这个席位不适合这个模型"**。要让后者可判，必须先有跨模型对照（对应 P3 的"换一双眼睛"思路，但成本高）。
3. **人工标注一致性未测**：本机制依赖审计席填 8–11 列，若两人标注分歧大，结论不可比。**建议：抽 20% 样本双人标注，算一致性；低于阈值（如 kappa<0.6）则先修字段定义，不修席位**（借 P2 的做法：它先花力气把标注一致性做到 kappa=0.88 才敢用数据）。
4. **判不了"该不该有这个席位"**：本机制只判"该席位在这个任务上表现如何"，不判"这个席位是否该存在"——后者是设计层（元机制），须拍。
