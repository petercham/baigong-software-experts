# 2026-11-18 提交权归一裁决登记 v1

## 〇、裁决原文（皮总 2026-11-18 20:00 口径·逐字）

「在 WorkBuddy 这个架构下，每个席位根本不应该自己 commit 才对吧？！只有主理人单一席位在每个流程节点结束后统一 commit 才是最合理的吧」

## 一、裁决采纳登记（主理人誊录·效力即时生效）

- 口径＝**提交权归一**：各席（工程师／QA／产品／架构）＝内容生产者＋取证生产者——写正文件落盘＋message 载体（含全部 V 系自证读数）落 .scratch＋回报交付物路径/blob/读数，**全程零 git 写操作（不 add 不 commit 不 amend）**；主理人＝唯一链面操作员，按席回报 pathspec＋message 载体机械执行 add 单 pathspec 紧邻 commit＋FX_COMMIT_DECLARE＋-F 承载＋输出重定向＋有证转后台，逐字誊录零改写。
- 作者归属不丢＝commit message 内嵌席位署名与尾标照旧；主理人不产内容本体（零业务写红线不破·誊录权＝表2-1 host 行明文）。
- 席侧只读 git 命令（rev-parse／show／status／diff）不禁——开工对钉与忠实性复测所需。

## 二、依据实证（2026-11-18 当日案型账）

- staged 悬挂五枚（席暂存未投即终结）；残骸锁损耗约 1.2 小时（席前台 commit 被超时 SIGTERM 砍死留 index.lock／next-index-PID.lock 残骸）；T1d 工程师席会话超时折损两枚（提交窗占临时席生命周期大头）；「回报自述与实态不符」案（席对 git 状态自述不可靠）。
- 机理定性＝WorkBuddy 架构下席位＝按需 spawn 临时进程，与单笔 8～10 分钟闸临界区结构性错配；同 worktree 全局 index 锁本已强制提交段串行，席各自 commit 零吞吐收益只有排队损耗——串行既不可避免，排队权归唯一常驻席为最优。
