# 通用开发纪律（写权闭集·代码纯度·回执清单·QA 纯净）

> 出处：本地约定（跨项目·全专家/技能开发通用·四件一体成文）。席位级权限声明真源在各席位 MD
> 「写权边界」节（互指不复写）；机检判据真源见审计器文档域 D6-3 与干净度测 T6（只指不搬）。

## 一 写权闭集

1. 交付物域（`.collab/` 以外一切交付面：deliverables/、bundle 装配体、专家包、技能包、组件包）
   **只有工程师（程序员）席有写权限**。
2. 其他席位（主理人/产品/架构/QA）的一切产出＝过程件，只落 `.collab/` 过程域
   （设计稿、分析、判词、回执、票面）。
3. 派工合规硬门：主理人拟票/派工时，凡含代码性质或交付面写入的任务**只派工程师席**；
   派错＝席位按「拒写权」条款拒绝并回报改派（席位 MD 自带该声明·第二道闸）。
4. 席位拒写权：非工程席受命向交付面写入时，有权且应当**拒绝写入＋报主理人改派工程师席**；
   拒绝不构成违例，执行才构成违例。
5. 调研是各席通用技能，不是席位：对决策者疑问的调研取证按问题适配席位派执行，不新设「研究席」编制。

## 二 代码纯度

1. 工程师写入交付面的内容不得携带过程件的**指针与内容**：出包路径（仓案面、`.collab`、
   盘符路径、家目录路径）不入交付件——判据＝从交付包根解析不可达的指针即违例
   （包内相对互引必须放行）；盘符、家目录、协作目录形态正则仅作加严兜底扫描。
2. 不可解析编号不入交付件。「不可解析」＝功能性定义：消费方无解析入口且交付件内
   无定义表（件内有定义表即放行；形态列举仅兜底不作定义）。
3. 开发叙事（为什么改、怎么改）不入交付件；例外＝已在交付清单中声明为交付组件的
   过程性文档（如沿革记录）——类型不枚举，以声明为准。
4. 交付面写入实行**声明闭集制**：每张施工票声明的文件闭集＝允许写入集；收口对账
   三段全链，**对账基面分段**——commit↔回执段基面＝git name-only；回执↔交付面、
   回执↔票面声明两段基面＝交付面文件系统 listing（与纯净扫描同面，生成件与
   未提交文件不逃逸）；越集即违例。闭集修订程序＝票面补声明（amendment 行）＋
   回执注明理由；禁止仅回执侧单方面扩集。
5. 交付包内一切指针只准**包内闭环**：非 sources 文件的指针只准指向包内非 sources
   文件；`sources/` 子包＝唯一允许进交付物的自包含料源，其内部指针同样不得出包。
6. `sources/` 内容闭集＝只含干净的蒸馏/沉淀记录；纠错件、案卷、票面、复盘、拍板
   指针等开发迭代过程物一律不得混入。
7. 判据细则与豁免口径以审计器侧 D6-3/D6-4/D6-5/T6 为真源，本节只载纪律不复写机检参数。

## 三 工程师完工回执

1. 工程师每张交付面执行票的完工回执**必须完整包含本次写入/修改的文件清单**
   （路径逐项列出，含新建/修改/删除标记）。
2. 对账口径＝`git show --name-only <commit>` 与回执清单**全等**；缺项/多项＝违例（回执失真）。
> **过渡口径（v2.9 §20.1·⑥）**：人工回执全等对账→B2/B5 账本（回执保留为申报载体）（旧条款保留为技法面，验收结论一律以 SWB v2.9 基线为准）
3. 回执落 `.collab/` 过程域；commit message 不替代回执。正文对 scratch 取证族的引用形态受 §八 第 5 项约束。

## 四 QA 纯净职责

1. QA 对回执清单**逐件**检查是否混入过程件或过程件指针（判据＝审计器 T6/D6-3 口径＋人工抽验）。
2. 交付面纯净性责任在 QA：漏检＝QA 未绿项，不回落工程师自证（生产方不兼判定方）。
3. QA 的判词落过程域；判词点名违例文件路径与命中模式，供返工票直接引用。

## 五 与既有段的关系

- 本卷与 `collab-rules.md`（fork 下沉件）并列不复写：那边＝顺序流转/信息传递/反馈回路，
  这边＝写权/纯度/回执/判定四闸。
- 与 `deploy-gate.md` 互指：装配/注册/覆盖缓存类部署动作义务在彼；本卷管写入内容本身。
- 本卷与 `handoff-discipline.md` 互指：那边＝交接/收口/报告/隔离律真源，这边＝写权/纯度/回执/判定四闸真源。
- §六 票面起草职权与派工件干净度（handoff-discipline §八）同根：那边＝指令干净度，这边＝条款起草权分席。
- §七 检出条款↔消费面对账与机制断言须附实测（handoff-discipline §九）互指：那边管引用方举证，这边管起草方挂落点。

## 六 票面起草职权（交接件起草权分席）

1. 开发执行票面（三块＝改动面声明闭集＋施工规格＋验收判据）＝交接件，起草权归
   该域专职分票席位（软开团＝架构席本职）；票面条款文本真源在分票席位，工程师照票面执行。
2. 路由席位（主理人）的派工文书＝只含路由要素：派工指令、席位选定、台账与看板登记、
   收口向上汇总；路由指令内不得内嵌施工条款或验收判据（下行只减不加的票面侧体现）。
3. 路由席位代写开发执行票面＝越权违例：纪律账登记＋分票席位补出正式票面重派；
   已经 QA 链核验的既往票面登记不回退不返工。
4. 同条一般化：任何专业域的执行计划/交接件由该域专职席位起草，路由席位只递送与派工。

## 七 检出条款↔消费面对账（起草侧义务）

1. 凡向设计/票面/交付条款写入「检出」「验收」「核对」类动作（含表列），同一文档必须指向
   其消费面：检器＋落点，或显式标「人工闸核对」＋执行席位＋步骤位。
2. 未指向消费面的检出条款＝未生效条款（写成≠生效）。
3. 验收段执行一次「写出的动作↔消费面落点」存在性对账（人工位），缺对账＝未绿项，
   不回落生产方自证。
4. 当期无机检义务。

## 八 临时工作物落位与清理纪律

1. 适用范围＝一切临时工作物：QA 复测区／工程师施工试跑暂存／架构取证探针／演练预演区／装配对拍区，不分工序席位。
2. 唯一落点＝所属项目仓根（项目根＝含 docs/STRUCTURE.md 之探针锚目录）`.scratch/<票号>/`：跨仓对拍需多仓并排的，各落各自仓 `.scratch/` 内；禁盘根裸路径（磁盘根直接建目录）、禁系统 Temp 目录（宿主临时环境变量展开所得目录，含 Windows `AppData\Local\Temp` 与 Git Bash `/tmp`）、禁仓外任何自建点。
3. 收口登记票必含清理判据：本票声明闭集外的临时区批毕删除＋附删除读数；确需留存者归档至项目指定归档仓＋附留存归档读数。收口态＝零残留——工作仓 `git status` 净＋本票 `.scratch/<票号>/` 已清或已登记留存去向。消费面＝收口票判定段：主理人汇编收口票时列入该项，QA 席收口判定核对删除/留存读数（人工闸）。
4. 派工书／票面禁写仓外临时路径模板（旧措辞〔禁例引〕「置系统 Temp」「置仓外 Temp」作废）；席位受命含此类路径时有权指出违例并请改派落位。
5. scratch 取证族可达路径不入留存工件：回执、判词、收口登记、commit message 等一切在 scratch 取证族完工自删后仍留存的工件，正文对任何席位的 scratch 取证族（各项目 `.scratch/<票号>/` 族及其内工件）仅准叙述性提及＝族名或工件基名裸文写、不以反引号路径形态落指针；判据＝指针机检可解析的指向 scratch 取证族之路径 token 零出现。取证需长存者，先升格为登记常驻件（归档面或票附件案面）再让指针只指常驻位。根因＝本节第 3 项完工自删与正文引用留痕全径的时序互搏：落笔当时在场故当时绿，自删后卫检必悬空（SWB-SCRATCHCFG 案 QA 判词黄-1 同构）。

## 九 项目根四区写权限总表（{root}/{project_id}/ 结构）

1. 宿主项目根 {root} 下每个项目工作空间 {root}/{project_id}/ 按四区分权：
   `sources/`＝仅人类（用户）可写，全席位＋主理人只读；`docs/`＝按文档归属席位
   （结构/架构/ADR＝架构席，产品说明书＝产品席，其余逐件由主理人指定）；
   `.collab/`、`.archive/`＝席位租约面／主理人落位；其余全部＝代码交付面，
   工程师按票租约（可另行指定）。
2. `sources/`＝人类唯一写权限目录：语义＝原始用户提交输入资料源＝唯一事实源
   （intake 语义）；任何解析件、digest、转正件不得写入此目录。机械席位写
   `sources/**`＝越界（deny_globs 五席覆盖＋租约签发面写域子集校验双拦）。
   本节 `sources/`＝宿主项目根四区之 sources 区，与本卷 §二.5/§二.6 交付包内
   `sources/` 子包（自包含料源）为两域，读侧勿混。
3. 双根模型（皮总裁定 2026-11-06·deliverables/ 双根）：开发面＝`{dev_root}/{project_id}`
   （本节四区之根，`{root}` 读作 `{dev_root}`）；交付面＝`{del_root}/deliverables/{project_id}`
   ＝装配-清理编译后干净可交付件存放路径，另归独立 git 集中管理，不入四区建档与写保护面。
   本包及基线副本文档内 `deliverables/` 字样一律读作交付面概念引用，非包内路径。
4. 历史引文不回改：旧文书中 `Sources\...` 旧径引用＝历史引文（append-only）；
   今后新文书一律 `sources/` 新路径。
5. 出处＝宿主裁定登记件（2026-11-06·「皮总拍板-sources四区写权限与
   deliverables语义校正」）；本卷载纪律条款不复写裁定本体。

## 十 项目进场建档工序（锚定→四区→STRUCTURE 产物→结构说明誊录）

1. 本卷 §九 四区与 `docs/STRUCTURE.md` 等规范＝专家团自身治理规范，**永不对人类用户构成约束**，
   只能配合用户：一切机制不得以「用户预置合规件」为前提。本节「项目根」＝开发面根
   `{dev_root}/{project_id}`（双根裁定 2026-11-06），交付面另根不入本节。
2. 新部署/空白项目进场序（S1–S6，仅一次；已有锚定＋四区者跳 S1–S3）：
   S1 锚定＝用户指定开发面根由主理人记明后，主理人经非 hooks 拦截写径落
   `<开发面根>/.workbuddy/swb-anchor`（首行 `project_root: .`·自指闭合）；
   环境变量 `SWB_REPO_ROOT` 在场＝同效且优先；
   S1b 平台域运行时确认（判定序见 TK-PROJINIT 票面 rev5 段·注册两件套／不注册如实登记）＝探针实测平台当时指定的 memory 路径落位（禁预设现值），落位在开发面根内→当场注册两件套（config 写权表平台域键·按当时实测路径生成 glob 字面·两 config 同批＋STRUCTURE 面登记该域注＝平台域·写权由平台定义下放），不在项目根内→不注册、如实登记读数；
   S2 四区建档＝按 §九 建 `sources/ docs/ .collab/ .archive/` 骨架（交付面不预建）；
   S3 账本骨架＝`<开发面根>/.collab/ledger/`；
   S4 结构说明收集＝用户任意自由形式件（`*.md`/`*.txt`）或聊天附件/口述＝原件经人类通道
   入 `sources/`（用户本人落笔或人类代行注 source_role；机械席只引导只读）；
   S5 誊录＋规范校验＝架构席按 STRUCTURE 规范六目成稿（四区枚举完备／delivery_paths 块／
   `project_root: "."` 行／未声明目录询问不判违规／声明未建补建／原件格式不作要求）；
   S6 迁移落笔＝校验通过稿落 `<开发面根>/docs/STRUCTURE.md`。
3. 校验不通过＝反馈引导用户澄清；**不代改原件、不要求用户按规范重写**。
4. `docs/STRUCTURE.md`＝建档步 S6 产物，非用户预置前提；探针以
   `.workbuddy/swb-anchor`（权威锚）→STRUCTURE.md（事后校验）→fail-safe 包根（deny）序解析，
   四脚本（write-guard/lease-issuer/commit-audit/memory-neutralize）逐字同款。
5. 交付面 `{del_root}/deliverables/{project_id}`＝开发期不预建不引导，收用户交付指令时
   按用户指定目录构建＋引导（lazy·独立 git 另管，不入本票写保护/租约/账本面）。
6. 出处＝决策者裁定四款＋deliverables 双根裁定两则（2026-11-06）；条款本体见 TK-PROJINIT 票面 §三。
