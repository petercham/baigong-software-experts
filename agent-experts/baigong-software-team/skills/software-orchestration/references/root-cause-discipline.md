## R-1 前置现势面值必现跑

### 条款本体

任何席位在票面、规格、断言中写入「前置现势面值」（某件钉值／行数／桶计数／红绿态现势）时，该面值必附当窗现跑读数＋现跑窗时间差申明；下游席消费该面值时必各自当轮现跑复核为是，禁照上游面值 verbatim 反推。面值与开工现势不符即登记面值失实，不得照面值强行落笔凑绿。

### 适用窗

开票席写前置断言与开工对钉时；施工席开工对钉与落笔前基线时；验收席 V1 槽复跑时；收口与放行登记转引面值时。

### 现象

drill-05 案型在册＝票面 E5「零红态现势」面值与开工现势不符＝照票 verbatim 反而红（存量红两因非本笔所致）；同族＝T2f 票面四处开工钉面值误值（照钉必 mismatch V1 停手＝放行黄-补-1 写死只认 rev 现势）＝面值起草窗真值与开工窗现势错配案型族。

### 机理

WorkBuddy 架构下票据落盘与投递之间存在他案插笔时间窗；上游面值系起草窗真值，下游开工窗现势可能已迁移；照面值 verbatim 反而与实态错配，导致「照票反而红／照票反而错」＝面值即漂移面，唯有现跑可锚现势（案型＝引用即漂移的前置断言面）。

### 适配动作

1. 前置断言书写形制＝面值＋现跑命令（缩进段）＋读数＋时点注（起草窗真值／收尾窗现值随带禁判漂移）。
2. 下游消费口径＝开工对钉必当轮现跑为是；对拍失配即机械现读为是、非红停手项（面值系上游起草窗真值不构成下游违例）。
3. 失实处置＝登记面值失实（随正条款或候补池），史件票面 append-only 不回改；面值真身归位另路（如面值串件案归候补池）。

    # 对拍失配裁决＝以命令输出为是，票面面值作起草窗真值照登（非红）

## R-2 面值算术自矛盾两账互算前置判

### 条款本体

面值入面前先互算＝凡落笔预期面值含「numstat 增删对」与「行数迁移」两账时，两值必彼此自洽（如单行插入＝numstat 1／0 对行数 n→n＋1 两账同向）；互算不过即登记面值失实候裁或勘正，施工席不得照自矛盾面值强行落笔，以实测两账为是。

### 适用窗

施工席按票面 §三 规格落笔前对预期 numstat 与行数面值互算时；开票席填 V2／V3 槽面值时；验收席面单核验（V3）两账比对时；配对段／计数类「落盘前应仍 X｜Y｜Z」预期面值互算时。

### 现象

面值算术自矛盾案族四度复现在册＝T2b 收口行 71 三度复现句（预期「1／0 与 37→38」两值算术皆不可能）＋T2c 收口行 74 落点锚行失实放行勘正＋T2h 收口行 135 四度复现句（「落盘后应仍 7｜7｜0」对含本件计数必错侧）；未复现正面态亦在册＝T2h 收口行 73（两账同向自洽＝正负两态俱在册）。

### 机理

面值算术自矛盾＝面值两账（numstat 轴 vs wc 行数轴／预期计数 vs 含本件计数）在算术上不可能同真＝票面起草窗算错；照自矛盾面值 verbatim 落笔必致两账之一必红＝施工席若照红即错判自己；互算前置判在落笔前以算术排除面值错侧（案型四度复现＋未复现正面态俱在册）。

### 适配动作

1. 落笔前互算＝把预期 numstat 与预期行数并排做算术判（增删侧与行数迁移是否同向＋末行无换行符存量面口径差一枚随登不冲突）。
2. 互算不过＝登记面值失实（随正条款规格级写死／候补池条文候选）＋以当轮实测两账为是（机械读数 8｜8｜0 为是形制）。
3. numstat 与 wc 差一枚＝末行无换行符存量面口径（numstat 计数轴含末行＝tail 末字节现跑非 0a 归因随登）＝两账不冲突面。

### 判定命令

    git show --numstat HEAD | tail -3                       # 施工笔面单两账现读（增删列 vs 行数迁移列）
    git show --name-only --format= HEAD | while read f; do wc -l "$f"; done   # 面单各枚行数现算（两账互算另一侧）
    # 自洽判＝numstat「加/删」对（旧行＋加−删）与 wc 现算行数相等＝绿；不等即面值失实登记候裁

### 依据附钉

T2b 收口 行 71＝「③面值算术自矛盾案三度复现＝派工预期面值『1／0 与 37→38』两值算术皆不可能」（21d1fccc／140 行现跑命中）＋行 116 候补池行（两账互算前置判据口径＝面值自矛盾三度复现＝与 T2a 收口「派工面值随红勘重算口径」同池沿册）；T2c 收口 行 74＝「⑤面值算术自矛盾案族沿册＝照票 verbatim 反而错」（c5413568／146 行现跑命中）；T2h 收口 行 135＝「派工预期面『落盘后应仍 7｜7｜0』算术自相矛盾照登＝机检读数 8｜8｜0 为是＝面值算术自矛盾案型四度复现随登」＋行 73＝「④面值算术自矛盾案未复现正面登记＝S2 numstat 1／0 与 37→38 加行形制两账同向自洽」（7f889958／142 行现跑命中）。

## R-3 面值链序必以机械现读为是

### 条款本体

转引链序句（相邻两笔父子顺序／某枚 parent 句）与自身 parent 句或他处读数冲突时，一律以机械现读为是（git rev-parse 逐枚^父笔现读＋merge-base --is-ancestor 判定），禁照转引链序句反推链结构；开工窗报备在册＝面值自矛盾案族的链序子型。

### 适用窗

开工竞态防呆对钉（链顶＋链序逐枚^现读）时；票面或登记文转引链序句消费时；两枚面值相邻顺序出现时；收尾窗链顶复跑时。

### 现象

面值链序误抄案型在册＝放行登记 §〇 面值链序句相邻两枚顺序误抄（0663312f 自身 parent 句对链序句同款自矛盾）＝机械现读优先口径三度复现（与面值自矛盾案族沿册）；开工窗报备面＝开票／施工两窗各自^现读发现。

### 机理

链序＝提交图的对象引用关系，唯一机械可核面＝^父笔现读＋祖先判定；转引链序句＝人对图的手抄，相邻两枚顺序易误抄＝手抄面值与自身 parent 句同款自矛盾时，机械现读是闭合唯一真源；照转引链序句判链＝以漂移面作锚。

### 适配动作

1. 开工链序现跑形制＝逐枚 rev-parse 枚^（父笔四十位现读）相衔自证零断，禁抄上游链序句。
2. 竞态防呆＝链顶非预期但为其祖先＝他案插笔无害竞态照登续行；非祖先＝停手候裁（merge-base --is-ancestor exit 码判）。
3. 链序转引句与现读冲突＝以现读裁决＋开工窗报备随登（面值链序误抄案型随登）。

### 判定命令

    git rev-parse HEAD                                   # 链顶四十位现读
    git rev-parse HEAD^ HEAD^^ HEAD^^^                    # 逐枚^父笔现读（相衔自证零断）
    git merge-base --is-ancestor <预期笔四十位> HEAD; echo exit=$?   # exit 0＝祖先（无害竞态）／exit 1＝非祖先（停手候裁）

### 依据附钉

T2e 收口 行 68＝「①面值链序误抄案型＝放行登记 §〇 面值链序句相邻两枚顺序误抄（0663312f 自身 parent 句对链序句同款自矛盾）＝开工席以机械现读为是＝开票／施工两窗开工窗报备在册」（a2fe44d5／153 行现跑命中）；同族面值链序误抄沿册＝本卷 R-2 案族（机械现读优先口径三度复现）。

## R-4 跨仓跨面归因必 pickaxe 坐实枚位

### 条款本体

跨仓（本链 ‖ 主仓）或跨面的「已施／未含／扩展已在」类归因断言，必附 pickaxe（git log -S／--find-object）坐实枚位（具体笔号＋两侧 blob 态），禁以方向直觉或单侧存在推断归因；归因方向相反案型＝断言方向与坐实笔号相反即登记为案型。

### 适用窗

两仓成对读数出现时（share 闸族／门禁脚本／钩子键面）；桶闸／脚本扩展归因时；「主仓已施‖本链未含」类双侧断言书写时；V 系验收复跑他域笔判据时。

### 现象

归因方向相反新案型在册＝票面「主仓已施‖本链未含」两误＝已施所指系 T1c 配对段非 T2d 计划扩展（方向相反＝以内容方向直觉替代笔号坐实）；反向正面范＝NOT-IN-WT-CHAIN 面 merge-base 具名现跑逐笔归因照登（主仓链面新笔零归我方）。

### 机理

同库两链面共享 gitdir 对象库但各持 HEAD＝blob 可在本链 --verify 解析 ≠ 该笔已入本链（两判据勿混）；「已施」类归因若只凭他域存在或语义方向推断，极易把 T1c 配对段扩展误归 T2d 计划扩展＝方向相反；pickaxe 以内容变更锚定笔号＝唯一坐实枚位面。

### 适配动作

1. 「已施」类断言必附 -S／--find-object 命中的笔号四十位＋两侧 blob 短式成对（本链 e098bd55 面 6 枚在位 ‖ 主仓 922fe2e9 面 0 枚形制）。
2. 归因方向存疑＝pickaxe 现跑坐实配对段扩展笔号（本链 T1c BUILD 笔 2d90ccb5、主仓唯一笔 f530859c 同款实证）后如实登记。
3. 入候补池＝跨仓归因必 pickaxe 坐实枚位＝条文候选（归成文面消费＝本目）。

### 判定命令

    git log --all --oneline -S "MC-PAIR-1" -- agent-experts/baigong-software-team/skills/sop/scripts/check-collab-buckets.py | head -3   # pickaxe 锚定内容变更笔号
    git log --all --oneline --find-object=<blob四十位> | head -2    # 以对象锚笔号（面值真身溯源）
    git rev-parse --verify <主仓blob短式> | cut -c1-12   # 可解析≠在链（两判据分离坐实）

## R-5 转引面值成对讲＋省形引用必现算补钉

### 条款本体

转引面值（他文转抄的钉值／行数／路径／件名）必以「来源面值 ‖ 现势值」成对讲法并列写死·两侧各自现跑；省形引用（省略路径段或件名尾缀）必现算补钉为真位全名＋blob 钉值，禁以省形名或转引名直接消费。引用即漂移已升格规范正文化先例同款路径。

### 适用窗

票面／登记文／判词转引面值消费时；路径省形（tests／probe-results.json 形）出现时；件名转引（混入 vs 卷入一字符差形）出现时；收口 E3 对拍引用名时。

### 现象

引用即漂移实战首咬在册＝T2h 快审窗 fresh 新见他域取证面版本漂（主仓侧 run-gates 实在行 167 非本链行 141）＝候补池条文升格正文化首案；省形案＝tests／probe-results.json 省形真位 tests／probes／results／（违例零发生预防性登记）；转引名漂移本尊复现＝票面素材枚 8 引用名「混入登记」对链上实名「卷入登记」一字符差（具名径 rev-parse exit 128 实证＝恰为本条款消费面对象）。

### 机理

转引＝跨面复制面值＝复制即引入漂移窗口（版本漂／一字符差／路径段省略）；成对讲法把来源面值与现跑现势并列＝差即显形不隐藏；省形名可能脱真位或脱实名（链上实名唯一＝具名径 rev-parse exit 128 复现）；唯一闭合面＝现算补钉回真位全名＋钉值再消费（案型＝转引名漂移本尊复现）。

### 适配动作

1. 成对讲法形制＝来源面值（派工书／登记文转引）‖ 现势值（本窗缩进段命令现跑）并列写死；两侧各自现跑·主仓侧只读经 git -C 现跑·禁凭记忆禁单侧断言。
2. 省形补钉＝真位路径现算（git ls-files／ls-tree 具名＋show 管道 hash-object）补钉全名＋blob 两值对真位全等再引用（违例零发生亦预防性登记）。
3. 引用名漂移＝一律照链上实名附钉（本卷 R-8 素材枚＝卷入登记实名，见 R-8 依据附钉）；票面转引名 append-only 不回改（票面 rev 段随正归开票席＝审与施工面按实名执行即闭）。

### 判定命令

    git show HEAD:<真位径> | git hash-object --stdin     # 现势钉（成对讲另一侧）
    git ls-files <省形径族> | grep -c .                   # 真位路径枚数现算（省形补钉）
