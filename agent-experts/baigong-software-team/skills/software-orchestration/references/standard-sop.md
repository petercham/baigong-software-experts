## 🏗️ 标准 SOP 工作流（中大型需求）

```
用户需求 → 产品经理(PRD) → 架构师(系统设计+任务分解) → 工程师(代码实现) → QA工程师(测试验证)
```

### 逐步流程

1. **接收用户需求**：分析用户的请求，确定工作范围和工作流类型。

2. **分派给产品经理（许清楚）**：将需求转发给许清楚创建 PRD 文档。
   - **简单 PRD（默认）**：产品目标 + 用户故事 + 需求池（P0/P1/P2）+ UI 设计稿 + 待确认问题
   - **完整 PRD（用户明确要求详细分析时）**：在简单 PRD 基础上增加竞品分析（5-7 产品）+ Mermaid 象限图 + 市场定位
   - ⚠️ 默认使用简单 PRD，除非用户明确要求竞品/市场分析

3. **分派给架构师（高见远）**：PRD 完成后，转发给高见远进行系统架构设计 **+ 任务分解**。架构师一次性输出：
   - 实现方案 + 框架选型
   - 文件列表及相对路径
   - 数据结构和接口（类图）
   - 程序调用流程（时序图）
   - **任务列表**（有序、含依赖关系、按实现顺序排列）
   - 依赖包列表
   - 共享知识（跨文件约定）
   - 待明确事项
   - **迁移/合并类设计附加项（条件触发）**：需求含对照样本（既有件/外部产品/旧系统）的迁移、合并或吸收重建时，架构产出必须附**对照样本机制对账表**＝对照样本逐项工序/机制列举，每行处置三态（照搬／部分保留（削哪留哪）／不保留＋理由）；对照样本机制未入任何行＝未被裁决的迁移丢失＝本阶段验收不过。

4. **分派给工程师（寇豆码）**：任务列表就绪后，转发给寇豆码编写代码。工程师将：
   - 按照系统设计和任务列表**批量编写代码**（同一模块相关文件一起写）
   - 全部文件完成后执行 **全局一致性审查**（IS_PASS: YES/NO）
> **过渡口径（v2.9 §20.1·②）**：IS_PASS 自审出口→制度③＋三段式（旧条款保留为技法面，验收结论一律以 SWB v2.9 基线为准）
   - IS_PASS: NO → 修复问题后重新审查（最多 2 轮）
   - IS_PASS: YES → 生成代码摘要，交给 QA

5. **分派给 QA 工程师（严过关）**：代码编写完成后，转发给严过关进行测试。QA 工程师将：
   - 为核心模块编写测试用例
   - 运行测试并进行 **智能路由判定**：
     - 源码有Bug → 反馈给工程师（寇豆码）修复
     - 测试代码有Bug → QA自行修复
     - 全部通过 → 报告成功
   - **最多 2 轮测试**：第 1 轮发现问题反馈修复，第 2 轮回归验证。2 轮仍不过则输出报告标注遗留问题
> **过渡口径（v2.9 §20.1·①④）**：QA 两轮上限→三段式机械判绿＋缺陷票回流；智能路由三态分派→回流四型＋B2 状态机迁移（旧条款保留为技法面，验收结论一律以 SWB v2.9 基线为准）
   - 迁移/合并类需求：核对对账表覆盖度＝对照样本机制清单↔对照样本机制对账表行 diff，缺口＝未绿项。

## ADR 工序（决策记录链）

1. **链序**：人类输入决策→主理人誊录登记（`.collab/decisions/`·append-only·逐字）→产品席＋QA席＋架构席会签→四方收口草案→架构席终写入 `docs/adr/`（编号四位·Status 闭集·头块五行照 ES E-ADR-1″）。

2. **会签语义**：会签＝对收口草案的签署认可；会签席可出保留项——保留项未闭合前终写段禁启动（收口未成）。**保留项闭合归位**：保留项经主理人呈人类裁定（输入决策权恒在人类侧，三席会签不替代决策）；裁定落 decisions 登记后，草案修订＝**架构席照新裁定登记件重誊草案**（誊聚权不含裁量·条款甲语义延伸及重誊；落位仍在 `.collab/drafts/adr/` 既有写域＝零新开写域）；会签席永不改草案（deny 语义不变）。重誊后全链重走会签（同序同判据），旧会签随重誊作废不入账本终态。

3. **终写段＝条款甲（纯机械誊写）**：架构师终写段逐字照录四方会签收口草案，**零文风裁量**——终写件与收口草案正文 diff 必空（哈希对等），架构席职责＝owner/champion 认领担责，不是执笔权，不是内容复审权。收口草案落位＝`.collab/drafts/adr/`（architect 既有写域）；会签签署＝账本签字记录（账本六类·经 state-transition.py 既有通道）；会签保留项落各席既有写域（product→`.collab/product/`、qa→`.collab/audits/`）＝零新写域。

4. **条款乙（既会签又终写不构成自审）**：ADR 记的是四方已收敛决策，非架构单方设计稿；防自审条款（转正代写通道·制度③）辖架构正文链（docs/ARCHITECTURE.md 族），ADR 记录链与其两条路各自成文、互不管辖。

5. **修订/supersede 归道**：ADR 之修订/废止＝**新 ADR 走同一工序链重跑＋supersede 双向互链**（E-ADR 族机理：supersede 双向、accepted 不可变、编号四位唯一不复用·ES v3.1 在册）；不改 §12 通道四类闭集——L2 条款/TCB/阈值/seat-permissions 的**改权**仍归 C1 四通道射程，ADR 是其**记录面**不是变更通道（两线各自成文：内容改权走 C1，决策记录走 ADR 工序）。
