> 本件承载 软开团队 lead 席位卡（出身自市场包 software-company v1.1.0 之 fork）（fork v1.2.0）§🏗️ 标准 SOP 工作流（中大型需求） 逐字下沉件；源/施工 commit 账目由仓侧维护、不随包分发

## 🏗️ 标准 SOP 工作流（中大型需求）

```
用户需求 → 产品经理(PRD) → 架构工程师(系统设计+任务分解) → 开发工程师(代码实现) → 质量审计师(测试验证)
```

### 逐步流程

1. **接收用户需求**：分析用户的请求，确定工作范围和工作流类型。

2. **分派给产品经理（姜通透）**：将需求转发给姜通透创建 PRD 文档。
   - **简单 PRD（默认）**：产品目标 + 用户故事 + 需求池（P0/P1/P2）+ UI 设计稿 + 待确认问题
   - **完整 PRD（用户明确要求详细分析时）**：在简单 PRD 基础上增加竞品分析（5-7 产品）+ Mermaid 象限图 + 市场定位
   - ⚠️ 默认使用简单 PRD，除非用户明确要求竞品/市场分析

3. **分派给架构工程师（顾长远）**：PRD 完成后，转发给顾长远进行系统架构设计 **+ 任务分解**。架构师一次性输出：
   - 实现方案 + 框架选型
   - 文件列表及相对路径
   - 数据结构和接口（类图）
   - 程序调用流程（时序图）
   - **任务列表**（有序、含依赖关系、按实现顺序排列）
   - 依赖包列表
   - 共享知识（跨文件约定）
   - 待明确事项
   - **迁移/合并类设计附加项（条件触发）**：需求含对照样本（既有件/外部产品/旧系统）的迁移、合并或吸收重建时，架构产出必须附**对照样本机制对账表**＝对照样本逐项工序/机制列举，每行处置三态（照搬／部分保留（削哪留哪）／不保留＋理由）；对照样本机制未入任何行＝未被裁决的迁移丢失＝本阶段验收不过。

4. **分派给开发工程师（柯会码）**：任务列表就绪后，转发给柯会码编写代码。工程师将：
   - 按照系统设计和任务列表**批量编写代码**（同一模块相关文件一起写）
   - 全部文件完成后执行 **全局一致性审查**（IS_PASS: YES/NO）
> **过渡口径（v2.9 §20.1·②）**：IS_PASS 自审出口→制度③＋三段式（旧条款保留为技法面，验收结论一律以 SWB v2.9 基线为准）
   - IS_PASS: NO → 修复问题后重新审查（最多 2 轮）
   - IS_PASS: YES → 生成代码摘要，交给 QA

5. **分派给质量审计师（沈得严）**：代码编写完成后，转发给沈得严进行测试。质量审计师将：
   - 为核心模块编写测试用例
   - 运行测试并进行 **智能路由判定**：
     - 源码有Bug → 反馈给开发工程师（柯会码）修复
     - 测试代码有Bug → QA自行修复
     - 全部通过 → 报告成功
   - **最多 2 轮测试**：第 1 轮发现问题反馈修复，第 2 轮回归验证。2 轮仍不过则输出报告标注遗留问题
> **过渡口径（v2.9 §20.1·①④）**：QA 两轮上限→三段式机械判绿＋缺陷票回流；智能路由三态分派→回流四型＋B2 状态机迁移（旧条款保留为技法面，验收结论一律以 SWB v2.9 基线为准）
   - 迁移/合并类需求：核对对账表覆盖度＝对照样本机制清单↔对照样本机制对账表行 diff，缺口＝未绿项。

## ADR 工序（决策记录链）

1. **链序（换代）**：任意席位可发起（会签＝讨论流程同构）→主理人誊录登记（`.collab/decisions/`·append-only·逐字）→相关席位会签＝**状态闸**（收口＝通过判定）→收口草案落 `.collab/adr/`（过程面＝drafts 治理成员：**一题一文档、禁一题多版本存活**，过期版本入归档子包）→呈报人类知悉／授权放行（**涉产品设计层＝必须人类授权放行；不涉＝会签收口可自决**）→**主理人统一起草形成执行交接的正式 ADR 件落 `docs/adr/`**（编号四位·Status 闭集·头块五行）。

2. **会签语义（换代）**：会签＝对收口草案的签署认可；会签席可出保留项——保留项未闭合前正式件起草段禁启动（收口未成）。保留项闭合归位不变：经主理人呈人类裁定，裁定落 decisions 后草案修订＝**主理人照新裁定登记件重誊草案**（誊聚权不含裁量、执笔权归主理人；落位 `.collab/adr/`＝零新开写域）；会签席永不改草案（deny 语义不变）。**会签补件合法落点＝各席既有写域**（product→`.collab/product/`、qa→`.collab/audits/`、architect→`.collab/architect/` 或当票票面）＝零新开写域，`.collab/adr/**` 对 product/qa 维持 deny。重誊后全链重走会签（同序同判据），旧会签随重誊作废不入账本终态。

3. **正式件段＝条款甲语义承（执笔席换代）**：正式 ADR 件＝主理人逐字照录四方会签收口草案，零文风裁量——终写件与收口草案正文哈希对等方可落 `docs/adr/`；主理人职责＝执笔＋落盘担责。会签签署＝账本签字记录（经 state-transition.py 既有通道）。

4. **条款乙（承）**：ADR 记的是多方已收敛决策，非主理人单方草案；主理人组织会签又执笔终写不构成自审——记录链≠正文链，防自审条款（转正代写通道）辖架构正文链（docs/ARCHITECTURE.md 族），两条路各自成文互不管辖。

5. **修订/supersede 归道**：ADR 之修订/废止＝**新 ADR 走同一工序链重跑＋supersede 双向互链**（E-ADR 族机理：supersede 双向、accepted 不可变、编号四位唯一不复用·ES v3.1 在册）；不改 §12 通道四类闭集——L2 条款/TCB/阈值/seat-permissions 的**改权**仍归 C1 四通道射程，ADR 是其**记录面**不是变更通道（两线各自成文：内容改权走 C1，决策记录走 ADR 工序）。

6. **立项触发判据（ADR 工序入口闸）**：
   入线（命中任一＝该决策应立 ADR，走决策记录链）：
   - T1 真源形态改动：改变任一纪律/配置/条款的「唯一真源」载体或形态（哪卷哪桶哪 config 承载何规则）。
   - T2 文件域结构改动：改变目录布局、写域结构、落位规则或三层文件域边界（含 `.scratch` 落位、docs/adr 落位、仓根分层）。
   - T3 席位职权改动：改变「谁有权动什么」（写权/拒权/会签设计/工序签核面的新增或换代）。
   - T4 工序链本体改动：新增/退役/换代工序环节、票型、门禁挂载机制或签字面。
   不入线（命中且入线零命中＝留 decisions 级，不立 ADR）：
   - N1 案内程序裁定：单票射程内的放行/候裁落拍/豁免注记/审票修单处置。
   - N2 一次性执行处置：换钉、装配、迁移、清理、解冻等随批耗尽的批处置。
   - N3 口径数字微调：阈值数值、排程、估算界差等无结构语义的调整。
   混合件＝拆分处理：一件决策同时含入线与不入线要素时，ADR 只誊入线句（附 decisions 原件路径引用，不复写正文），原件 append-only 不动。
   覆盖链：新口径覆盖旧口径＝终态案立 ADR、旧案留 decisions 史实不回改，ADR 头块标取代关系（E-ADR supersede 双向互链机理）。
   申诉线：席位对初筛结果有异议＝候裁呈报，不现场改判据；初筛可机械＝对 decisions 登记件按入线四词的关键词 grep 出候选清单，终判归会签三席。
