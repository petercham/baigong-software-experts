# 他域工单规范卷（references 面·工单形制本体）

本卷承载「他域工单」形制本体：他域交互从「链上 message 夹带＋收口批次面义务挂账」升格为有形制的工单体。射程＝我域（本包）向领办域发起的诉求件＋领办域向我域知会的入账面；票面形制不归本卷（票面真源＝thin 卷在册不动·效力域字段不入票模板＝票级放行登记采裁在册）。他域文件零写＝形制级写死（§三 效力域五行）；跨仓投递动作不归我域（§五）。

## 一、形制总则

- 工单体＝一号一件的独立成文件；件号入件头（§二 字段一）；一件一号，禁多号共件、禁一号多件（并单例外见 §二 字段一「并单口径」）。
- 一号一单为原则：按诉求性质分单（不同领办域／不同响应面／不同时效＝必分单）。
- 并单口径：仅同一领办域内、同一响应面、同一时效的多枚诉求可并为一单＝并单指诉求并单非议题全并；并单依据须引链上放行登记原文具名。
- 工单件与票面互斥：工单不是票＝不入票面桶、不走票面机检射程；工单件落位＝桶闭集内在册桶（见 §四 落位条款），禁新立桶（新桶＝机检裸奔面）。
- 体例纪律（工单件与规范卷本体同规）＝零反引号零 at；叙述面路径裸文＋全角斜杠；引用原文以 ⟦⟧；命令一律缩进段；入线四词字面禁写（词表以票级放行登记勘正表为准）。
- 成文即登记：工单件落盘＋登记面入账（§四）＝我域义务面完成态；投递与消费态由领办面回注，非我域写权（§三 五行之三）。

## 二、工单体八字段（节题闭集·逐件实占·节题计数恰 8）

工单体节题顺序固定如下八字段，每件逐件实占，禁留空槽；验收口径＝节题计数恰 8。

字段一：编号族

- 形制＝EXT-YYYY-MM-DD-<主题短名>-v<N>（EXT 前缀＋日期形制·一日期一主题一号·版本号 v1 起 append-only）；件头首行标题必含件号全文＝件头对号可机核。
- 落盘面名＝EXT-YYYY-MM-DD-<主题短名>-v<N>.md（与件号同形制·不撞收口登记名正则＝配对段不误判）。
- 并单口径：并单件仍一号，内列多诉求逐项编号（R-1／R-2／R-3＝逐项可独立销账）。

字段二：领办域具名

- 写明领办域＝哪个仓／哪个会话窗／哪个角色领办；禁「相关方」「上游」类泛指。
- 领办域判定依据引链上放行登记或裁定件具名（blob 四十位＋行数成对）。

字段三：效力域声明五行

- 行一＝本席写权域止于本包（写集面单全部居本包声明闭集内）。
- 行二＝目标域零写权申明（我域对领办域仓内一切路径零写；只读取证不禁）。
- 行三＝跨仓投递动作归主理人主根窗（我域义务止于成文＋登记＋呈递主理人；投递时点与方式归主根窗另排）。
- 行四＝消费判据归属被领办域（领办域收口必列项与否＝其设计权＝我域不越权裁）。
- 行五＝失效发现面＝随动账（我域消费面随动账登记在册＝钉值／行号分叉的我方发现面责任在我方）。

字段四：诉求体闭集四型

- 四型闭集＝动作诉求（请领办域改其域某件某处·逐项可销账）／信息诉求（请领办域提供我方缺失信息）／随动知会（他域已改／已定事项告知我方消费面＝不要求动作）／仅备案（我方登记事项告知留存＝不要求动作不要求信息）。
- 每件诉求体必标型；并单件内逐项标型；闭集外自造型＝违例。
- 响应面与时效（字段七）须与型匹配：动作诉求＝响应面写明领办域内销账动作；随动知会／仅备案＝响应面可空但必具名申明「无动作面」。

字段五：钉值取证面

- 一切他域引用＝blob 四十位＋行数成对，或 commit 四十位＋面单成对；禁裸名（非四十位短式 sha 裸引＝违例；具名八位短式仅在与其四十位全式成对出现处可用）。
- 两仓成对讲法（他域行号与钉值写死条款）＝凡引他域件行号或钉值，必本链侧值＋主仓侧现势值并列成对讲（本链钉值＋行号／主仓侧钉值＋行号同栏并列）＝「引用即漂移」防御条款：本链行号对领办域现势必漂＝单侧行号呈领办侧即取件必 MISS。
- 取证读数＝当轮现跑；禁抄旧数；跨仓值经只读命令现取（hash-object／wc／sed 取行）后誊入。

字段六：依据链

- 本单成立所依的链上件逐枚具名（票级放行登记／裁定／收口批次面义务行）＝每枚 blob 四十位＋行数＋关键行号三面成对；引文以 ⟦⟧ 逐字。
- 排程生成项如实登记（计划面单无对应行时申报为排程生成项·引收口批次面义务行为据）。

字段七：响应面与时效

- 写明：领办域内的销账动作（哪件哪节列入／哪个断言列增否）＋我方侧销待口径（成文即销「待发」态＝已成文待发投递）＋投递态归主理人窗登记。
- 终点表述统一＝「成文＋登记＋呈递主理人」（投递到达类近义表述不入产出件＝投递非我域义务面）。
- 时效＝随领办域下一收口拍／汇链窗等具名窗口；禁「尽快」类不可判值。

字段八：状态面闭集与回流挂钩

- 状态面闭集＝已登记／已投递／已消费／已闭合 四态；我方成文＋登记＝置「已登记」；「已投递」归主理人窗回注；「已消费」归领办面回注；「已闭合」＝双侧账平后由领办收口或我方随动账销账后置态。
- 状态变更＝在件尾状态行追加（append-only·状态行历史不回改）；我方禁回注「已投递／已消费」＝该两态回注权归投递窗与领办面。
- 回流挂钩：工单件被我域票链消费时＝票链侧回流件引用工单件号＋盘 blob 成对；工单件侧不反向写票体（他票票体禁写）。

## 三、效力域字段闭集（形制级硬条款五行）

- 我域义务止于成文＋登记＋呈递主理人；投递动作归主根窗；我域禁一切跨仓投递动作（对领办域仓内路径零 add 零 commit 零写）。
- 开票效力越界＝体系缺陷案型的正面防御：工单件的写集面单必全部居我域声明闭集内；面单出现领办域路径即停手呈裁。
- 版本外共享面（主仓 .git／hooks／类）归属协议：该类面由主根会话独占改；我域侧只保有随动账（钉值／行号两栏）＋分叉知会义务（S 型＝随动知会／仅备案）；我域禁对该类面做修复动作。
- 只读取证面：领办域件经只读命令（hash-object／wc／sed／log／show）取值不违效力域；取证读数落我域 ignore 取证域。

## 四、知会登记面规格（入账路径＋落位）

- 登记台账＝本卷 §四.3 节（首样现填）；后续工单逐行追加（append-only）。
- 他域改动向我方知会的入账路径：领办域链上改动笔（我域侧判据＝merge-base --is-ancestor 对我域 HEAD＝NOT-IN-WT-CHAIN 者）＝经只读现跑确认后入登记面一行＝日期＋领办笔 commit 四十位＋面单枚数与首末枚具名＋我域消费面影响一句＋状态置位。
- 缺位症状（本登记面设立依据）：他域改动我域仅靠链上 message 夹带知会＝无消费面＝分叉静默合链风险；登记面＝该缺位的我域侧最小消费面。
- 落位条款：规范卷落本包 skills／sop／references／ 桶；实战工单件落本包 .collab／decisions／ 桶（EXT 前缀日期形制）＝两落位皆在册桶名；MC-BUCKET-1 桶名闭闸扫描域＝仓根一层不扫包内嵌套桶＝「包内桶受桶名闭闸覆盖」不成立（配对段 MC-PAIR-1 覆盖成立＝缺省下探本包桶）；新立包内桶＝机检裸奔＝禁。

## 五、投递与消费两态

- 成文＋登记＋呈递主理人＝我域义务终点三件套；呈递载体＝完工回报面列具工单件路径＋盘 blob 四十位＋行数。
- 投递动作本体＝主根窗职权（把工单件内容呈入领办域消费面）；我域禁一切跨仓投递（add／commit／写领办域路径／改领办域桶皆属投递动作＝禁）。
- 消费侧两态回注：「已投递」由投递窗回注工单件尾状态行或回报面注明；「已消费」由领办面收口引用工单件号；我域随动账在消费面落地（消费脚本升版＝随动账销账）后置「已闭合」。
- 时效面：未消费工单件＝随各收口／汇链窗批次面随登待办；禁静默过期。

## 六、纪律

- 零反引号零 at；叙述面路径裸文＋全角斜杠；引用原文以 ⟦⟧；命令一律缩进段；入线四词字面禁写（本卷通篇自查口径）。
- 钉值枚枚成对（blob＋行数／commit＋面单）；禁裸名；短式仅在成对处具名使用。
- 两仓成对讲法：他域行号与钉值必本链侧与主仓侧并列；单侧值即违例。
- 产出件不抄 thin 使用说明行（引用即漂移条文：对任何真源固定行「引用即漂移」＝不沿袭）。
- append-only：工单件正文不回改；修订以 v<N+1> 新件或件尾 rev 段追加；状态行只追加。
- 他票票体／账本／链上史件零触；工单件不自列候裁（批次编排类不上楼）。
