# 违例归账＝网络动作不查成法通道，现踩已闭的坑（2026-11-19 23:1x 皮总斥「git 提交踩过的坑每个重新踩一遍？key 也是代理也是，就不会用一直用的成功方法直接 curl？」）

## 一 违例事实

来件通道处置（百工 git issue 工单）中，主理人依次试了 `gh`（本机从未登录＝必败路）、走本机代理的 curl/git（代理断连＝已证伪路），均失败后才想起既有成法＝**凭据管理器 key＋绕本机代理**（本仓 git push/ls-remote 历来走此路，凭据可 `git credential fill` 现取）。三笔试错损耗全属重复踩坑。

## 二 归因

同「止痛掩病」自查哨兵同族＝成功路径在册不引用，凭手头默认工具另辟新路。网络类动作此前无「先查成法账」条目，本次补立。

## 三 补立口径（即日生效）

1. 凡需 GitHub API/网页面认证的动作：第一步＝`git credential fill` 取既有 key＋绕代理（unset http_proxy/https_proxy）直连；不试 `gh`（未登录态在册）、不试不绕代理的默认路。
2. 任何工具路使用前先问：本仓此前同类动作成功走的是哪条路？在册成法优先于默认习惯。
3. 脚本类取证：git  plumbing 输出含中文/特殊字符路径时，解析一律 `-z` 制（ls-tree -z／diff -z），禁按行 split（引号转义路径必错＝本窗已实证案型「MISS 29 枚」假读数）。
