## 〇、总览与落点决定

S1 交付面落点根＝`deliverables/skills/fuxi-skill/`（沿用 S0a 已确立的「产品线目录＋职能子目录」结构惯例：S0a 职能面＝`gates/`）。

**三契约文件落点决定＝`deliverables/skills/fuxi-skill/contracts/` 子目录**，与 `gates/` 平级：

```
deliverables/skills/fuxi-skill/

  contracts/
    evidence-grading.md

  board → 不落交付面，实例落 `.collab\board\`（见 §三.3 与候裁点 C-4）
```

落点理由（三条）：
1. **职能分离**：`contracts/`＝声明面（字段与节的注册闭集本体），`gates/`＝检面（对声明面做机械断言）。断言工具按固定路径静态定位三契约文件（ST-1/ST-2 的判据对象），契约与工具互不嵌套，注册面路径即断言基面。
2. **不稀释 S0a 面**：`gates/` 语义＝工具与断言目录；契约文件塞入会破坏「一目录一职能」，且 FC-2 字段注册表在工具侧、契约声明在契约侧，二者靠 §五互洽对照表对账，不靠同目录。
3. **留档区与契约同根**：`rejected/` 属交付面（未通过候选保持可审计＝A5 的产品线纪律面组成部分，非过程案卷），与契约文件同根，可被同一 git 版本受控（A6），ST-5「目录存在且条目可列」有固定路径基面。

**「看板三栏＋状态词表合并起草件」的载体决定**：不单造第四件，合并落 `artifact-contract.md` 第五节（状态词表与看板节）。理由：断言目录 ST-1 已将 artifact-contract 预注册为「名 evidence-grading／failure-modes／artifact-contract 三件之一的主契约面」——状态词表与看板契约并入其中即天然满足 ST-1，且不触 ST-2 三文件名闭集变更（变更需走 S0a 面重交付）。详见候裁点 C-5。

三文件共同硬纪律：**节闭集**（一级节名集合＝本件所定，多节/缺节/改名＝diff 非空即 fail）＋**字段名闭集**（文件内出现的状态/字段名 ⊆ 注册表，未注册字段零容忍，FC-2）。

## 一、三契约文件规格

### 1.1 `contracts/evidence-grading.md` — 证据三级标注与可答口径

节闭集（一级节名，恰为下列六节）：

| # | 节名 | 内容 |
|---|---|---|
| EG-1 | `适用范围` | 双轨全部候选单元与产物要素级标注；不含采集姿态（姿态属各轨 adapter） |
| EG-2 | `三级标注` | 三级取值闭集＋标注规则 |
| EG-3 | `来源三态` | 来源态取值闭集＋与三级标注的正交声明 |
| EG-4 | `三问可答口径` | 任一候选单元必答三问的字段口径 |
| EG-5 | `候选单元记录` | 候选单元记录格式＋字段名闭集＋示例行 |
| EG-6 | `语料门槛登记` | 语料纪律的可机检门槛数值登记位（A1） |

**三级标注（EG-2）**：
- 字段名＝`证据等级`（中文名沿用中英混用基线，候裁点 C-2）；取值闭集＝`原文可证实`／`跨文本推断`／`模型补全`（对应设计稿 A3 的 ①原文可直接证实 ②跨文本统计推断 ③模型补全）。
- 硬规则：`模型补全` 强制显式标注，不得以未标注隐式存在；允许且鼓励在证据不足处直接写「证据不足」不补全（与 §五 D9 口径衔接）。
- 与 `evidence_grade`（产物契约状态字段，D11 三栏证据卡第一栏）的**轴区分**：`证据等级` 标注「该要素内容与来源的关系」（可证实/推断/补全）；`evidence_grade` 标注「该结论的证据获取方式」（人工验证/机械断言/LLM 判定）。两轴正交、各自闭集、不得互推互替。此区分必须写入 EG-2 节正文，防字段语义并轨（FC-2 字段名各自注册）。

**来源三态（EG-3）**：字段名＝`来源态`；取值闭集＝`本人原文`／`第三方转述`／`模型推断`（A3/B7 三态标注，可回查）。来源态与三级标注正交（本人原文可以是跨文本推断的原料）。

**三问可答口径（EG-4）**：任一候选单元（candidates 期与 rejected 期皆算）必须可机械回答：
1. **证据等级**？→ 字段 `证据等级`（EG-2 闭集）＋字段 `evidence_grade`（FC-1 闭集）双轴在场；
2. **对照臂有无**？→ 字段 `control_arm`（§1.3 产物契约 D11 卡定义）；
3. **测试题是否在语料内**？→ 字段 `leakage_check`（§1.3 产物契约 D11 卡定义）。
三字段缺任一个＝该单元不可答，ST-5／S1 验收「三问」判据不过。

**候选单元记录（EG-5）**：机读块形态（markdown 内嵌 fenced json 块，保证可解析）。字段名闭集与示例行：

| 字段名 | 取值/类型 | 说明 |
|---|---|---|
| `candidate_id` | string | 候选单元编号，批次内唯一 |
| `所属轨` | `person`／`method`／`bundle` | 沿用 ST-4 `所属轨` 取值风格 |
| `证据等级` | EG-2 闭集 | 三级标注 |
| `来源态` | EG-3 闭集 | 三态标注 |
| `evidence_grade` | {人工验证, 机械断言, LLM 判定} | FC-1 注册值，逐字同集 |
| `calibration_state` | {校准态, 待校准} | FC-1 注册值，逐字同集；缺省即「待校准」（fail-closed） |
| `source_id` | string | 与 `位置` 成对（FC-3） |
| `位置` | string | 章节/页码类位置形态（FC-3） |
| `control_arm` | §1.3 闭集 | 三问之二 |
| `leakage_check` | §1.3 闭集 | 三问之三 |
| `abstain_tier` | {有支持, 有限定, 无支持但貌似合理, 明确幻觉} | 仅结论级条目必填；与 BW-2 注册四档逐字同集 |

示例行（json 块）：

```json
{"candidate_id": "c-0107", "所属轨": "person", "证据等级": "跨文本推断", "来源态": "本人原文",
 "evidence_grade": "LLM 判定", "calibration_state": "待校准",
 "source_id": "src-03", "位置": "第三章·第二节",
 "control_arm": "未测", "leakage_check": "未检", "abstain_tier": "有限定"}
```

**语料门槛登记（EG-6）**：登记可机检门槛数值——`一手占比门槛`＝50%（一手占比>50% 门槛，A1）；`新鲜度窗口月数`＝12（最近 12 个月采集位，A1）；`黑名单存在`＝必须非空。此节为数值登记位（门槛参数≠领域判据，入基座无争议），产物/批次报告中的占比类数字受 BW-3 裸数字规则管辖。

### 1.2 `contracts/failure-modes.md` — 失败模式 if-then 表框架＋分轨条目

节闭集（恰为下列五节）：

| # | 节名 | 内容 |
|---|---|---|
| FM-1 | `表结构` | 条目五元组格式定义 |
| FM-2 | `分流语义` | 处置三态词＋「无逃逸路径」硬条款 |
| FM-3 | `共享条目` | 双轨同构失败模式（基座本体） |
| FM-4 | `person轨条目` | person 轨真条目（护栏方向＝防「编」） |
| FM-5 | `method轨条目` | method 轨真条目（护栏方向＝防「调不出/误触发」） |

**FM-1 表结构**：每条＝五元组闭集 `编号`／`轨别`／`触发`／`检出`／`处置`。轨别取值＝`共享`／`person`／`method`（与 §三 B-3/A4 边界注对齐：框架入基座，具体条目分轨）。

**FM-2 分流语义**：处置三态词＝`降级`／`阻断`／`转人工闸`。硬条款（写入正文、机检扫描）：
- 处置字段不得为空、不得含「视情况」「酌情」「后续再定」类不确定措辞（检出＝子串扫描，命中即 fail）——失败时无逃逸路径；
- 每条 `检出` 字段必须可指向一个机械或清单化动作（含「人工闸」本身是合法处置去向，但触发与检出仍须具体）。

**FM-3 共享条目（5 条）**：

| 编号 | 触发 | 检出 | 处置 |
|---|---|---|---|
| FM-S-01 | 语料不足（一手占比不足门槛或语料为空） | 一手占比检查读数（EG-6 门槛）；「没有文件的研究＝没做」落盘核对 | person 轨：转人工闸（索取补充语料或确认降级）；method 轨：阻断（无文本即停，向用户要文本） |
| FM-S-02 | 上下文不足（维度级结论无据可支） | 维度级结论无 `source_id`＋`位置` 成对标注（FC-3 检出） | 降级：该维度写「证据不足」不补全，强制标 needs_review |
| FM-S-03 | 成本失控（标注/蒸算开销越出预注册预算） | 开销台账越线读数 | 阻断当前批次，转人工闸复核预算 |
| FM-S-04 | Agent 冲突（双路/多判读结论互斥且不可归并） | 双判读结论 diff 非空且无归并规则 | 转人工闸：矛盾原样留档（不平滑，B-7 铁律），产物标 needs_review |
| FM-S-05 | 产出互斥（同一要素两版结论并存） | 要素级重复结论 diff 非空 | 阻断：两版并存留档＋矛盾声明，禁平滑合并 |

**FM-4 person 轨条目（4 条，防「编」）**：

| 编号 | 触发 | 检出 | 处置 |
|---|---|---|---|
| FM-P-01 | 幻觉填充（无据要素入候选） | `证据等级`＝模型补全 且无 `abstain_tier` 落档 | 阻断：该要素退回，补 `abstain_tier` 落档或剔除 |

**FM-5 method 轨条目（3 条，防「调不出/误触发」）**：

| 编号 | 触发 | 检出 | 处置 |

## 二、rejected/ 与 coverage-audit 规格（A5）

### 2.1 目录约定

```
deliverables/skills/fuxi-skill/rejected/
  <batch-id>/                 ← 每蒸馏批次一目录（batch-id 命名＝日期-对象编号 kebab）
    <candidate-id>.md         ← 每条淘汰候选一个条目文件（candidate_id 与 EG-5 一致）
    coverage-audit.md         ← 每批次恰一份审计件
```

- `rejected/` 目录本身必须存在（批次为零时允许空目录）＝ST-5「可枚举」的机械基面：目录存在＋条目可列；空 listing 是合法的可枚举态（断言工具已按此语义实现）。
- candidates（在选候选）不落 `rejected/`，其记录以 EG-5 候选单元记录形态嵌于批次工作件；淘汰动作＝候选条目落入 `rejected/<batch-id>/`＋coverage-audit 计数更新，两步同 commit（版本受控 A6）。

### 2.2 条目文件字段（淘汰条目）

条目文件机读块字段名闭集＝`candidate_id`／`所属轨`／`淘汰维度`／`淘汰理由`＋继承 EG-5 三问字段（`证据等级`／`control_arm`／`leakage_check` 必须在场非空——淘汰条目同样可答三问，保证「未通过候选保持可审计」是可答的而非仅可看的）。
- `淘汰维度`＝本轨判定维度名（person 轨白名单＝跨领域复现／预测力／排他性；method 轨白名单＝跨段落佐证／可执行性／任务效用——判定维度分轨＝A5 边界注，框架共用）；
- `淘汰理由`＝自由文本非空＋不得含 FM-2 不确定措辞。

### 2.3 coverage-audit 审计件

恰含三问字段（逐字＝ST-5 注册名）：`哪些留下`／`哪些扔了`／`为什么`——三字段齐备非空；计数类数字受 BW-3 裸数字规则管辖（行级三件套扫描）。审计件同时登记 `一手占比` 读数行（承 EG-6 门槛，受 BW-3）。

## 三、看板三栏＋状态词表合并起草件规格（R22②，载体＝AC-5 节）

### 3.1 三栏结构契约

看板实例件格式（固定 markdown 结构，机检＝栏目名串扫描＋状态 token 扫描）：

```
.collab\board\board-<YYYY-MM-DD>.md
---
性质＝记录件·人工触发填写·非控制器
---
## 本轮改动
（本表周期/事件窗口内对交付面 fuxi-skill 面的改动条目列表；无改动必须写「无」）
## 触发的坏信号
（四条坏信号①IR串味②锚失去可回查位置③门禁统一到最弱④内部矛盾消失＋FM 条目命中读数；无命中必须写「无」）
## 人工闸结论
（人裁处置记录，含状态词表取值 token；无议题写「无」）
```

**「记录件非控制器」条款（入契约正文，AC-5 节内）**：看板信号不得自动驱动任何产物改写、不产生任何状态迁移、不自动生效（与 R16 三定义域/自指循环结论同源）；一切状态迁移仅经人工闸结论＋独立提案＋版本审计生效。机检位＝文件头性质声明行必须在场（缺行＝fail）。

### 3.2 阈值与周期（设计定稿值——本票定，附建议值理由）

| 参数 | 定稿建议值 | 理由 |
|---|---|---|
| 填写触发 | **双触发制**：①事件触发——任何一次对交付面 fuxi-skill 面的改动或任一状态词迁移，须在改动同轮填板；②周期兜底——每 **14 自然日** 至少一板（无改动也填三栏「无」） | 看板价值在「坏信号→人工闸」链路新鲜度；14 日＝产线早期节奏下限与人力成本的折中；机检＝相邻 `board-<日期>` 文件名日期间隔 ≤14 天，超限＝fail（周期违规记未验并转人工闸议题） |
| 坏信号触发阈值 | 四条坏信号及 FM 条目命中计数 **≥1 即须填板**（零容忍） | §十一 S4 行验收口径＝四信号检查项全绿；坏信号无配额制 |
| 悬置升级阈值 | 同一「未验」/「待校准」悬置项连续 **3 个板次** 无状态迁移 → 强制列入人工闸议题 | 一个缺陷通常需「定位→修复→复测」一个来回，3 板次（≈42 天）为容忍上限；3 为建议值，随周期参数同裁 |
| 复审到期日规则 | `复审到期日` ＝ `快照时戳` ＋ **90 自然日**；越期未复审的产物 → 状态自动列 `needs_review` 候选清单（列清单＝存证动作，不自动改写状态，须人工闸确认） | A6「快照陈旧」由复审承接；90 日与 14 日填板周期成 6:1 嵌套，保证到期前至少两轮看板可见 |

### 3.3 状态词表取值闭集

**基线闭集（与 FC-4 注册位逐字全等，建议不扩）**：`needs_review`／`active`／`归档区`／`待校准`／`未验`。

层级口径（写入 AC-5 节正文）：`needs_review`／`active`／`归档区`＝产物级状态；`待校准`＝校准轴状态（与 calibration_state 同词同源，由 κ 自动驱动）；`未验`＝要素/读数级标记（三值报告缺一记「未验」等）。

「已核」语义：不单设状态词——人工闸「已核实通过」的语义由看板「人工闸结论」栏自由文本＋对应产物状态保持/迁移到 `active` 承载；理由＝FC-4 词表已随 S0a 交付锁定，扩词表须走 S0a 面重交付，收益不抵成本。单设与否列候裁点 C-1，推荐不扩。

看板实例落点（`.collab\board\`，交付面外）：看板记录的是产线内部治理活动，属过程记录非产品工件；契约（栏名/词表/阈值）在交付面 AC-5 节，实例在场外。列候裁点 C-4。
