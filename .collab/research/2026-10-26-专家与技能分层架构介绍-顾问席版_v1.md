## 一、载体：专家包在 WorkBuddy 里长什么样

一个专家包（plugin）＝一个专家团队的完整可分发单元，注册到 WorkBuddy 后即可对话使用：

```
aigc-video-team/                     ← 专家包（当前 v1.4.0）
├── .codebuddy-plugin/plugin.json    ← 包元数据（名称/版本/成员/技能清单）
├── agents/*.md                      ← 专家层：每席一份 persona MD（身份卡）
│     lead + content-strategist + screenwriter + director
│     + production-designer + editor + operations ＝ 7 席
├── settings.json                    ← 团队装配（席位与技能绑定）
└── skills/<skill>/                  ← 技能层：按能力域横切
      ├── SKILL.md                   ← 技能主文（≤5000 token 级）
      └── references/*.md            ← 分卷细则（被动知识·由 SKILL.md 引用）
```

- **注册＝一次性快照扫描**：注册脚本读 plugin.json 建索引，**不增量同步**；结构变更须「删旧→拷新→重注册」闭环（v1.4.0 已按此完成）。
- 当前 5 个技能（能力域横切，**不按角色/席位分**）：`orchestration`（编排）／`governance`（治理与闸）／`content`（内容）／`visual`（视觉）／`release`（成片与发布）。

## 二、两层模型与主判据（决议 Q1）

| | 专家层（席 MD·常驻） | 技能层（skill·按需加载） |
|---|---|---|
| 判据 | 「**换一个人也必须一模一样**」的东西 | 「**换一个专家做同类任务也用同一套**」的东西 |
| 装什么 | 身份、红线、权限、判定权、闸纪律铁律 | 方法论、判据、模板、工艺、回归用例 |
| token 轨 | **≤2500 红线**（目标 2350） | SKILL.md **≤5000 级**＋references 分卷 |

- **冲突时专家层赢**；skill 加载失败走降级纪律（能力声明＋降级，不静默失能）。
- **技能不承载**（决议 Q2）：身份红线、放行判定、审美终审、项目级风格规约（圣经 SSOT）、数据本体与确认状态——这些永远在专家层或人类闸手里。

## 三、编排归属：N1 三层拆解案（决议核心）

团队流程（五道人类确认闸 G1 圣经→G2 剧本→G3 提示词→G4 生成预算→G5 成片＋档位路由）的内容按三层拆放：

| 层 | 内容 | 归属 |
|---|---|---|
| ① 闸序与档位路由 | 五档各走哪些闸、顺序、派单时序 | **主理人 MD（编排层）** |
| ② 单闸执行程序 | G4 怎么呈预算块、G3 怎么组织样张呈报 | **随相关 skill** |
| ③ 闸纪律铁律 | 显式确认、沉默不算、不确认不流转、闸不可跳 | **专家层常驻** |

两条成文细则＋三守门（防拆歪）：

1. **「呈什么/何时呈/确认前禁止什么」＝骨架留主理人 MD；「怎么组织呈报、怎么记录」＝细则进 skill**——「执行程序随 skill」不得被宽读为把确认物清单搬走。
2. **三守门**：单真源（同一内容只一处全文，互引不双写）；常驻保障（路由与步骤不依赖 skill 加载）；判定权不下放（细则 skill 不含路由/闸判定）。

## 四、技能层内规（决议 N2＋维度标准）

- **N2 承载判据**：被动查询的知识→`references/` 文档（由 skill 引用）；主动触发的程序→独立 skill。
- **维度型别**（`object-build/references/10-skill.md`）：D 纪律强制型／T 流程型／M 方法论型／F 模板型。**D＋F 混装合法；D＋T 混装须拆**——整改任何 SKILL.md 前先判型别归属。
- **分层形态**（Q3）：按能力域横切建库，严禁按角色/席位分层；纵向仅 core/domain 一层命名约定；skill 内部深浅由渐进披露天然承担；情景记忆进案例库、语义层进 references/，均不塞进 skill 目录。

## 五、人类闸与判定权（不可让渡项）

- 五道人类确认闸 G1–G5 的**放行判定权永远在人类**（A-04 接口不动）；AI 侧只组织呈报、记录闸道。
- 闸纪律（显式确认、沉默不算数、不确认不流转）为专家层常驻铁律，不随技能加载状态浮动。
- 已拍数字示例：单镜头重生成 ≤3 次（裁-44：总次数上限≤3，其中重试≤2）。

## 六、给顾问的评估基准提示

1. 评估「缺什么」时请区分**三层归属**：某机制「在主理人 MD／在 skill／在专家层铁律」都算「在包」；只有三层都没有才算缺失（「在包不在文」≠缺失）。
2. 圣经（项目级风格规约 SSOT）＝**项目层资产**，不是专家包资产：包提供「怎么生产圣经」的程序（G1 确认物清单），不携带某项目的圣经内容本身。
3. 具名外部引用须过锚点核验（A-01 纪律）：查无实源的具名引用降格为社区约定表述。
