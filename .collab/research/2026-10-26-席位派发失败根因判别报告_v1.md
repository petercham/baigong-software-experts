## 4. 判别论证（排除法）

1. **排除②（席位 MD）**：
   - 前提 A：MD 唯一作用通道 = 注入提示词文本（3.1 全文+全库检索证实，无任何运行时钩子条款）。
   - 前提 B：错误发生在框架恢复预检，Duration 0s，未进模型调用（3.2 错误签名 + Framework Auto-Notification 投递方式）。
   - 前提 C：同 MD 的新实例重派成功（3.2 对照实验）。
   - ∴ MD 内容不在故障路径上，②不成立。
2. **锁定①（平台机制）**：
   - 故障点可定位到"挂起→恢复"这一新增跨轮持久会话环节：resume 预检按 `resumeSessionId` 查会话 → 进程内会话已随取消终止、磁盘 transcript 不存在 → `was not found`。
   - 平台自身声明（L271 "transcripts are preserved"）与磁盘实况（文件不存在）矛盾 → 持久化/落盘路径存在缺陷，属平台运行时层。
3. **残余不确定性**：闭源实现不可读，"未落盘"的具体子机制（取消时 flush 缺失 / 索引注册竞态 / 清理过早）无法细分 → 置信度 85% 而非 100%；但"平台层 vs 席位 MD 层"的判别本身证据充分。

## 5. 平台 bug 登记条目

- **标题**：团队挂起成员（paused teammate）恢复失败——resume 预检报 session not found，挂起实例 transcript 未落盘
- **错误签名**：`Unable to resume teammate session agent-<uuid>: Error: Teammate session agent-<uuid> was not found`（Framework Auto-Notification，Duration 0s）
- **环境**：WorkBuddy 桌面版（Windows），Agent Team / 专家团模式，跨轮持久团队会话
- **复现步骤**：
  1. 主理人 TeamCreate + Agent 派发团队成员（background teammate）；
  2. 成员运行仅数十秒内，用户取消主理人轮次 → 成员被挂起（`status=paused, lifecycle=alive`）；
  3. 下一轮主理人按框架提示对 alive 成员 SendMessage 续飞；
  4. 框架自动通知报 `Unable to resume teammate session ... was not found`，成员转 `status: failed`。
- **关键异常**：`runtime.json` 保留完整 `resumeSessionId`/`transcriptPath` 字段，且框架提醒声称 transcripts preserved，但对应 `.jsonl` 文件在磁盘上不存在（`find` 全盘零命中）；同团队其他成员 transcript 均正常存在。
- **影响**：挂起恢复能力（续飞）不可靠，只能整单重跑，丢成员上下文。
- **建议反馈渠道文案**（可直接粘贴）：
  > WorkBuddy 团队模式 bug：用户取消主理人轮次后，运行仅约 30 秒的 background teammate 被挂起（status=paused, lifecycle=alive），随后按框架指引 SendMessage 续飞，框架报 "Unable to resume teammate session agent-1528a92f-d18f-4b20-90e3-6873f9eb3482: Teammate session was not found"（Duration 0s）。teams/runtime.json 中该成员 resumeSessionId 与 transcriptPath 字段齐全，框架提示词也声称 transcripts preserved，但该 transcript .jsonl 在磁盘上根本不存在（同会话其他成员均存在）。疑似取消时挂起实例的 transcript 未 flush/未注册。请修复挂起路径的持久化，或在 transcript 缺失时让 resume 预检给出可降级路径（如从 assignment 全文重建会话）。

## 6. 对主理人兜底策略的建议

| 情形 | 建议 |
|---|---|
| 成员被挂起后首次续飞 | 可先试一次 SendMessage 续飞（成本低，信箱投递本身会成功） |
| 续飞后收到 Framework Auto-Notification `resume ... not found` | **立即放弃续飞**，不再重试同一实例——该成员已 `status: failed`，会话数据不可恢复 |
| 重派 | 直接 Agent 重派新实例，任务书**全文重发**（不假设旧进度可续）；名字被占用自动加 `-2` 后缀属正常，无需处理旧占位 |
| 止损预防 | 对预计运行较长的成员，尽量**不要在其运行中途取消主理人轮次**；确需取消，默认按"该成员进度作废、需重派"规划 |
| 台账修正 | 重派后同步 TaskUpdate 把任务 owner 指向新实例名，避免台账与 runtime 脱节 |
