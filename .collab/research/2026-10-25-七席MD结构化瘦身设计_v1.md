## 一、基线复算与差值

### 1.1 口径声明（可复现脚本见附录 A）

按颁定口径「CJK≈1 token/字、非 CJK≈4 字符/token」，全文为粒度一次性计算：

```
token(文件) = |CJK 字符| + ⌈|其余字符| / 4⌉
CJK 类集合 = CJK 统一汉字 + CJK 扩展 A + 中文标点 + 全角字符（U+3400–4DBF／4E00–9FFF／3000–303F／FF00–FFEF）
```

**申报两处口径选择**（易被忽略从而造成差值）：①含 YAML 前置元数据区（它是每次加载都付的内容）；②含空白字符与 Markdown 语法字符（管道符、反引号、星号），它们按非 CJK 计。

**本口径的具名与取整（本轮新增，四项里的第 1、第 4 项）**：本口径＝附录 A 那份脚本，**具名为 `script-v1`**，其取整方式为 **`ceil`（上取整）**，实现＝附录 A `tokens()` 函数中的 `-(-(n) // 4)`（**以脚本本体为准，不以行号为准**——行号会随文档编辑漂移，脚本不会）。**引用本文读数时必须照抄这两项**——只写"按 CJK＋非CJK/4 算的"不算申报：那句话里没有取整方式，而取整方式在"非 CJK 不可被 4 整除"时会产生 1 token 之差（§1.2 脚注、§九-2 第 4 项）。

> 更正依据，**逐条写明不写满**：①**本席历史 blob 复算**（同脚本跑 `a147690`／`1c6b80b`／现版三个提交 × 七席，下表）；②**主理人独立跑同脚本**跑当前七席，与本文读数 **7/7 全等**（＝口径唯一性得到第二人确认）；③`agents/` tree SHA 在 `0f40abe`／`1c247df`／`ef3c66e` 三提交**同为 `273c8b5`**（＝排除"期间文件被改"这个替代解释）。**三条合起来只能指向"文件版本差"，没有第四条路。**

三点结论：

1. **只有一套口径（附录 A），没有第二套算法。** `1c6b80b` 一列与旧读数逐项吻合；operations 那 1 token 已查明为**取整方式差**（`ceil` vs `//`），与版本无关。**两种情况都不构成"第二种口径"**——前者是**旧对象**，后者是**同对象的两种取整实现**；而后者已被 §九-2 第 1、4 项（口径具名为 `script-v1`、取整显式为 `ceil`）锁死。
2. **增量＝v1.4.0 落包本身。** 且增量的分布本身就是一条交叉证据：`production-designer`／`screenwriter`／`content-strategist` 在 2d 窗口增量＝**0**，与「批 2d 八条只落在 lead／director／editor／operations 四件」这一硬约束清单**完全对应**——**没有任何一处多出来的条款**。
3. **两起归因错，方向正好相反，根因是同一个——一并入账。**
   - **第一起（本席）**：把**文件版本差**当成了算法差。当初那个解释不了的 **＋1,607**，真实身份＝**lead 在批 2d 里被落进去的那一部分**。我当时试算了 8 种变体去猜算法——**对象还没锁死就先猜原因。**
   - **第二起（主理人，本席照录其自纠）**：把**取整差**当成了版本差。operations 的 2,930 vs 2,931 不是"版本微调"，而是 `ceil` 与 `//` 之差；**带了 SHA 也定位不了**，因为两个实现取的是同一份字节，谁都没取错。
   - **共同根因**：**对象（哪一版、哪一份实现）还没锁死，就先去解释差异。** 一个猜算法、一个猜版本，方向相反、代价相同。**这正是 §九-2 存在的理由——它不叫"锁口径"，它叫"先锁对象与实现，再谈读数"。**

   **第 2 点（PD／screenwriter／strategist 在 2d 窗口增量＝0）不受本次修正影响**：那三席的差值是 ＋37／＋35／＋34 量级的**真实版本差**，不是 1 个 token 的取整差，交叉证据继续成立。

**处理方式**：本文读数＝**批 2d 后实测**，且＝**`script-v1` 这一份被指定的实现**（不存在"严/宽"两说，见 §1.3）。预算按它定；旧读数不再作为任何判据，仅在 §〇-8 中用作"红线如何被吃掉"的证据。**须一并写明**：另有一份取整方式为 `//` 的实现存在（判词席），它与本文在非 CJK 不可被 4 整除时差 1 token——**它是"未具名的另一份实现"，不是"另一套公式"**，处置办法是让它退出流通，即 §九-2 的四要素申报。

### 1.3 预算口径（前提已更正）

> **v1 初稿本节的标题是"为什么按严口径设计"，前提是"存在严/宽两套口径"。该前提已被 §1.2 推翻：不存在第二套公式，只有一份被指定的实现（`script-v1`）。**（补充一处精度：另有一份取整方式为 `//` 的实现在流通，它与 `script-v1` 在非 CJK 不可被 4 整除时差 1 token——**这是"另一份未具名实现"，不是"另一套公式"**，处置见 §九-2 第 1、4 项。）本节保留表格（它仍然说明"为什么预算不带水分"），但前提换成正确的那个。

| | 按旧读数（批 2d 前 `1c6b80b`）定预算 | **按批 2d 后实测定预算（本设计）** |
|---|---|---|
| 读数的身份 | **过期快照**——它漏掉了已经落盘的条款 | **当前唯一真值** |
| 用它定预算的后果 | 预算建立在"这些条款还不存在"的文件上；执行到一半发现真实体量差 1,607（lead）／196（director）／193（editor） | 无此风险 |
| 出错方向 | 交付后才发现超线（返工，且返工时条款已不可改） | 最多是多留了一点余量 |

**结论**：不是"取严口径把不确定性揽到自己这边"，而是**"取旧读数＝拿过期文件当判据，根本不是口径选择问题"**。本设计按批 2d 后实测定预算，**这个决定在初稿里就是这么做的，结果正确；但当时的理由（"两种口径取严的"）是错的，现予更正——结果对不能豁免理由错，理由错的下一次会把另一件事也判错。**

## 三、分层结构（回答 Q1）

### 3.1 五层模型

| 层 | 内容 | 载体 | 加载方式 | 体量约束 |
|---|---|---|---|---|
| **L1 常驻** | 身份／三栏／权限／输入白名单／铁律引用／必读指针 | **席位 MD**（`agents/*.md`） | 每次会话全量 | **≤2,350 token（红线 2,500，留 ≥150 余量）** |
| **L2 索引** | 本域的触发词与 references 索引（薄） | `skills/<域>/SKILL.md` | 触发命中时加载 | **≤200 行**（对标本仓 object-audit 主文件范式） |
| **L3 下沉本体** | 操作细则、模板、闸门表、流程步骤、v1.4.0 逐字条款 | `skills/<域>/references/*.md` | ①触发命中自动加载，或②MD 硬读指针显式读 | 单件建议 ≤1,500 token（平铺一层，不套娃） |
| **L4 打包/注册** | `plugin.json.skills` 声明、README 计数表 | 包根 | 安装/注册时 | — |

> L2 索引＝ `skills/<域>/SKILL.md`：负责触发词与 references 索引，**≤200 行**（对标本仓 `deliverables/skills/object-audit/SKILL.md` 的主文件 <200 行 + references 分件范式）。

### 3.2 为什么不能放进它（对比表）

| 候选 | 结论 | 理由 |
|---|---|---|

### 4.2 "对席位自包含的损害"有多大，怎么补

**诚实评估**：目前的七席 MD 是**自包含角色定义**（读一件即可开工）；下沉后变成"常驻定义＋按需加载"。损害是真实的，但可控：

| 损害 | 补大力途径 |
|---|---|
| 会话首次可能需要多读一个文件 | **⛓ 必读指针**：MD 中以 sleeping 行明确列出"执行 X 前必读 Y"。这是确定性通道，**不依赖语义匹配** |
| 触发词未命中 ⇒ 条款未加载 | 同上（双通道：`description` 触发 ＋ MD 硬读） |
| 条款被改时，MD 不知道 | 放进 references 后仍受 git 追踪与逐字 diff 门保护（§六-2 检查点 D） |

**对 hard policy 的处置原则**：

> **凡"不读就会违规/漏做"的内容（v1.4.0 全部条款、回传协议、铁律、默认模式），一律用「⛓ 必读」硬读指针；凡"读了更好"的内容（完整模板、完整手册、长清单），只靠 `description` 触发。**

```

### 6.0 阶段 0：护栏咬合验证（不是实机跑一轮——形态已由静态取证证明）

## 附录 A｜计数脚本（建议作为唯一口径 `script-v1` 入仓）

```python
# tools/count_agent_tokens.py · 口径 v1（CJK≈1 token/字、非 CJK≈4 字符/token）
import re, sys, glob
CJK = r'[\u3400-\u4dbf\u4e00-\u9fff\u3000-\u303f\uff00-\uffef]'
RED_LINE = 2500
def tokens(text: str) -> int:
    cjk = len(re.findall(CJK, text))
    return cjk + -(-(len(text) - cjk) // 4)      # ceil(非CJK/4)
if __name__ == '__main__':
    pat = sys.argv[1] if len(sys.argv) > 1 else 'deliverables/profiles/*/agents/*.md'
    bad = 0
    for p in sorted(glob.glob(pat, recursive=True)):
        t = tokens(open(p, encoding='utf-8').read())
        flag = 'OK ' if t <= RED_LINE else 'OVER'
        bad += t > RED_LINE
        print(f'{flag} {t:6d}  {p}')
    sys.exit(1 if bad else 0)
```

**为什么脚本要 `exit 1`**：它就是 C1/V1 门禁本身——红一次也不对。
