## 一、蒸馏人物：五层结构 + 四种实现路线
### 1. 目标产物的五层结构
nuwa-skill 把一个人要蒸馏的东西明确拆成五层，这是目前开源社区最系统的方法论：
| 层次 | 说明 | 识别标准 |
|---|---|---|
| 表达 DNA | 语气、节奏、用词偏好、句式、幽默风格、确定性表达方式 | 高频句式、专有词汇、引用习惯 |
| 心智模型 | 3–7 个跨领域复现的认知框架 | 同一框架在 2+ 不同领域出现；有自创术语命名；能预测其对新问题的立场 |
| 决策启发式 | 5–10 条 "if X, then Y" 判断规则 | 每条有具体案例支撑 |
| 反模式 | 明确反对什么、不做什么 | 价值观排序中的"不可逾越线" |
| 诚实边界 | 这个 Skill 做不到什么 | 蒸馏不了直觉、捕捉不了突变、公开表达≠真实想法 |
其中**心智模型是核心**——判断标准很硬：跨领域复现（同一框架在不同领域反复出现才算真实心智模型）、有命名术语（自己给思考模式起过名字的才算核心信念）、有预测力（能预测本人对新问题的立场）。naive 的角色扮演只是在复读名人语录，而高质量蒸馏是在用名人的认知框架帮你分析新问题——这是两者的本质区别。
### 2. 语料收集的六路并行调研
nuwa-skill 的做法是启动 6 个并行子 Agent，各负责一个信息维度，每个 Agent 的研究结果必须落盘到对应文件（"没有文件的研究等于没发生的研究"）：
| Agent | 搜索目标 | 关键提取物 |
|---|---|---|
| 1 著作 | 书籍、文章、论文、newsletter | 反复出现≥3 次的核心论点、自创术语、书单 |
| 2 长对话 | 播客、长视频、AMA、深度访谈 | 压力下的反应、即兴类比、立场变化、拒绝回答的问题 |
| 3 短表达 | Twitter/X、微博、短帖 | 高频句式、争议立场、幽默风格、公开辩论 |
| 4 外部视角 | 他人分析、书评、批评、传记 | 外部观察到的模式、批评与争议、同侪比较 |
| 5 决策记录 | 重大决策、转折点、争议行动 | 决策情境与逻辑、事后反思、说与做的一致性 |
| 6 时间线 | 从出道到现在 | 关键里程碑、思想转折点、**最近 12 个月**（防陈旧） |
语料来源有明确的优先级：本人著作/长访谈/实际决策记录（最高）> 社交媒体/他人评价（中等）> 二手转述（最低，需交叉验证）。**发现矛盾时不要平滑掉，要保留**——矛盾是深度的重要信号。
### 3. 四种实现技术路线（按成本从低到高）
| 路线 | 适用场景 | 局限 |
|---|---|---|
| **结构化系统提示词（SKILL.md）** | 最主流，开源社区默认方案 | 全局压缩可能丢失微妙的行为模式与隐式决策标准 |
| **Few-shot in-context** | 把 10–50 段代表作直接挂上下文 | 2025 年 arXiv 上的系统评估显示，SOTA LLM 通过 in-context learning 模仿个人隐式写作风格的能力仍然有限 |
| **RAG 外部知识库** | 语料量大（如巴菲特 1957–2023 全部股东信）时，把语录/访谈/剧本入向量库按语义检索注入 | 检索质量决定上限，无法保证整体一致性 |
| **LoRA 微调** | 需要深度风格迁移时 | StyleAdaptedLM 的做法：在基础模型上用带风格标注的语料训 LoRA adapter，再 merge 到指令模型；不透明、难审计、难修订 |
### 4. 验证闭环
这是大多数爱好者方案缺失的一环。writer-persona（一个 Claude Code 插件）给出了完整的"提取→回测→打分→自动修正→生成"反馈环：
- **信息隔离**：生成草稿的 Agent 看不到你真实的回答，只拿到对话上下文与 persona 定义——保证测的是真实预测力，不是抄写
- **8 轴语言评估**（基于计算文体学）：语义保真 25%、语气/情感 20%、正式度 15%、话语模式 15%、词汇选择 10%、功能词 5%、句法结构 5%、格式 5%，学术根基包括 Burrows' Delta（2002）、Writeprints（2008）、BERTScore
- **自相似度上限**：先测你自己消息两两之间的相似度（典型 70–80 分），以此作为 100 分基线，避免拿"完美"去苛求 AI
nuwa-skill 的四重验证则更偏认知层：**已知测试**（挑 3 个本人公开回答过的问题，用新 Skill 回答后与真实立场比对）、**边缘测试**（挑 1 个本人未公开讨论但相关的问题，期望输出"基于模型 X 和 Y，可能…但不确定"而非绝对确定）、**声音测试**（100 字内能认出是谁，而非通用 AI 腔或语录拼接）、**结构检查**（心智模型 3–7 个、每个有局限说明、≥2 对内在矛盾、一手来源占比 >50%）。官方 15 个 Skill 已通过独立双 Agent 盲测，全员 A 级（≥85 分）。

## 二、蒸馏思想体系：RIA-TV++ 七阶段管线
cangjie-skill 把"把一本书变成可调用的 Skill 集"的流程做成了确定性管线，核心目标是**结构化复用而非叙事压缩**——读完之后你知道"什么情境下用哪个方法"，而不是只留下一份摘要。
### 七个阶段
1. **整体理解（Adler 分析）**：用 Mortimer Adler 的阅读法做结构、诠释、批判、应用四层分析，产出 `BOOK_OVERVIEW.md`
2. **并行提取**：5 个专门化提取器（框架、原理、案例、反例、术语表）同时从源文本拉候选单元
3. **三重验证 + 晋级门**：按候选类型检查源充分性、可执行性、任务效用。关键规则：**一个只被完整解释过一次的流程或公式也可以入选，重复出现或作者原创性不是必要条件**；未通过的候选保持可审计状态
4. **RIA++ 能力构建**：验证通过的内容被结构化为 R/I/A1/A2/E/B 六维能力卡（R = Reading 原文、I = Interpretation 诠释、A1 = 亲身经验关联、A2 = 未来应用、E = Execution 执行步骤、B = Boundary 边界）
5. **Zettelkasten 链接**：依赖、对比、组合关系被编码进能力图与共享术语表
6. **压力测试**：为每个 Skill 设计测试提示，**包括诱饵问题和跨技能混淆测试**；失败则回炉重构
7. **确定性编译交付**：同一 Bundle 可编译为 `single`（路由式单体）或 `pack`（路由 + 若干独立 Skill 的紧凑包）
### 每张能力卡片的字段结构
这是"蒸馏非伪造"的关键——每张卡片强制携带：
- **原始出处**（哪本书哪一节，可回溯）
- **触发条件**（什么情境下该调用这张卡）
- **执行步骤**（可操作的流程/公式）
- **使用边界**（什么时候不该用、失效条件）
- **验证状态**（是否通过三重验证与压测）
YouMind 上的 book-to-skills-distiller 是同思路的商业化实现，同样强调八阶段管线 + "五条红线锁住蒸馏非伪造"。这个生态已经有大量落地案例：巴菲特股东信（1957–2023）蒸馏出 20 个投资推理 Skill、芒格《穷查理宝典》12 个决策判断 Skill、《影响力》12 个说服心理 Skill、《黄帝内经》22 个方法论 Skill，甚至安德鲁·吴的《AI for Everyone》视频课也蒸馏出 25 个 Skill。
### 示例：把《影响力》蒸馏成能力卡
```
Skill: 社会认同触发器
触发条件: 当需要提升某行为的采用率，且目标人群存在不确定性时
执行步骤:
  1. 找到目标人群的"类似他人"
  2. 展示这类人已经在做该行为
  3. 强调数量与具体性（"每月有 3000 名用户…"）
边界:
  - 当行为本身有争议时社会认同会反向作用
  - 伪造社会认同有伦理与法律风险
原始出处: 《影响力》第 4 章
验证状态: 已通过诱饵问题测试（"如果只有 3 个人做过还算社会认同吗？"）
```

## 选型建议与常见失败
**选型逻辑**可以这样决策：语料 <10 个可用来源时，先在 Phase 0 就预警并主动扩充诚实边界——nuwa-skill 的原则是"宁可生成一个诚实标注局限的 60 分 Skill，也不要一个看似完美的 90 分造假 Skill"；只有代表作与访谈时，走五层结构 + 6 路调研的轻量路线；有完整书籍/课程体系时，走 RIA-TV++ 的能力卡路线；需要多视角协作决策时，用"智者议会"式的多 persona 辩论格式（巴菲特×芒格×稻盛和夫×纳瓦尔等 7 人同时辩论，由主持人总结分歧点）。
几个已知的系统性失败与对策：
- **人格漂移**：长对话中 persona 逐渐"溶解"回通用 AI 腔。SPASM 框架提出 stability-oriented 的历史构造机制（ECP）来抑制 drift，在多 Agent 对话仿真中验证有效
- **幻觉与过度泛化**：把角色共性当成本人特性，或编造本人从未表达过的立场。Person Distillation 论文专门设计了**边界探测协议**：好的表征应在证据不足时主动弃权、限定或承认不确定，评价时要区分"有支持的答案、有限定的答案、无支持但貌似合理的答案、明确的幻觉"四档
- **语录复读 vs 框架思考**：这是"角色扮演"与"人格蒸馏"的分水岭。检验标准很简单——问一个本人从未公开讨论过的新问题，看输出是引用拼接还是用其心智模型推理
- **版权与伦理**：Person Distillation 把它列为未来方向的核心议题，包括同意机制（什么信息可以蒸馏、哪些侧面可以表征、能保留多久、能行使什么权限）、可验证遗忘、以及"高保真不等于无限权限"的原则。仓颉生态的配套 darwin-skill 解决的是 Skill 的自动演化，nuwa/distill 的 skill 则只能做"截止调研时间的快照"，无法捕捉本人的思想突变
一句话总结当前成熟度：**人格蒸馏在开源社区已形成"多 Agent 调研 + 五层提取 + 三重验证"的事实标准，思想体系蒸馏已形成"RIA 能力卡 + 触发条件 + 压力测试"的事实标准，但两者都还处于"有方法论、无行业标准"的阶段**——Person Distillation 论文提供的六侧面/六方法族/六保真度框架是目前最接近学术共识的概念地基，工程侧则以 nuwa-skill 与 cangjie-skill 为最完整的可复用实现。

目前尚未形成完全统一的标准范式，但已经分化出两条相对成熟的技术路线：针对"人"的**人格蒸馏**以 nuwa-skill、Person Distillation 理论框架为代表，针对"思想体系"的**方法论蒸馏**以 cangjie-skill（RIA-TV++ 管线）为代表。两者在语料构成、提取策略、表示形式、验证手段上有系统性差异，可以对照选型。

| 1 著作 | 书籍、文章、论文、newsletter | 反复出现≥3 次的核心论点、自创术语、书单 |

### 3. 四种实现技术路线（按成本从低到高）
| 路线 | 适用场景 | 局限 |
|---|---|---|
| **结构化系统提示词（SKILL.md）** | 最主流，开源社区默认方案 | 全局压缩可能丢失微妙的行为模式与隐式决策标准 |
| **Few-shot in-context** | 把 10–50 段代表作直接挂上下文 | 2025 年 arXiv 上的系统评估显示，SOTA LLM 通过 in-context learning 模仿个人隐式写作风格的能力仍然有限 |
| **RAG 外部知识库** | 语料量大（如巴菲特 1957–2023 全部股东信）时，把语录/访谈/剧本入向量库按语义检索注入 | 检索质量决定上限，无法保证整体一致性 |
| **LoRA 微调** | 需要深度风格迁移时 | StyleAdaptedLM 的做法：在基础模型上用带风格标注的语料训 LoRA adapter，再 merge 到指令模型；不透明、难审计、难修订 |
### 4. 验证闭环
这是大多数爱好者方案缺失的一环。writer-persona（一个 Claude Code 插件）给出了完整的"提取→回测→打分→自动修正→生成"反馈环：
- **信息隔离**：生成草稿的 Agent 看不到你真实的回答，只拿到对话上下文与 persona 定义——保证测的是真实预测力，不是抄写
- **8 轴语言评估**（基于计算文体学）：语义保真 25%、语气/情感 20%、正式度 15%、话语模式 15%、词汇选择 10%、功能词 5%、句法结构 5%、格式 5%，学术根基包括 Burrows' Delta（2002）、Writeprints（2008）、BERTScore
- **自相似度上限**：先测你自己消息两两之间的相似度（典型 70–80 分），以此作为 100 分基线，避免拿"完美"去苛求 AI
nuwa-skill 的四重验证则更偏认知层：**已知测试**（挑 3 个本人公开回答过的问题，用新 Skill 回答后与真实立场比对）、**边缘测试**（挑 1 个本人未公开讨论但相关的问题，期望输出"基于模型 X 和 Y，可能…但不确定"而非绝对确定）、**声音测试**（100 字内能认出是谁，而非通用 AI 腔或语录拼接）、**结构检查**（心智模型 3–7 个、每个有局限说明、≥2 对内在矛盾、一手来源占比 >50%）。官方 15 个 Skill 已通过独立双 Agent 盲测，全员 A 级（≥85 分）。

## 二、蒸馏思想体系：RIA-TV++ 七阶段管线
cangjie-skill 把"把一本书变成可调用的 Skill 集"的流程做成了确定性管线，核心目标是**结构化复用而非叙事压缩**——读完之后你知道"什么情境下用哪个方法"，而不是只留下一份摘要。
### 七个阶段
1. **整体理解（Adler 分析）**：用 Mortimer Adler 的阅读法做结构、诠释、批判、应用四层分析，产出 `BOOK_OVERVIEW.md`
2. **并行提取**：5 个专门化提取器（框架、原理、案例、反例、术语表）同时从源文本拉候选单元
3. **三重验证 + 晋级门**：按候选类型检查源充分性、可执行性、任务效用。关键规则：**一个只被完整解释过一次的流程或公式也可以入选，重复出现或作者原创性不是必要条件**；未通过的候选保持可审计状态
4. **RIA++ 能力构建**：验证通过的内容被结构化为 R/I/A1/A2/E/B 六维能力卡（R = Reading 原文、I = Interpretation 诠释、A1 = 亲身经验关联、A2 = 未来应用、E = Execution 执行步骤、B = Boundary 边界）
5. **Zettelkasten 链接**：依赖、对比、组合关系被编码进能力图与共享术语表
6. **压力测试**：为每个 Skill 设计测试提示，**包括诱饵问题和跨技能混淆测试**；失败则回炉重构
7. **确定性编译交付**：同一 Bundle 可编译为 `single`（路由式单体）或 `pack`（路由 + 若干独立 Skill 的紧凑包）
### 每张能力卡片的字段结构
这是"蒸馏非伪造"的关键——每张卡片强制携带：
- **原始出处**（哪本书哪一节，可回溯）
- **触发条件**（什么情境下该调用这张卡）
- **执行步骤**（可操作的流程/公式）
- **使用边界**（什么时候不该用、失效条件）
- **验证状态**（是否通过三重验证与压测）
YouMind 上的 book-to-skills-distiller 是同思路的商业化实现，同样强调八阶段管线 + "五条红线锁住蒸馏非伪造"。这个生态已经有大量落地案例：巴菲特股东信（1957–2023）蒸馏出 20 个投资推理 Skill、芒格《穷查理宝典》12 个决策判断 Skill、《影响力》12 个说服心理 Skill、《黄帝内经》22 个方法论 Skill，甚至安德鲁·吴的《AI for Everyone》视频课也蒸馏出 25 个 Skill。
### 示例：把《影响力》蒸馏成能力卡
```

触发条件: 当需要提升某行为的采用率，且目标人群存在不确定性时

  1. 找到目标人群的"类似他人"
  2. 展示这类人已经在做该行为
  3. 强调数量与具体性（"每月有 3000 名用户…"）

  - 伪造社会认同有伦理与法律风险
```

## 选型建议与常见失败
**选型逻辑**可以这样决策：语料 <10 个可用来源时，先在 Phase 0 就预警并主动扩充诚实边界——nuwa-skill 的原则是"宁可生成一个诚实标注局限的 60 分 Skill，也不要一个看似完美的 90 分造假 Skill"；只有代表作与访谈时，走五层结构 + 6 路调研的轻量路线；有完整书籍/课程体系时，走 RIA-TV++ 的能力卡路线；需要多视角协作决策时，用"智者议会"式的多 persona 辩论格式（巴菲特×芒格×稻盛和夫×纳瓦尔等 7 人同时辩论，由主持人总结分歧点）。
几个已知的系统性失败与对策：
- **人格漂移**：长对话中 persona 逐渐"溶解"回通用 AI 腔。SPASM 框架提出 stability-oriented 的历史构造机制（ECP）来抑制 drift，在多 Agent 对话仿真中验证有效
- **幻觉与过度泛化**：把角色共性当成本人特性，或编造本人从未表达过的立场。Person Distillation 论文专门设计了**边界探测协议**：好的表征应在证据不足时主动弃权、限定或承认不确定，评价时要区分"有支持的答案、有限定的答案、无支持但貌似合理的答案、明确的幻觉"四档
- **语录复读 vs 框架思考**：这是"角色扮演"与"人格蒸馏"的分水岭。检验标准很简单——问一个本人从未公开讨论过的新问题，看输出是引用拼接还是用其心智模型推理
- **版权与伦理**：Person Distillation 把它列为未来方向的核心议题，包括同意机制（什么信息可以蒸馏、哪些侧面可以表征、能保留多久、能行使什么权限）、可验证遗忘、以及"高保真不等于无限权限"的原则。仓颉生态的配套 darwin-skill 解决的是 Skill 的自动演化，nuwa/distill 的 skill 则只能做"截止调研时间的快照"，无法捕捉本人的思想突变
一句话总结当前成熟度：**人格蒸馏在开源社区已形成"多 Agent 调研 + 五层提取 + 三重验证"的事实标准，思想体系蒸馏已形成"RIA 能力卡 + 触发条件 + 压力测试"的事实标准，但两者都还处于"有方法论、无行业标准"的阶段**——Person Distillation 论文提供的六侧面/六方法族/六保真度框架是目前最接近学术共识的概念地基，工程侧则以 nuwa-skill 与 cangjie-skill 为最完整的可复用实现。

那么女娲和仓颉skill 是哪种？

**女娲对应"人物蒸馏"路线，仓颉对应"思想体系蒸馏"路线，两者是同一生态中分工互补、刻意不重叠的项目**——女娲蒸馏"人怎么想、怎么说"，仓颉蒸馏"书里的方法论怎么用"。生态里还有第三个成员 darwin-skill（进化 Skill），负责把前两者产出的技能持续迭代。
## 两者对照
| 维度 | 女娲 nuwa-skill | 仓颉 cangjie-skill |
|---|---|---|
| **路线归属** | 人物蒸馏 | 思想体系/书籍蒸馏 |
| **蒸馏对象** | 人（导演、作家、企业家等） | 书、长视频、播客、课程、访谈 |
| **核心产出** | 思维分身：可对话、可切换视角的 persona | 能力卡：带触发条件、可执行步骤的工具集 |
| **提取结构** | 五层——表达 DNA、心智模型、决策启发式、反模式、诚实边界 | RIA++ 六段——原文、诠释、书中案例、触发场景、执行步骤、边界 |
| **语料策略** | 6 Agent 并行调研（著作/长对话/碎片表达/外部视角/决策记录/时间线），从 40+ 一手来源采集 | 5 Agent 并行提取（框架/原则/案例/反例/术语），先 Adler 整书理解 |
| **验证机制** | 三重验证：跨域复现、生成力（能预测对新问题的态度）、排他性；已知/边缘/风格三类测试 | 三重验证：跨域佐证、预测力、独特性（通过率仅 25–50%）；含"诱饵题"的压力测试 |

## 为什么这样切分
仓颉作者自己解释了切分逻辑：受女娲启发后想到"我们可以蒸馏一个人，为什么不蒸馏他花了大量时间写的书"——书是一个人反复推敲、实战沉淀的深度思考，蒸馏书拿到的是可落地验证的方法论，这与蒸馏人的思维方式是两个维度。所以两者**不是竞争关系，是刻意分工**：女娲产出的 Skill 是"用芒格的视角帮我分析这个投资决策"，仓颉产出的 Skill 是"遇到这个问题自动调用《穷查理宝典》里的逆向思维框架并给出执行步骤"。

做自动迭代，这等于把“技能当代码、配测试套件”的工程范式引入 LLM 工件——这是两个项目里最扎实的部分。**5. 验证过滤器有判别力。** 仓颉声称三重验证通过率仅 25–50%——一个会拒绝一半候选的过滤器比橡皮图章式验证有信息量得多；女娲“宁要 60 分诚实、不要 90 分造假”的原则在认识论上也是对的。**6. 诚实边界/弃权要求与 2026 年 Person Distillation 论文同向。** 论文强调忠实表征应主动弃权和限定，女娲把“无法预测全新问题”写进 Skill 本体，方向正确。## 二、扎实性崩塌的地方（结构性缺陷）**1. 验证是自指的——这是最致命的一条。** “双 Agent 盲测全员 A 级（≥85 分）”听起来像临床试验，实际是**同一个模型家族的 LLM 在评价 LLM 输出**。LLM-as-judge 的文献已经反复证明这类评估存在自我偏好偏差（偏爱同源输出）、长度偏差、立场偏差。评“像不像李安”这件事，评判者自己对李安的理解就不完整——用一个有噪声的仪器去校准另一个有噪声的仪器，得到的是噪声的共鸣，不是保真度测量。真正的独立性要求：不同模型家族、不同操作者、预注册评分标准。这些都没有。**2. 已知问题回测大概率被污染。** “挑本人公开回答过的问题，用 Skill 回答后与真实立场比对”——问题在于，李安的真实回答几乎必然在基座模型的预训练语料里。所以通过测试可能测的是**模型的回忆能力**，而非蒸馏产物的重建能力。这是测度效度的根本缺陷：你想测“蒸馏技能的增量”，实际测的是“基座本来就记得多少”。严谨设计需要**时间切分**：只用 2020 年前的语料造 Skill，用 2020 年后本人已揭示的真实回答做测试集（预测式验证）——没有任何证据表明他们做了这个。**3. 评分权重是无出处的拍脑袋数字。** “语义保真 25%、语气 20%、正式度 15%……”——这些权重没有任何实证校准，是把“判断”穿上了“测量”的外衣。真正的科学做法是先做因子分析或与人类评分拟合回归得出权重。**4. 借来的学术名字是装饰而非实现。** writer-persona 宣称学术根基包括 Burrows' Delta（2002）——但 Burrows' Delta 是一个**具体计算方法**（最高频功能词频率、z 标准化、距离度量），而他们的实现是让 LLM“给功能词打 5% 的分”。这不是 Delta，是 Delta 的名字。同理，仓颉的理论地基 RIA 出自《这样读书就够了》（成人学习理论的应用读物，非实证验证的教学法）、Adler 阅读法出自 1940 年的《如何阅读一本书》（从未被作为理解协议实证验证过）、Zettelkasten 是卢曼的个人实践智慧。这些都是**值得尊重的实践框架，但把它们称为“科学”是过度声明**。**5. “确定性管线”名不副实。** 仓颉宣称管线确定——但提取阶段是 LLM 调用，本质上随机。确定性只存在于最后的编译打包环节。“确定性蒸馏”是个营销性表述。**6. 样本量是轶事级。** 15 个 Skill 全员 A 级，n=15，无统计推断、无消融实验、无基线对照（比如：naive 提示词 + 同样语料 few-shot 能拿多少分？如果 naive 方案也能拿 80 分，整个五层结构的价值就存疑——而这个关键消融从未做过）。**7. 无第三方复现。** 所有验证数据都由项目作者自己发布。“15 个 Skill 通过独立双 Agent 盲测”的“独立”是作者自己的 Agent。科学声明的底线是独立复现，这里为零。## 三、和真正的科学标准差多远学术界的 persona 建模研究（Character-LLM、RoleLLM、PersonaLLM、CharacterGLM 这一系）至少做到：训练/测试严格切分、自动指标 + 人类评估双轨、与基线模型对照报告。Person Distillation（2026）论文给出的评估协议也明确要求区分“有支持的答案 / 有限定的答案 / 无支持但貌似合理的答案 / 幻觉”四档，并专门设计边界探测。**女娲和仓颉实现了这套学术直觉的“产品设计层”（结构、溯源、弃权、测试），但完全跳过了“测量科学层”（真值、对照、人类评估、防污染）。**打个比方：它们像是一套写在笔记本上的实验 SOP——步骤设计得像模像样，但没有对照组、没有盲法、仪器没校准、实验员既是受试者又是评分者。## 四、如果你想自己评估它们（可操作的检验清单）1. **污染对照**：问 Skill 一个本人公开回答过但足够冷门的问题，再问一个同等冷门、本人也回答过、但你确认基座模型裸奔（不带 Skill）也答得出来的问题——如果两者得分接近，说明 Skill 没有增量2. **排他性对照**：让同一个 Skill 框架蒸馏另一个人，然后盲测输出——如果分不出“李安 Skill”和“张艺谋 Skill”的输出，五层结构就是装饰3. **消融测试**：naive 提示词 + 10 段代表作 few-shot vs. 完整 Skill，盲评打分——这是最关键的缺失实验4. **时间切分验证**：只用旧语料造 Skill，测新近公开的回答——唯一能同时解决污染和预测力的设计5. **真跑一次文体学**：用 Python 实际计算 skill 输出与本人语料的功能词分布、字符 n-gram 距离，替代 LLM 打分## 一句话总结**这两个项目是“民间最佳实践 + 借用学术修辞”的产物：作为工程范式，它们比社区平均水平高一个身位（结构化、可测试、可溯源、有诚实边界）；作为科学方法论，它们在验证自指、真值污染、无对照无消融、无人类评估这四点上全部不达标。** 如果你的用途是“给自己造一个好用的思维分身/工具库”，它们值得用；如果你的用途是“做出可信的保真度声明”（比如产品宣传、学术引用），现有验证体系撑不起来——需要按上面第四节的清单补实验。

这两个技能合并成一个统一的蒸馏技能合适吗？

**取决于你说的“合并”是哪一种**——这个词至少有三种含义，其中一种是错的，两种是对的。融合成“一个技能、一套 schema”不可行；统一成“一个蒸馏平台 + 两个专门提取头”是正确方向；按对象做“bundle 组合”是最务实的个人用法。
## 三种“合并”的对照
| 方式 | 做法 | 适合谁 | 主要风险 |
|---|---|---|---|
| **融合**（真合并） | 一套提取 schema、一个系统提示词同时覆盖人和书 | —— | 本体冲突，两边都稀释 |
| **编排**（元技能） | 统一入口 + 输入分类器，分叉到两条提取管线，**共享**验证/测试/溯源底座 | 想建蒸馏平台的人 | 工程成本、维护负担 |
| **组合**（bundle） | 保持两个独立 skill，按需共同调用 | 个人使用者 | 几乎没有，只是手动 |
## 为什么融合是错的：两者的 schema 在根上不可通约
这不是工程洁癖，是**蒸馏对象的本体论差异**：人是一个持续生成判断的主体，书是一个已结晶的工件集合。蒸馏人要保真一个“生成函数”，蒸馏书要保真一批“静态程序”。具体冲突至少有四处：
**1. 最深的一处：核心原则直接互相矛盾。** 女娲的铁律是“发现矛盾不要平滑掉，矛盾是深度的重要信号”——因为忠实表征一个人就必须保留其内在张力；仓颉的铁律是“边界必须明确、验证不过不晋级”——因为工具必须可执行、歧义必须消解。合并后的系统提示词里同时写着“保留矛盾”和“消解歧义”，执行时必然打架。你无法用一套价值观同时当好传记作者和教材编辑。
**2. 输出物的生命周期相反。** persona 是要被“进入”的——触发后持续在场、贯穿整段对话，失效模式是人格漂移；能力卡是要被“调用”的——触发条件命中即激活、用完即退场，失效模式是误触发。一个 skill 要同时支持“持续在场”和“即用即走”两种存在方式，路由和保持机制都会变形。
**3. 验证的语义不同。** 女娲问的是“像不像这个人”（主体保真度），仓颉问的是“这个方法有没有用、出处对不对”（工件效用 + 可回溯性）。前者需要排他性测试（能区分李安和张艺谋），后者需要诱饵测试（边界外会不会乱套）——评测协议根本是两套。
**4. schema 字段互为噪声。** 表达 DNA、确定性措辞、时间线演化对一本书没有意义；触发条件、执行步骤对一个人格没有意义。合并 schema 的结果是两边都背着对方的无用字段，提示词膨胀且路由准确率下降——这正是 skill 生态里“技能要聚焦”的常识所反对的。
顺带一提，两个项目的作者**刻意划了这条边界**（仓颉文档明确写“作者人设角色扮演是 nuwa-skill 的事”），这不是历史偶然，是他们对这个本体差异的自觉确认。
## 为什么平台级统一是对的：70% 的底座其实是同构的
剥离掉提取 schema 之后，两条管线的骨架惊人地一致：**语料纪律（一手来源优先、新鲜度检查）→ 并行多 Agent 调研 → 验证门过滤 → 结构化落盘（强制溯源）→ 测试件生成 → 诚实边界声明**。这些完全可以抽成共享内核。
而且统一平台能解决一个当前两项目都搞不定的现实问题：**混合对象**。蒸馏尼采算蒸馏“人”还是蒸馏“书”？他的全部著作就是他的人格载体，现在的二分法在这里断裂。理想的产物是“尼采 bundle"：persona 层（语气、立场、自我矛盾、风格）+ 能力卡层（永恒轮回、谱系学方法作为带边界的工具）。只有元技能架构能产出这种东西——这是“编排式统一”最强的一个理由。
**更关键的是，统一评估基建是补上一轮批评短板的最佳杠杆。** 你上一轮问“方法论科学吗”，结论是两边都缺时间切分、缺消融对照、缺污染检测。如果要做融合，这些恰恰应该建在共享层：一套统一评估 harness（时间切分协议、naive 基线对照、污染探测题库、跨对象排他性测试）同时服务两条管线，比各自建一套弱的好得多。**合并的正确投资位置是测量层，不是提取层。**
## 如果要建，架构草图
```
统一蒸馏元技能
├─ Phase 0: 输入分类器
│    人 / 书 / 课程 / 混合对象（如"尼采"→ 混合模式）
├─ 共享语料层
│    来源优先级、一手占比检查、新鲜度、落盘纪律
├─ 分叉提取层
│    人 → 6 头调研（著作/长谈/碎片/外部/决策/时间线）→ 五层结构
│    书 → 5 头提取（框架/原理/案例/反例/术语）→ RIA++ 卡片
├─ 共享验证内核
│    三重验证门 + 溯源强制 + 诚实边界 schema
│    【新增】时间切分验证 / naive 基线对照 / 排他性测试
├─ 统一测试层
│    test-prompts.json（darwin 兼容）
│    persona 用漂移测试，卡片用诱饵测试，分类器分派
└─ 编译层
     single / pack / bundle（persona + cards 打包）
```
## 什么时候连编排都不值得
如果你只是**使用者**：两个 skill 并存，按对象手动选用，同一人物叠加调用（女娲分身 + 仓颉卡片库）就能拿到 90% 的收益，元技能的工程成本不划算。如果你是**评估者**：别合并，直接在两边之上建独立评估层最有价值。只有当你是**建造者**（想做一个面向他人或长期维护的蒸馏工具），元技能架构才值得投入——而且投入重点应该放在共享验证内核和评估 harness 上，而不是急着统一提取 schema。
一句话：**“合并提取逻辑”是在错误的层做统一，会把两个各自成立的范式稀释成一个两边不靠的折中物；“统一基建、分叉本体”才符合这两类蒸馏对象的真实差异**——就像你不会把 C 编译器和 Python 编译器的语法规则合并，但会都跑在同一个 LLVM 后端上。
