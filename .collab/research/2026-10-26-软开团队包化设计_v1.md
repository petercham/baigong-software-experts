## 🗣️ 外部顾问讨论会（主持人兼任）

- **触发即兼任**：收到讨论会类指令（组织／主持／收口外部顾问讨论会，或编制议题包、汇总件、决议件）→ 本席**临时兼任主持人**，开工第一件事加载技能 `external-advisor-collab`；主持人职权闭集、轮次程序、纪律与产物体例以该技能 `references/` 为唯一真源，本文件不复述。

### P-3 token 线适用性终判

**终判＝「收编批不套线、只登记基线；新内容单独设预算；整席是否套线候皮总拍」**。理由：

1. **收编≠治理**（派工件已定调）：收编批判据＝逐字照录（diff 市场版零差异），若同批套 2500 线，lead 3,576 直接红——要么违判据砍字、要么带红上线，两头都不是收编该干的事。
2. **基线先入账**：§一.1 五席读数四要素齐（script-v1/ceil/实测人/时刻），README 计数表照登（aigc 体例），lead 超线事实**显式登记为「红线待治理」**——藏账比超线更坏。
3. **Q6 决议条款的射程**：决议稿 Q6 原文「2500 分轨＝席 MD（身份层）严守 2500」成文语境＝AIGC 七席治理（批 3b 全链），是否外溢到软开席，决议文本未明示——**不替皮总拍**，候拍 Q4 给两分支后果。
4. **新内容预算**：P-2 小节 ≤200 token（实测 198），无论 Q4 拍哪个分支都成立——增量成本先锁死，存量债另批治。

### P-4 注册与切换流程

**生效链**（实测盘上三文件域）：`仓内真源 → 部署面 marketplaces/my-experts/plugins/software-company/ →（宿主加载）→ 运行缓存 cache/my-experts/ → 会话`。

**操作步骤级流程**（V6/R4 先例做法）：

1. 仓内真源改毕、门禁过、commit；
2. 复制仓内 → 部署面（整目录覆盖；行尾差异按 aigc 先例登记不拦）；
3. 重跑 `register_expert.py <部署面目录>`——**幂等**（源码实测：已注册条目走「Updated existing registration」分支，marketplace.json 更新 name/source/description 三字段）；
4. 新开会话召唤软开团队 → 宿主按 marketplace.json source 重新复制运行缓存 → 加载仓内版；
5. 冒烟（V6 型）：新会话召唤 lead，核 frontmatter name、新小节在位、讨论会指令触发技能加载。

**切换语义（据 §一.4 更正后）**：当前会话已加载 my-experts 轨＝收编后轨不变、内容归正，**无断档、无「从市场包切走」动作**。市场缓存 `cache/experts/software-company/` 不碰不删（宿主资产；只要不再从专家中心选「市场版 software-company」即不加载）。

**回滚路径**：仓内 git revert → 重跑步骤 2–3（部署面还原）→ 新会话即回旧版。部署面是纯副本，回滚成本＝一次复制。

**风险登记**：①运行缓存由宿主自管，若宿主按版本号 1.1.0 判定「已缓存免刷新」，可能出现改部署面不刷新的漂移（aigc 漂移实证 §1.5 同型）——缓解＝收编批把版本号升 `1.1.1`（候拍 Q5 附带项），版本号变了宿主必然重拷；②会话中途不重载（生效需新会话），收口话术须写明。
