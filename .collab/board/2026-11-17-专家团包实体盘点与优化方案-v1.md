## 〇、一句话结论

**这个包的交付面是健康的，但它有三个"面"在时间轴上断成了三级台阶，而且没有任何机检在看着台阶。**

## 二、六个硬伤（按后果严重度排序）

### E1｜部署面滞后十天，运行态执行的是旧规则

**实证**（逐项对拍部署面 vs 真源）：

| 缺什么 | 后果 |
|---|---|
| `skills/sop/scripts/semantic-governance.py`（1,699 行） | 语义治理三子命令闸不存在——而 `config/semantic-closed-sets.json` 也不在，整套能力零落地 |
| `skills/claim-commitment-governance/`（7 件） | 主张—来源—验证—外发治理技能不可加载 |
| `tools/`（devkit-tools 18 件） | 部署面根本没有 tools 目录，TOOLHOME 批的产物一次都没装配过 |
| 五张席位卡的 11-09 修订（3–7 行差异/卡） | **主理人卡缺「ADR 文书＝主理人自写」行**，缺该治理技能入口；仍在按 11-05 规则把 ADR 派给架构席 |

**现场证据**：本次会话系统注入的主理人卡路径就是部署面，其路由表写着「系统设计、ADR、开发票 → 架构席」。这与 11-08 皮总裁定（ADR 统一主理人写，`67a3462`）**方向相反**。也就是说：这十天里所有关于 ADR 工序的讨论、裁定、成文，对运行态**零影响**。

**根因**：四段部署链的③人类闸未过（TK-GWP-DEPLOY 挂账），之后没有任何"部署面滞后"的监测。不是某人忘了，是**没有东西会喊**。

### E2｜注册面缺 sop，至少 13 个版本没修

`.codebuddy-plugin/plugin.json` 的 `skills[]` 现为 4 项（software-orchestration、external-advisor-collab、deep-research、claim-commitment-governance），**不含 `./skills/sop`**。

追史：`0.1.17`（B2 交付面主体搬家，`91eb86f`）起就是这个形态，一直到 `0.1.30` 未变。搬家那次列了三个技能，sop 被漏掉，此后 13 个版本无人发现。

**后果**：`sop` 是技法域——票模板、决策包模板、回流件模板、两基线副本、17 个 TCB 脚本的调用细则全在它下面。目录在盘上（部署面 24 件），但**没有技能入口**。席位卡只能靠硬路径 `skills/sop/scripts/xxx.py` 直调，模板类资产则完全没有入口。

这不是"少注册一个技能"的小事：它让"票体四字段自包含"这套最常用的技法失去了按需加载通道。

## 四、优化方案（按投入产出排序）

### O1｜三面一致性机检（最高 ROI，建议做成一支脚本）

**做什么**：一支 `check-bundle-parity.py`，四个输入面对拍，输出缺项/多项/版本不符。

**判据（每条都可机械判）**：
1. 真源 `skills/*/` 目录集 ⊇ `plugin.json.skills[]` 引用集；
2. `plugin.json.skills[]` ⊆ 装配面 `skills/` 目录集（防声明了但没装）；
3. 装配面 `skills/` 目录集 = 部署面 `skills/` 目录集（防半刷新）；
4. `bundle.lock.components[].target` ⊆ 装配面目录集（防组件漏装）；
5. `ASSEMBLY.manifest.json.assembled_at` 与真源 HEAD 提交时间的差 ≤ 阈值（如 3 天，超即 WATCH）；
6. 根 `plugin.json` 与 `.codebuddy-plugin/plugin.json` 的 `version`/`agents` 逐项相等，`skills` 差异必须落在显式白名单里。

**收益**：一次写，永久抓 E1/E2/E3。**成本**：约 200 行，挂 `run-gates` 起步 advisory。
**分级**：属工具面新增（不是改真源口径），可自决起草；挂不挂门禁需一次判断。

---

### O2｜补装配与部署欠账（需部署票，四段链走完）

**做什么**：重装配（4 组件齐全）→ 验 devkit-tools 与 claim 域挂上 → 挂预览 → 皮总人工闸 → 部署。

**重点验证三项**：
1. `semantic-governance.py` 在位且 `selfcheck` exit 0；
2. 主理人卡的「ADR 主理人自写」行生效；
3. `skills/sop` 被平台按名加载（这条同时验证 O3）。

**收益**：把十天成果真正交到用户手里。**风险**：部署面刷新会改变行为（ADR 不再派架构席、钩子开始拦语义治理面），需要一次试跑。
**分级**：属部署动作，硬门要求独立部署票＋人类明示批准，本件不代开。

**分级**：随部署票走，不单独立项。

### O4｜plugin.json 单一真源化

两个方案，选一个：
- **甲（保守）**：根版由点版机械生成（脚本读点版，产出市场包装字段），加 O1 判据 6 兜底。代价：生成脚本要维护。
- **乙（激进）**：合并为一个文件，确认平台对两处 schema 的读取优先级后删冗余。代价：要先做一次平台读取行为实测。

**建议甲**：不动平台契约，只消除人肉同步。
**分级**：改包结构，需票。

## 五、不建议做的事（防过度修正）

1. **不要因为过程件多就砍 `.collab`**：审计、判词、回执是这套体系的质量凭证，删了等于把"可审计"这个卖点删了。要的是**迁出视线**，不是销毁。
2. **不要把 `tests/` 从包里删掉**：它排除了装配面，但真源仓留着才有回归可能。缺的是跑，不是留。
3. **不要为了"统一"动手改根 plugin.json 的 schema**：它是市场包装格式，改坏了上架就出问题。O4 甲案（生成）比乙案（合并）稳。
4. **不要给三面一致性再加人工签核**：O1 是脚本对拍，加了人签就退回老路。

## 六、与上一件的合流

上一件说：流程慢在"步数"，根因是"没有档位 + 机械兜底缺失"。

本件给出了那个"机械兜底"最该落的第一块砖：**三面对拍**。

理由是同构的——上一件的数据说 20% 治理笔在返工、红项一半是钉值与路径；本件的 E1/E2/E3 说明**连"包和部署面是否一致"这种最基本的事实，都靠人记**。sop 漏注册 13 个版本没人发现，部署面落后 10 天没人喊——这不是能力问题，是**没有一支脚本在算这件事**。

所以两件的结论可以合成一句：**这个团队最缺的不是更多纪律条文，是把已经写下来的事实交给机器去核对。**

## 七、边界与不确定

1. **"部署面落后十天"是事实，"运行态按旧规则执行"是推断**：我只能证明部署面文件是 11-06 版、主理人卡缺 ADR 行；平台是否在别处（如缓存层）另有新版，我未验证。
2. **sop 未注册的后果程度是推断**：文件在盘上，席位卡用硬路径调用不受影响；受影响的是"按技能名加载"这一通道。平台对未注册目录的处理方式我未实测。
3. **hooks 的 cwd 约定未验证**（S1）：我没有运行平台钩子的能力，只能指出路径形态是相对的。
4. **体量与 token 读数为实测**（本机现跑），但 token 口径为 README 自述的 script-v1（CJK≈1、非 CJK≈4 字符），与真实计费口径可能有差。
5. **本件零改动**：没有改任何文件、没有派席、没有触发装配或部署。
