## 二、白话正文（决策者面向·人话纪律在册）

### 问题出在哪

现在仓里所有的闸——提交前拦截、写侧拦截、记账对账——全都跑在同一台机器、同一个权限层里。主理人手里有一个环境变量开关（ALLOW_GATE_DOWN=1），一开就能把提交闸整体降级放行；而且探针实证：连这个开关都不用，改用「跳过钩子」提交，本地闸同样零拦截（见 §五附录·乙段探针 P1／P2）。这就是立案时那句话的实底：**被检者不能给自己装一把自己拆不掉的锁**。现在的体系能做到「事后赖不掉」（账本＋哈希链＋证据配对），做不到「事前拦得住」。

### 三个办法各是什么（大白话）

**办法一·把一道闸搬到主理人够不着的地方（远程把关＋分支保护）。** 在 GitHub 上装一套自动检查：任何要进主干的提交，都由 GitHub 的独立机器把本地那套内容闸原样复跑一遍，不过关就进不去。再配上分支保护：主干不许直接推、不许改写历史、连管理员也不能例外。关键在「钥匙归谁」：这套保护的开关权限（GitHub 管理员）由决策者亲自持有，主理人只保留普通推送权限。这样主理人要拆这道闸，就得拿到决策者的账号——信任锚从「主理人自律」换成「决策者持钥匙」，和体系里密钥根归人类离线自持是同一个道理。**这是三个办法里唯一一把主理人拆不掉的锁。**

**办法二·给逃生门加一把要人发的钥匙（降闸令牌制）。** 现在降闸是自助的：设一个环境变量就能降。改成：每次降闸要事先向决策者要一张一次性通行证（带有效期、带事由、限提交范围），本地闸机械校验这张证——无证降闸＝当场红；同一张用第二次＝当场红；降闸动作与通行证在账上配对留痕，对不上＝报警。同时把仓里几笔老旧欠账（三枚旧违规＋两枚工具旧缺）先用白名单或卫生票消化掉，把「不得不降闸」的需求面收窄。诚实说在前面：**本地这把锁理论上仍可被硬拆**（跳过钩子那条路本地拦不住），办法二单独用只能做到「抬成本＋留凭证」，它真正的硬闭环要等办法一落地——因为 GitHub 复跑不看本地有没有降闸，违规就是红。

**办法三·每天一双和主理人无关的新眼睛（独立哨兵窗）。** 由决策者这边的定时任务，每天唤起一个全新的只读会话：不写任何东西、只读账本和链条，核五件事——日终对账跑没跑／有没有降闸却没通行证／关键脚本有没有被改动／本机链条和 GitHub 上的链条是否一致／账本有没有断更。有问题就用大白话直接报给决策者（不经过主理人），每条报警三句话：发生了什么、为什么要紧、能做什么。哨兵不拦截、不裁决——它只是把「事后赖不掉」在二十四小时内送到人眼前，纠错动作仍然是人。

### 怎么选（取舍）

三个办法不是三选一，是三层：**办法一装锁（事前拦）、办法二留凭证（降闸要人批）、办法三报警网络（事后二十四小时可见）**。单独用二或三都回到「赖得掉但拦不住」的原点，因为它们跑在本地；单独用一已经命中命题（存在一把拆不掉的锁），但降闸行为和账目异常还得靠二、三补可见性。建议＝三案全开、按一→二→三落地（二和三的「对账配对」都依赖一提供的「改不掉的远端镜像」，所以一先行；二、三在一落链后可并行）。

### 甲·案①带外面化（远程 CI 复跑＋分支保护）

白话目标＝装一把主理人拆不掉的锁：进主干必须过 GitHub 独立复跑，保护开关的钥匙只在决策者手里。

机制＝五件：(1) 复跑面＝.github／workflows／gate-replay.yml，push／PR 触发，ubuntu 镜像内 python3 原样调 share／run-gates.sh --root . --no-write（--no-write 只读模式在册＝exit 读数与写盘模式一致＝FX-U21 与 D-86 裁例现读）＋十一枚 check-* 族随 run-gates SCRIPTS 行现读全装载；(2) 证据链回指＝复跑读数按②证据件同 schema 产出 artifact＋在合并 PR 报告面留 run-ts＋commit 配对（本地证据件居 ignore 域不入链＝回指语义＝「远端跑过且绿」绑定 commit 对象本身，GitHub 侧状态记录不可由本地改写＝这才是锚）；(3) 分支保护＝main 禁直接 push（主理人直推形态被卸）＋禁 force push＋禁改写历史＋required status check＝gate-replay＋管理员也须走 PR（admin enforcement 开）；(4) 凭证拓扑＝GitHub 仓库管理员＝决策者本人账号持有；主理人现有 token 降为仅可推候选分支；(5) 路由随动＝主理人工作流改为「推候选分支→GitHub 绿→合并入 main」＝对现「链上笔」语义零破坏（合并即入链）。

可进 CI 的闸面清单＝可移植面＝content 闸族十一枚（check-provenance／check-skill-meta／check-pointers／check-entity／check-collab-lint／check-pointer-closure／check-source-of-truth／check-ticket-reconcile／check-adr／check-hook-health／check-collab-buckets——run-gates SCRIPTS 行现读逐枚具名＝全为只读 python＋仓文件读取＝linux 可跑）＋check-staged-declaration 语义改配＝CI 面对象＝commit 面单（PR 文件清单）而非 staged 区＝判据可复跑形态在 CI 侧等价成立（commit 面单＝git show --name-only＝跨平台只读）。不可进 CI 面＝会话装载面三脚本（write-guard／commit-audit／memory-neutralize＝PreToolUse 平台事件形态，CI 无该事件流）＋声明闸的本地阻断职能（提交前拦＝只能本地做，CI 做「漏网检出＋进不了主干」）。

### 乙·案②逃生门上锁（降闸令牌制）

白话目标＝降闸从「自己说了算」改成「每次要人批」：没有决策者发的通行证，闸降不下来；用了通行证，账上留证对得齐。

机制＝四件：(1) 令牌签发＝决策者离线用私钥签一条 JSON（随机码＋有效期＋事由＋适用 commit 范围），交付方式＝人工粘贴（经主理人转交不损效力＝验签靠公钥不靠渠道）；(2) 校验点＝pre-commit 侧机械校验＝check-staged-declaration.py／run-gates.sh 两处置绕过点前插验签调用（新件 gate-token-verify.py＝验公钥签名＋时限＋未消费）；公钥在仓＝签名件本身 append 入仓根账本「签字」类记录载荷扩展字段（RECORD_TYPES 六类闭集零动＝B16-f J-1 采甲在册约束随守）；(3) 一次一码＝随机码消费态入仓根账本＝同码二次出现＝当场红；(4) 配对留痕＝降闸提交＝「签字」记录＋bypass 证据件＋commit 三者配对＝③哨兵日核配不拢即报。
兼容既有先例＝当日「受控降闸具名随笔」案型（commit message 具名＋闸 BLOCK 面归因存量）＝令牌制上线前存量随笔照登不回改（T1 时间效力条款同纪律）；上线后同形态＝随笔升级为「通行证号内嵌 message」＝灰度判据字段随票声明。
配套需求面收窄＝三枚旧 OA-T1＋两枚 infra 旧缺＝T4 卫生票或白名单基线件消化＝日常提交不再需要降闸＝令牌面低频。

成本与副作用＝决策者每次降闸多一个签发动作（低频＝T4 后预期月频以内）；新增密钥对运维（公钥随仓／私钥人类离线）；两闸脚本改动＝行为变化面＝段③预览验证面＝各令牌形态双向断言入 T2 验收。

失效承接＝私钥丢失＝令牌面停摆＝降闸＝零＝闸恒强（fail-closed 方向安全）；校验脚本缺陷＝fail-closed 语义沿 GWP-P3-1（守卫失效＝阻断非放行）。

诚实申明＝本地锁可硬拆＝P1／P2 探针直证＝跳钩子连令牌校验一并跳过＝令牌制单独用＝「防过失＋留凭证」非「防对抗」；其硬闭环依赖案①：旁路提交进了不了 GitHub 绿名单＝①的 required check 才是终拦；本案不声明「主理人绝对无法降闸」。

### 丙·案③独立哨兵窗（定时新鲜只读会话＋白话报警）

白话目标＝每天一双与主理人无关的新眼睛：只读、不写、查出异常就用大白话直接告诉决策者。

机制＝三件：(1) 唤起面＝决策者侧定时（本机任务计划或 GitHub Actions schedule——schedule 臂需 T1 后装＝仓内 workflow 由链分发＝装载仍外部触发）唤起一个**全新只读会话**，装载包＝与专家团同包但席位注册为只读哨兵席（write_globs＝空集＋deny 全量＝表2-1 新行＝签4）；(2) 测定面＝五查机械判据：日终对账 diff 与绑定读数（reconcile-daily.py 现件直调）／降闸有无通行证配对（仓根账本 bypass 类 vs 「签字」类配对核）／禁动面钉值漂移（§五·丁对钉集取现行版）／本地 HEAD 链 vs origin 链一致核（git fetch 只读）／账本断更与 seq 连续性；报警语体硬目＝每条三句（发生什么／为什么紧／能做什么）＋呈拍三律沿 10-roles 真源只指不搬＝件内可机械预检句数与字数目＝看不懂＝不合格＝既定人话纪律在册；(3) 送达面＝带外直送决策者（J-2 荐甲）＋治理域登记件入链存证。
哨兵权限面＝只读＋禁 git 写＋不落临时物于仓外（探针重定向 .scratch／哨兵票号／ 用毕即拆）＝其自身行为面＝同包纪律装载＝被检者之外的第三只眼但**不持裁决权**。

成本与副作用＝每日一跑的低成本；新增席位注册与 config 两枚随动＝配置面维护；误报面＝钉值漂移类需与当日放行票对拍（白名单＝当日已放行票号具名）＝报警语体含「可能正常」出口防狼来了。

失效承接＝哨兵窗自身失效＝断更本身即报警项（决策者侧看门狗＝连续两日无报警记录＝问一声＝人类侧动作＝不需要机械保证）；哨兵读到的账本被伪造＝读的是 git 面＋远端面差分＝本地伪造在远端差分下现形（依赖 T1）。

诚实申明＝哨兵＝可见性层非拦截层＝不裁决不拦截＝纠错仍归决策者；哨兵窗运行在决策者侧会话＝其「独立性」＝唤起与权限源在决策者侧＝非绝对独立（同一宿主平台）＝诚实口径＝「与主理人不同会话不同权限」，不写「超然第三方」；本件本身居仓＝哨兵产出报警件入链后主理人可读＝可读不影响报警已达决策者＝带外面为正途。

### R-1·红-A① 案①机制补臂＝检看者与被检者分离（对 v1 行 210 的增补＝新增机制(6)）

    (6a) 取源规则＝CI 复跑面的「检看器」不得取自被检提交：复跑所用闸脚本族（run-gates.sh＋check-* 族）与
         workflow 定义本体一律从「受保护钉位」检出到 RUNNER_TEMP 后调用；被检 PR 面只提供内容对象
         （被检文件集），不提供工具层。钉位形态二取一（等价）：
         甲＝固定 commit 钉值（仓内一枚钉值件存四十位 sha）；乙＝受保护 ref 名（main）＋复跑内先取该 ref 再取其物。
         本包荐甲＝钉值可被③哨兵钉值漂移臂日核，ref 名不可核龄。
    (6b) 取源规则的可判面＝复跑日志首行打印工具层 blob 哈希与钉值件比对＝不等即红＝required check 名不变＝
         绿必由钉位工具层产出＝「改弱脚本再自证绿」在复跑面失效。
    (6c) 钉值件写权与维护责任＝归决策者侧（人类侧·与 §11 外置物 CI 行承载者同侧）；主理人对钉值件写＝deny；
         钉值变更动作＝C1 特快（人类先令＋限时追认）＝不开自动旁路。
    (6d) 补强臂（与 6a 并联·可选）＝检看器所在径（.github／workflows／＋share／闸脚本族）加 CODEOWNERS＝
         人类批准方可改＝改检看器须人类点头＝低频人类审＝与呈拍三律不冲突。
    失效承接（钉位方案自身失效＝何态）＝钉值件缺位／指向不存在对象／RUNNER_TEMP 取物失败＝复跑 fail-closed＝
         required check 红＝进不了主干（方向安全·沿 GWP-P3-1 守卫失效＝阻断非放行）；
         钉值陈旧＝工具层落后被检面语义＝误拦＝③哨兵日核项加「钉位龄＋钉位工具层 blob 对 main 差」超阈白话报；

         强度仍等于人类审批与凭证面的纪律强度。
