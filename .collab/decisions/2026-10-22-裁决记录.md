## 裁-11 部署架构原则：席位不绑模型·交接只认盘面（2026-10-22 16:1x·皮总论定·tri-collab v3.1）
- **来源**：皮总原话「当前是因为 WorkBuddy 作为 UI 不支持给每个 Agent 单独指定后端，只能从有没有写盘权限做最小化拆分。实际上未来不同类型的 Agent 灵活配置不同模型应该是趋势——让不同的工作使用最有性价比的组合，避免 token 浪费和同模缺陷。所以交接本身就是需要用盘面交接的形式，而不是智能体内交接的形式」。
- **定形两条**（落 `40-deployment.md` 架构原则节＋`20-handoff.md` §一＋SKILL.md 骨架）：
  1. **席位＝权限与读域定义，不绑定模型**；逐席独立配后端模型＝目标形态。业界印证：RouteMoA（arXiv:2601.18130）15 模型池按任务路由成本 −89.8%·延迟 −63.6%·准确率反升 10.2%（B 级转述·已标）；generator-and-judge 范式原话 "a model is a poor critic of its own blind spots"——判定方须异模型才成立，与本器「席位的隔离强度＝模型的隔离强度」互证。当前 UI 不支持逐席配模型→按写盘权限最小化拆分＝**过渡妥协**（此定性入文，防后人把妥协当设计）。
  2. **交接只认盘面，不认智能体内部**：会话上下文是模型内部状态——跨模型传不过去、随会话消亡；盘面 md 交接＝**异质模型时代唯一模型无关（model-agnostic）的协作介质**。定性反转注记：盘面交接不是形态 A 的妥协，是异质模型部署的**前提条件**。
- **推论（记而未行）**：将来 UI 支持逐席配模型时，席位表无需改动——权限分级模型（v3.0）正是为此预留：席位与模型解耦后，换模型只动部署配置不动纪律。
