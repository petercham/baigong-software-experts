# bundle-assembly-registration · 专家包装配与注册

**本件＝一道工序（装配 → 注册），不是发布器能力说明。**

**发布器能力**（产地到部署面的单向复制、同步账本体例、状态对账、准入闸、退出码闭集）的真源＝`object-build/references/60-publish.md`。本件**只指针、不复述其正文**；本件判的是「这道工序走完没有」，不是「复制怎么实现」。

## 一、期与型

| 轴 | 结论 | 一句话理由 | 判据出处 |
|---|---|---|---|
| 期 | **运行时挂载**（技能层通例：声明编译期、挂载运行时） | 每次按索引件的输入取值执行，产物不入任何仓版本库、按内容寻址增长，不存在「装订后不可换」的绑定 | `object-build/references/15-binding.md` |
| 型 | **T 步骤型** | 有明确的「做完了」：索引件＋各源仓（输入）→ 装配面／部署面（产物）可逐文件对账 | `object-build/references/10-skill.md` |

T 型必填四项＝**入口条件／步骤（含停手条件）／出口判据／产出件**，落点依次为本件 §三／§四／§五／§六。

## 二、两侧与三件套（术语闭集）

| 名 | 是什么 | 取值从哪来 |
|---|---|---|
| **索引件** | `bundle.lock`：组件 → 仓／ref／ref 种类／源路径／装配目标路径 | bundle 源仓内的 bundle 目录 |
| **装配面** | 仓外同级 `<bundle 源仓>-build/<bundle 名>/`；可用 `--out` 覆盖，**不得落进任何源仓内** | 装配器缺省规则 |
| **部署面** | 平台插件缓存下的 `<包>/<版本>/` 目录；路径由平台侧给出，本件不写死 | 平台侧 |
| **装配三件套** | 装配全账（组件→commit 的解析结果）＋ 同步账本（逐文件指纹流水）＋ bundle 本体与组件子树 | 装配器产物 |

同步账本的体例（键集、块追加、四元组、摘要算法）见 `object-build/references/60-publish.md`（指针·本件不复述）。

## 三、入口条件（四条全绿才起步；装配器 fail-closed，先于任何写）

1. 索引件存在且为合法 JSON，`bundle.name` 与 `components` 均非空。
2. 每个组件行五键齐：组件名／仓／ref／源路径／装配目标路径。
3. 各源仓**已跟踪文件零改动**（`git status --porcelain -uno` 输出为空）。未跟踪文件只报告不拦。
4. 每个组件的 ref 可解析为 commit；ref 种类为 tag 时锁的是不可变 tag，不得用分支名或 HEAD。

## 四、步骤（含停手条件）

| 步 | 动作 | 停手条件（命中即停，不得往下走） |
|---|---|---|
| 1 | 前置自检：索引件完整性、源仓 clean、ref 可解析 | 任一不绿 ⇒ 停，回源仓修，不得「先装配再说」 |
| 2 | 跑装配器：`python <装配器脚本> --assemble "<bundle 目录绝对路径>"`（装配器＝`object-build/scripts/publish.py`） | 退出码非 0 ⇒ 停；码值语义按 `object-build/references/60-publish.md` 的退出码闭集（指针） |
| 3 | 产物核对：三件套齐 ＋ 文件数对账（判据 C1–C6） | 任一对不上 ⇒ 停，视为装配未完成 |
| 4 | 幂等复跑：同一命令再跑一次，期望输出含「零写入」且退出码 0 | 出现写入 ⇒ 停，查是否有源侧变动或装配面被手改 |
| 5 | 注册前置：目标版本号已 bump（版本值与包主文件同源）＋ 部署面未被占用 | 未 bump ⇒ 停；被占用 ⇒ 停，改走平台侧重注册 |
| 6 | 装配面 → 部署面**整体复制替换**（含版本目录新建与旧版本目录去留） | 报错或半写 ⇒ 停，回滚到备份，不得留半新半旧的包 |
| 7 | 注册后验证：部署面出现装配全账 ＋ 两侧逐文件指纹差集为空 | 差集非空 ⇒ 停，按漂移处置 |
| 8 | 交审计：把 §五 的判据清单与第 2／4 步命令输出交 `object-audit` 判 | 判据出现「合格／合理／完善」类词 ⇒ 判据重写，不算出口 |

## 五、出口判据（全量机检口径见 `references/30-criteria.md`）

| # | 判据（可机检） | 机检方式 |
|---|---|---|
| C1 | 装配器退出码＝0 | 命令退出码 |
| C2 | 装配面装配全账存在，其文件计数值 ＝ 装配面非元数据文件计数 | 读 json ＋ 计数断言 |
| C3 | 装配面同步账本存在，末块文件行数 ＝ 装配全账的文件计数值 | 文本解析 ＋ 等值断言 |
| C4 | 装配全账每个组件的解析 commit 为 40 位十六进制，且 ref 种类与索引件一致 | 正则 ＋ 逐项比对 |
| C5 | 装配面路径不在任何源仓目录树内 | 路径前缀断言 |
| C6 | 索引件每个组件的装配目标路径在装配面为非空目录 | 目录存在性 ＋ 非空 |
| C7 | 幂等复跑输出含「零写入」且退出码 0 | 命令输出 ＋ 退出码 |
| C8 | 部署面版本目录存在，其装配全账的包名与版本值与装配面逐字相等 | 读两侧 json 比对 |
| C9 | 装配面与部署面逐文件指纹双向差集均为空 | 双向集合差 |
| C10 | 注册后对账落「一致」态（态的定义与判定式见 `object-build/references/60-publish.md`，指针） | 对账命令 |

## 六、产出件

| 阶段 | 产出 | 入不入仓 |
|---|---|---|
| 装配 | 装配三件套 ＋ 组件子树 | **不入任何仓版本库** |
| 注册 | 部署面版本目录 | 平台侧持有 |
| 证据 | 第 2 步与第 4 步的命令输出、注册后比对结果 | 按项目治理规范落证据域 |

## 七、负样本（摘要四条；全量见 `references/40-negatives.md`）

| # | 情形 | 为什么算「静默出错」 |
|---|---|---|
| N1 | 源仓有已跟踪未提交改动 | 被拦是好事；**未跟踪文件不拦**——误把「未跟踪文件多」当拦因去清理，白做 |
| N2 | 真源对账漏带根标记参数 | 组件根被当未纳管，报出一堆假阻断；照着「修 N 条」去做＝改错地方 |
| N3 | 部署面正被平台占用时复制替换 | 部分文件写失败却不报错，包体半新半旧，跑起来像一个正常的旧包 |
| N4 | 版本号未 bump 就重注册到同一版本目录 | 平台缓存不重载，看起来「注册过了」，实际跑的还是旧快照 |
