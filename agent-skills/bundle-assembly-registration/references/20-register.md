# 注册段（装配面 → 部署面）

> **归属**：`bundle-assembly-registration` 的第 5–7 步细则（注册前置·整体替换·注册后验证）。
> **边界**：复制实现、账本体例、状态对账、准入闸、退出码闭集、删除纪律的真源＝`object-build/references/60-publish.md`。本件只指路径，不复述其正文。

## 一、注册的定义（先定死，免得做成增量）

**注册＝把装配面整体复制替换到部署面的版本目录。不是增量、不是合并、不是「两边取并集」。**

| 常见误解 | 正解 |
|---|---|
| 只把变化的文件复制过去 | 整体替换：部署面终态＝装配面终态 |
| 部署面多出来的旧文件留着无害 | 留着＝包体是「装配面 ∪ 旧残留」，两侧指纹差集非空，判据 C9 直接不过 |
| 可以用部署面的内容回填装配面 | 单向：装配面是唯一产地，反向同步会把部署面变成第二产地 |

## 二、版本目录怎么处理

1. **先 bump 版本号**（纪律①），版本值与包主文件同源；未 bump ⇒ 停手。
2. **新建目标版本目录** `<包>/<版本>/`，把装配面内容整体复制进去。
3. **旧版本目录的去留**：先备份，再按平台的版本保留约定处置。
4. **删除纪律**：只允许删「我们自己发过、现在不发了」的差集，**禁止按目录枚举递归删**——部署面混着我方件与平台件，枚举删必然误删。删除判据与唯一允许的删除形态见 `object-build/references/60-publish.md`（指针）。
5. **复制形态**：二进制逐字、不转码、不动换行、不动 BOM，权限位跟着走（同上件指针）。

## 三、占用风险（本段最大的静默失败源）

部署面**是正在被平台使用的插件缓存目录**，不是工作空间：

| 风险 | 表现 | 处置 |
|---|---|---|
| 复制时目标被独占 | 部分文件写失败，工具可能不报错 | 复制后必做双向指纹差集（C9）；差集非空即停手回滚 |
| 覆盖后平台仍持旧快照 | 界面/运行表现与部署面字节不符 | 走平台侧重注册，或重启平台后复验 |
| 半新半旧的包 | 跑起来像一个正常的旧包，症状延迟出现 | 不得停留在该状态：回滚到备份，重新走完整流程 |

**优先路径＝平台侧重注册**：把装配面当作一个新包注册／更新，由平台侧完成落地与缓存切换。**直接覆盖缓存目录是备选路径**，只在确认未被占用、且已备份时才走。

## 四、注册前置（第 5 步的三查）

| 查 | 期望 | 不绿怎么办 |
|---|---|---|
| 版本号已 bump，且与包主文件同源 | 相等 | 停手，回装配段改版本 |
| 部署面未被占用 | 可独占打开／平台未加载 | 停手，改走平台侧重注册 |
| 已备份现部署面 | 备份存在且可读 | 停手，先备份（无备份不得覆盖） |

## 五、注册后验证（第 7 步）

| # | 查 | 机检口径 |
|---|---|---|
| C8 | 部署面版本目录存在，其装配全账的包名与版本值与装配面逐字相等 | 读两侧 json 比对 |
| C9 | 装配面与部署面逐文件指纹**双向**差集均为空 | 两个方向的集合差，各打印差集条数 |
| C10 | 对账落「一致」态 | 对账命令；态的定义与判定式见 `object-build/references/60-publish.md`（指针） |
| 附加 | 部署面出现装配全账与同步账本 | 文件存在性（旧快照无这两件＝注册尚未执行） |

**旧快照的识别信号**：部署面有包内容但**没有**装配全账与同步账本 ⇒ 该部署面不是本工序的产物，注册尚未执行，不要据此判断「已经注册过」。

## 六、与真源对账的关系（易错点）

装配态下跑真源对账**必须显式带根标记参数**（组件根与技能真源根的双根口径），不带会把组件根当成未纳管，报出一批假阻断。

- 对账工具：`share/check-source-of-truth.py`（指针·含根标记参数与基线重生成的用法）。
- 本件不定义对账判据，只记这条**调用纪律**：不带根标记参数的对账结果不可作为放行依据。

## 七、停手条件汇总

| 命中 | 动作 |
|---|---|
| 版本号未 bump | 停，回装配段 |
| 部署面被占用且无法走平台侧重注册 | 停，等释放 |
| 无备份 | 停，先备份 |
| 复制报错或半写 | 停，回滚到备份 |
| C8／C9／C10 任一不绿 | 停，按漂移处置（处置口径见 `object-build/references/60-publish.md`，指针） |
