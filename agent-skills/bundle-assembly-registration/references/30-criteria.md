# 出口判据全量（机检口径·供审计器咬）

> **用法**：本件是 `bundle-assembly-registration` 出口判据的**唯一清单**。判据编号 C1–C10 与主文件 §五 一一对应。
> **三态口径**：绿（有证据）／未绿（无证据）／不适用·已移出（须注明移到哪一步、谁拍的）。**「已移出」不计入绿**；绿 ＋ 未绿 ＋ 移出 ＝ 判据总数（10）。
> **判定权**：判据由本工序给出，**判定由 `object-audit` 出**（构建方不自证）。

## 一、判据表

| # | 判据 | 机检方式（可复跑） | 不绿的典型原因 |
|---|---|---|---|
| C1 | 装配器退出码＝0 | `python <装配器脚本> --assemble "<bundle 目录>"` 后取退出码 | 源仓脏、ref 不存在、索引件缺键 |
| C2 | 装配全账存在，且其文件计数值 ＝ 装配面非元数据文件计数 | 读装配全账的 `files`；数装配面文件（排除索引件／同步账本／装配全账三件）后等值断言 | 装配面被手改、复制半写 |
| C3 | 同步账本存在，末块文件行数 ＝ 装配全账的文件计数值 | 解析末块文件行；等值断言 | 记账与落盘不同步 |
| C4 | 每个组件的解析 commit 为 40 位十六进制，且 ref 种类与索引件一致 | 逐组件正则 `^[0-9a-f]{40}$` ＋ 与索引件 `ref_kind` 比对 | ref 被移动、索引件与装配面不同源 |
| C5 | 装配面路径不在任何源仓目录树内 | 路径前缀断言（装配面对各源仓根不得为子路径） | `--out` 指进源仓 |
| C6 | 每个组件的装配目标路径在装配面为非空目录 | 目录存在性 ＋ 条目数 ＞ 0 | `target` 写错、该 ref 下无此组件 |
| C7 | 幂等复跑输出含「零写入」且退出码 0 | 同 C1 命令连跑两次，比对第二次输出与退出码 | 源侧有变动或装配面被手改 |
| C8 | 部署面版本目录存在，其装配全账的包名与版本值与装配面逐字相等 | 读两侧装配全账，逐字比对两个字段 | 版本未 bump、复制未覆盖 |
| C9 | 装配面与部署面逐文件指纹双向差集均为空 | 两侧递归取相对路径与指纹，算两个方向的差集，期望各为 0 条 | 部署面被占用导致半写、残留旧文件 |
| C10 | 注册后对账落「一致」态 | 对账命令；态的定义与判定式见 `object-build/references/60-publish.md`（指针·本件不复述） | 复制实现走歪、权限位没跟着走 |

## 二、判据的咬合自检（写判据时逐条自问）

| 自问 | 不通过的样子（须重写判据） |
|---|---|
| 这条能写出退出码或逐条核验动作吗 | 「装配面质量合格」「复制完整」——不可机检 |
| 这条有唯一取值吗 | 「文件数大致对得上」——无等值断言 |
| 这条的落点是产物本体还是治理面计数 | 只数「跑过几次命令」＝票面绿、本体没做 |
| 这条会不会出现「谁都能判绿」的宽口 | 「看起来正常」 |

## 三、证据三件套（交审计时一并提供）

1. **第 2 步命令输出**（含退出码）。
2. **第 4 步幂等复跑输出**（含「零写入」字样与退出码）。
3. **注册后比对结果**（C8 两字段值、C9 双向差集条数、C10 对账态）。

缺任一件 ⇒ 对应判据记**未绿**，不得凭「流程走过了」计绿。

## 四、与发布器判据的分工

状态对账的态集合、准入闸、退出码闭集、删除纪律＝`object-build/references/60-publish.md` 持真源（指针）。本件的 C1–C10 是**工序出口判据**，问的是「这道工序走完没有」；它不重新定义发布器的任何判据，也不复制其判定式。
