# 专家角色构建（席位定义／专家包）

> **状态**：草稿 v0.1（此前完全空白——审计侧只有判项、无构建规范）。
> **出处**：三栏／信息隔离／升级路径＝本地约定（四席协作归纳）；「生产方不得兼判定方」＝业界通识（separation of duties）；「最小权限」＝业界范式（least privilege）；「单写者」＝命名者一手（Mechanical Sympathy 的 Single Writer Principle）。

## 第 0 步：先判它是不是"角色"（不是 → 别走本器）

**业界空缺须先承认**：官方九类与 superpowers 四型里**都没有「角色定义」这一类**。所以角色在本体系里不是第五型，而是 **D 型 skill 的一种具体形态**。

判据三问，任一为否就是走错门：

| 问 | 否 → 它其实是 |
|---|---|
| 有没有**不许越的线**（越了要出事）？ | 方法论文档 → 走 M 型 |
| 有没有**固定的产出动作**？ | 纯知识说明 → 走 F 型 |
| 有没有**对谁负责**的关系？ | 通用工具说明 → 走 T 型 |

## 第 1 步：填三栏（缺一不写）

| 栏 | 写什么 | 缺栏后果 |
|---|---|---|
| **管什么** | 本角色的判定权／产出物（使命，一句话） | 无边界＝什么都管＝什么责任都不担 |
| **不管什么** | 明确禁区（不判定／不写盘／不入回执链） | 无禁区＝越权高发 |
| **对谁** | 上行给谁、下行给谁、能否并行 | 无接口＝消息乱飞或断链 |

**写「不管什么」时的最小集**：至少写清三件——① 是否可判定自己或他人的产出（自证禁止）② 是否可写盘 ③ 是否可自行扩范围。这三条不写，「不管什么」等于没写。

## 第 2 步：声明权限（四类·各自"有/无＋写域"）

| 类 | 必须写成 | 反例 |
|---|---|---|
| 写盘 | 有/无 ＋ **具体写域**（哪些目录） | "按需写"＝无边界 |
| 执行 | 有/无 ＋ 可跑什么（脚本／命令／外部调用） | "可执行必要命令" ＝什么都可 |
| 外发 | 有/无 ＋ 发给谁 | 未声明＝默认可发 |
| 判定 | 有/无 ＋ 判谁（**不得含自己**） | 生产方兼判定＝阻断 |

**单写者（不可谈的一条）**：同一治理盘**有且只有一个**写盘角色。其余席位**永无写盘权**——不是「默认无、项目可改」，是无例外。

单个写盘角色的三个常见违反形态，造的时候就避开：
1. 两个角色都写同一目录（"各写各的子目录"也算，闭集被打散）；
2. 审计／验证角色以"证据"为由保留写权（证据应由写盘角色誊录，报告正文承载内容）；
3. 写权写成"默认无，项目可配"——**配置项存在即会被打开**。

## 第 3 步：写加载隔离

| 项 | 写什么 |
|---|---|
| 不被调用不占上下文 | 常驻面只留一行路由；角色件在触发时加载 |
| 只加载自己那件 | 不夹带别的角色的操作细则；只写「X 负责，见其件」 |
| 信息隔离声明 | 显式写「本角色**不需要**知道什么」（例：执行角色不见讨论过程与未定方案） |

## 第 4 步：写升级路径

一句话写死「**停手上报给谁**」。无升级路径＝角色遇冲突会自行降标准（这是角色失效最常见的形态，比能力不足更隐蔽）。

配套两条：角色不得自行扩权／扩范围；范围变更须拍板人。

## 第 5 步：写盘角色专有的附加项

写盘角色的定义里必须写明：**落盘前自读项目治理规范**，据此定归属／命名／路由／修订制；**不得凭印象落盘**。缺这条＝会产出格式对但不合规的件。

## 一条不可谈的：本体层决策权不给任何 AI 角色

**什么叫做完／合法值域／评估标准／范围边界，只能人类独占；AI 角色只有提案权。**

造角色时若写出「可自行决定判据／验收标准／阈值放宽」＝该角色从设计上就是错的（不是执行时会出错，是定义即越权）。

## 自检（写完跑一遍）

| # | 自测 | 判法 |
|---|---|---|
| 1 | 三栏齐 | 每栏都有非空内容，且「不管什么」含三条最小集 |
| 2 | 权限四类齐 | 写盘／执行／外发／判定各有"有/无"，写盘带写域 |
| 3 | 单写者 | 造一个"另一角色也写同一目录"的假设场景，定义里应能直接判否 |
| 4 | 负样本 | 造一个"该角色越权"的场景，看定义里有没有咬住它的句子 |
| 5 | 隔离可查 | 「不需要知道什么」写得能被抽检（下一轮实际投递内容能对上） |

## 交接口（写完交审计器时提供什么）

1. 三栏全文（管什么／不管什么／对谁）。
2. 权限四类表（尤其写盘＝有/无 ＋ 写域）。
3. 升级路径那一句原文。
4. 本体层决策权归属声明（应为"人类独占·AI 仅提案"）。
