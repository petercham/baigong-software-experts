### 2.2 五个必答项立场

1. **第 8 席：有条件批准，不建议无条件暂缓。** 功能缺口是事实性非偏好性（快速模式自称首选却无配音归属）；前置条件＝TTS 供应链在依赖声明中定档；评估门槛不是「跑 2–3 个项目看工时」而是「定档后估算配音字幕占剪辑师工时比例」——专业 TTS＋词级精调＋校对＋核验＋末段补长大概率超 30%，独立合理；edge-tts 级合并即可。定档动作本身就能回答，不需要用项目试。
2. **G4：分栏独立表态优先；皮总要结构干净则独立 G4b；不推荐合并成一个确认。** 分栏＝同一轮交互两栏、分别确认独立生效，预算栏可先过资产栏可后过，任何一栏未确认则对应动作不启动；不增闸数不增轮次但保决策独立。
3. **快速档闸减负：采纳方向，两个限定。** ①样张成本必须计入 G4 预算闸总额，不能因「是确认用预览」游离在预算纪律外——否则计费时点从 G4 后提前到 G3 前；②G2+G3 合并的前提是样张已能代表脚本画面效果；正确顺序是 G2 确认脚本 → 生成样张 → G3（脚本＋样张）合并确认 → 放量，**合并的是确认动作不是准备动作**。不会削弱硬闸纪律——「显式确认、沉默不算」语义未变，变的只是确认物从提示词原文换成样张。
4. **沉默超时：挂起＋恢复指令可行，阈值按档位。** 三要点：挂起态不销毁现场（状态/已过闸/待确认工件全保留，断点恢复不重跑）；恢复指令绑定上下文摘要；超时阈值按档位（极速/快速 24h、标准 72h），超时后记录「等待需求方确认（Gx，自 YYYY-MM-DD）」并停止推进，**超时不等于拒绝、不等于默认通过、不等于项目取消**三条写死。
5. **运行时契约最小可行形态＝三件套，按序落地。** 层 1 资产暂存区（最硬阻塞点；宿主执行席管理共享目录，资产 ID 规约 `<项目简称>/<类别>/<编号>-v<版本>`，各席只写自己类别、只读别人引用，回传「资产 ID＋摘要」不传二进制；引 Agentic Multimedia Firm 的组织层论证：资产会分支、累积权利义务、需要账本）；层 2 工具白名单（按计费触点档位矩阵，每席声明可调工具，主理人持工具注册表；异步任务模式决定契约必须含「任务 ID 回传、失败不自动重复提交、非终态只查原 taskId」三条）；层 3 契约 schema（随判据 skill 交付；执行环境放宿主执行席侧，输入读暂存区、报告写 `reports/`、退出码 SendMessage 回传；参考 takecheck；更完整质检参考 `neoaudit` 三级架构——规则过滤→专用小模型→多模态大模型深评，已覆盖肢体崩坏 OpenPose/闪烁光流/文字乱码 OCR/跨镜头角色一致性 Face Embedding 等 V 轨判据）。**三层是依赖链不能跳层。**

## 三、GLM-5.3 第二轮核心观点与理由

### 3.0 先行调研（三条，为后文供弹）

1. **多智能体编排状态传递**：LangGraph 共享状态/Checkpointer、AutoGen 黑板、Claude Code subagents 的 workspace＋文件引用——2025 年成熟实践已收敛为同一形态：**大产出落盘为工件，消息只传引用＋摘要**，由显式状态层承载；纯消息中转大文件是公认反模式。→ MiMo P0-2 不是孤例是行业共识，C1 层 1 直接对齐 workspace/artifact 模式不用自创。
2. **AIGC 视频模型音频能力**：可灵/即梦/海螺/Sora 类 2.x 代际主流模型已普遍支持**音画同步生成（对白/音效内嵌）**，TTS 独立链路必要性下降，但词级字幕＋语速核验仍是独立工种。→ 直接影响 D1：第 8 席存废取决于供应链选型，而选型天平在向「生成模型自带音频」倾斜。
3. **视频一致性手段**：参考图/首尾帧锚定＋种子管理已是标配，「看图认领」与 manifest 对账是工具链原生操作粒度。→ 资产制度与工具链同构，落地阻力低。

### 3.1 五个盲区的优化（每条：改哪里/改成什么/拍板者判什么）

1. **④维落地件缺失 → 上架物料清单＋包级回归矩阵**：物料闭集清单（plugin.json 全字段规约：name 小写连字符全局唯一/version 语义化/author 含 name+email/expertType: team/agentName＝主理人 MD name＝文件名三处一致/teamInfo/members[].avatar/displayDescription 中英 40–50 字/tags×3/quickPrompts×3 且 defaultInitPrompt＝quickPrompts[0]/categoryId 官方闭集值）；settings.json；**头像替换排期**（借用官方素材是④维红旗——品牌混淆＋授权语义不清，定制 8 张 512×512 PNG ≤500KB，或最低限度 README 声明借用来源）；回归矩阵 12–15 条测试 prompt，**必须覆盖五档路由各 1 条正路径＋每档 1 条拒绝/降级路径**（圣经被拒、G4 超限、判据退出码 2、B 路分诊、规则库缺失时「未经核实」标注）。拍板判：物料齐全性＋矩阵是否「每档一正一反」——**validate 防字段、回归矩阵防表演，缺一不可**。
2. **确认预算未量化 → 圣经形制节增第 5 字段**：按档位声明人机交互上限——标准 SOP=4（G1/G2/G3/G5）＋G4 条件；极速=2；返工=1–3 按触达范围；数值与 D3 联动；超限向需求方说明并请求豁免、写入变更记录。
3. **契约无 schema → JSON Schema 随判据 skill 交付**（判据 skill 的 `references/schemas/`）：`script.schema.json`（含 **claims 数字溯源必填规则**：带数字的句子必须有 source）、`words.schema.json`（词级时间戳 word/start/end）、`asset-manifest.schema.json`（资产编号/类别∈{角色,场景,道具}/适用场次/圣经条款引用/提示词/种子/版本/授权状态）。「schema 本身就是可执行验证物（ajv 一类可直接跑）——**schema 先行、脚本随后、文字判据垫底**，三层递进」。拍板判：schema 是否覆盖各闸呈报全部字段；claims 必填规则与编剧席「登记≠验真」是否对齐。
4. **生成模型可用性契约 → 供给侧契约节**：①可用性检查——G3 前主理人探测模型目录/连通性；无目录契约时退化为「契约日期快照＋上次成功记录」双证；②降级链——图生视频（带参考图）→ 文生视频 → 降档（分辨率/时长取允许最长档并交付注明，**不许反向改分镜**，与跳跃视界同纪律）→ B 路文字交付；每级承诺「交付物不缩水」（降级仍交提示词/样张，不空手）；③供给侧触发 A/B 分诊——宿主生成能力不可用时主理人主动建议 B 路。拍板判：每级触发条件与交付物承诺；「可用性」最低判据（探测 or 双证）。
5. **极速档预算口径歧义 → A+B 组合说死**：A（简版风格卡四行：风格关键词/禁忌/验收标准/**生成预算行**）＋B（默认公式兜底，需求方可覆盖）。只采 A 则需求方不填时 G4 触发条件悬空；只采 B 则三行承诺被破坏；组合后预算恒有出处、口径唯一。主理人 MD 圣经节＋人类确认闸节两处同步改。

### 3.2 C1 运行时契约——最小可行三层（按 1→2→3 建设）

**层 1 媒体资产暂存区（最优先，其他两层的地基）**：宿主执行席管理 `workspace/{project-id}/assets/`，manifest.json 挂点＋按资产 ID 编目（语义前缀＋版本号，如 `asset-role-chenGuan-001`）；写权限导演席（标准档）可写、其余只读引用；**SendMessage 契约修订为「回传资产 ID 清单＋摘要」**，非文本产出一律 ID 引用。对齐 artifact/workspace 行业共识，顺手解 MiMo P2-6 上下文膨胀。拍板判：暂存区归属；SendMessage 修订条文。

**层 2 判据脚本执行环境（第二优先，C4 防退化载体）**：**执行主体＝主理人，但需豁免条款**——主理人新增「质检执行权」（只调判据脚本、不代写任何产出），因「真实输出过闸」要求判据在闸上同步可判，交宿主执行者异步执行会退化成 DS 警告的「永远停留在文字清单」。I/O 契约：传入资产 ID → 读 workspace → 报告写 `workspace/{project-id}/qc/report-{gate}.json` → 主理人读退出码＋报告呈闸；退出码 0/1/2 语义与「2 不是通过、skipped 清单、修完必须复跑」写进主理人铁律。首版脚本化顺序：**资产齐全性（唯一阻塞计费的判据，G4 前置）＞ 时长咬合 ＞ 结构完整性**——与 DS 清单相同但排序理由是按「是否阻塞计费」排。拍板判：**主理人「质检执行权」豁免是否成立——这是对「主理人不碰生产工具」原则的唯一例外，必须显式拍**。
