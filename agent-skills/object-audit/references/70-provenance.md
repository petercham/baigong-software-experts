# 规范来源声明（spec provenance·审计侧）

> 期别：**编译期**。
> 出处：本地约定（显式标注）——「归属声明随身」「每条规则带三档出处」沿用 `50-document.md「D1-1 归属声明随身」` 与 `10-skill.md「S3 出处」`；「元数据字段集封闭、正文格式不限」＝开放标准一手（Agent Skills 规范）。
> **分工（不互抄正文）**：造「必须带」在 `object-build/references/60-publish.md`「准入闸·A3 出处齐」；本件只回答「**缺了判何态**」。两器不互抄正文，只互指路径。

## 〇、本件自身不带来源声明块（自举约束）

**规范不能给自己发证。** 本件的出处在上面那一行「出处」，授权链落在 `.collab/decisions/`——**不另设 provenance 块**，否则就是一个"自己给自己签发的证书"，签发的资格本身就是待证事项。

由此得出一条可判的推论，审任何执行体时都用它：

> **一个执行体的来源，必须指向比它更早落盘的东西。**
> 指向"同一时刻、同一批"或"更晚"的东西 ⇒ 该来源不成立（它不是来源，是互相背书）。

## 一、审：块在不在、字段齐不齐（P-1）

七字段是**闭集**——缺一个不合格，多一个也不合格（多字段＝偷偷扩协议，下游解析器会各按各的读）。

| 字段 | 审什么 | 取值要求 | 参与判定？ |
|---|---|---|---|
| `spec_id` | 编号是否落在本包号段内 | `^(OA\|OB\|MC\|PUB\|ADR)-[A-Za-z0-9\-.]+$` | 否（路由键） |
| `spec_file` | 所指文件是否存在 | 仓内相对路径，正斜杠，禁绝对路径 | 是（P-2 的定位前提） |
| `spec_anchor` | 是不是**稳定锚** | 条款编号或标题行首串；**不是行号、不是序号** | 是（P-2） |
| **`spec_clause_sha256`** | 摘要是否仍等于现值 | 64 位十六进制 | **是（P-3·唯一判定字段）** |
| `spec_version` | 格式是否可读 | `^[0-9]+\.[0-9]+$`，**不与任何现值比对** | **否**（描述性） |
| `spec_effective` | 格式是否可读 | `YYYY-MM-DD` | 否（描述性） |
| `provider` | 是否为本包名 | 必须是 `deliverables/` 下的现存包名，**不是人名** | 否（路由对象） |

**问**：块存在且键集合恰为七键？

**判何态**：块缺失／键集合不等于七键 ⇒ **exit 1**（**声明的作者欠**：写来源是作者的义务，"有没有来源"就是"能不能发"的前提，见 `object-build/references/60-publish.md`「准入闸·A3 出处齐」）。**不要把它记成 exit 3**——3 是**提供者**欠账，把"作者没写"记成"规范没人维护"，正是本包记在账上的**归属错**（`00-skeleton.md「引证失效的七个类型·归属错」`）。`provider` 写人名 ⇒ 同判 exit 1，并另判 **T1 项目实体命中**（`SKILL.md「T1 换项目测试」`）——脚本会因此**自己违反它要执行的那条干净度判据**。

## 二、审：这个块放在哪（容器）

```
# .py / .sh —— 文件末尾前的固定注释块
# --- spec-provenance v1 ---
# spec_id: OA-S5
# spec_file: deliverables/object-audit/references/10-skill.md
# spec_anchor: S5
# spec_clause_sha256: <64 hex>
# spec_version: 0.1
# spec_effective: <YYYY-MM-DD>
# provider: object-audit
# --- /spec-provenance ---

<!-- .md —— 正文首块 HTML 注释（同构） -->
<!-- spec-provenance v1
spec_id: …
spec_clause_sha256: <64 hex>
…
-->
```

解析＝"取首尾标记之间的 `key: value`"，一种正则三个载体通吃（不引入结构化配置依赖）。

**问**：`.md` 件的声明块是否放在**正文首块**、而不是文件头的元数据区？

**判何态**：放元数据区 ⇒ 不合格（阻断）。两条依据都不是偏好：①开放标准只允许固定的几个元数据字段，加字段会让跨工具打包或上传**硬失败**；②本包存量件已普遍带非规范元数据字段，是一处待清的历史债，再加一个字段＝加重它。

## 三、审：锚还指得到吗（P-2）

**问**：在 `spec_file` 里按 `spec_anchor` 定位，是否**恰好命中一处**（一行正文或一行表格行）？

**判何态**：

| 命中数 | 态 | 为什么 |
|---|---|---|
| 0 | **exit 3** | 锚没了——被指文件重构过，来源断链 |
| ＞1 | **exit 3** | 锚歧义——取到哪一条变成不确定，**不确定的判据不能进判定链** |
| 1 | 继续 P-3 | — |

## 四、审：那句话还是那句话吗（P-3）

**问**：按 P-2 取到的那一行，按本件规定的规范化（去首尾空白、连续空白压成单个空格、多行拼接）后取 sha256，是否仍等于 `spec_clause_sha256`？

**判何态**：不等 ⇒ **exit 3**（提供者欠账：条款变了，脚本还没跟上）。

**这一条是本机制最值钱的地方**：它把"文档改了、脚本还在跑旧判据"从**静默跑着**变成**阻断并上报**。审的时候要记住它问的**不是**"这份文件有没有被改过"，而是"**这条脚本执行的那句话，还是不是当初那句话**"——两者的差别就是全部误报的来源。

## 五、审：这个"来源"是不是拿标签冒充内容

对三种"关于内容的标签"逐一问。三种都**不能**回答 P-3 那个问题：

| 拿什么当判据 | 能不能判"那句话变了" | 反例（审的时候照这个问） |
|---|---|---|
| **版本号** | 不能 | 同一处"版本差"背后可能是**零内容差**（只补登元数据），也可能是若干条款全变；三处版本推进里可能没有一条与脚本相关。用它判 ⇒ 无关改动天天触发失联，真失效被淹在噪音里 |
| **行号** | 不能 | 行号是**可变量**：被指文件插一段，其后行号全部漂移。行号只允许作人读快照，**不入机检** |
| **整文件摘要** | 不能 | 一个文件里住着十条以上条款；改第八条会让执行第一条的脚本判自己失效——**误报的另一种形态**，与版本号同病 |

**判何态**：一个执行体的 `spec_anchor` 写成行号或序号 ⇒ **不合格**（阻断，因为它必将在下一次编辑后静默失准）；用整文件摘要 ⇒ 不合格（粒度与被判对象不匹配）。

**粒度原则一句话**：**判据的粒度必须与被判对象相等**。脚本执行的是**一条条款**，所以判据必须锚在**那一条**上。

## 六、审：`provider` 是不是只是写了个名字

**判不了的部分必须说出来**：本件**判不了**"这个 provider 是否真的有权定义这条"。授权链在 `.collab/decisions/`，只有人能核。

**判何态**：`provider` 指向的包存在但**无对应裁决或规范条目** ⇒ 判**关注**并**呈拍**，**不自动否决**——机制能判"有没有挂来源"，判不了"这个来源算不算数"，越界去判就是机器替人拍板。

## 七、自举期特例：新条款还没有落盘

**问**：一个执行体执行的条款，此刻在 `deliverables/` 里尚不存在，它的来源写什么？

**答**：唯一允许的临时来源是 `.collab/decisions/` 的**裁决条目**——`spec_id` 以 `ADR-` 开头，`spec_file` 指裁决记录，`spec_anchor` 指该条目的标题串。且**必须在该条目落盘之后**，脚本才可提交。

**判何态**：

| 情形 | 态 |
|---|---|
| `ADR-` 来源 + 裁决条目存在 + 锚唯一 | 通过（自举期内合法） |
| `ADR-` 来源但裁决条目不存在/锚不唯一 | **exit 3** |
| 规范件里**已有**对应条款，脚本仍挂 `ADR-` | 判**关注**「转写未完成」——须把 `spec_file` 改向方法论件（一次改，两处都不留悬空） |
| 条款与脚本同批提交、来源互指 | **不合格**：互相背书不是来源（§〇） |

## 八、审 provenance 时的报告口径

1. **逐件一行**：块有无 → 缺哪个键 → 锚命中数 → 摘要比对结果。
2. **处置人分栏**：exit 3 一律记在"提供者欠账"栏，**不得计入"产物不合格"**（`00-skeleton.md「引证失效的七个类型·归属错」`）。
3. **不报"看起来像"**："这个摘要像是没更新"不是判定；要么重算比对，要么写"未核"。
4. **锚的定位必须贴串**：报告里写 `文件＋条款锚`，**不写行号**（写了会随文件长高而失效，且下一个人读到的行号与你的不同）。
