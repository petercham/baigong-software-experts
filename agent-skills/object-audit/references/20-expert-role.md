# 专家角色对象审计（专家包/席位定义）

> **本件只持审计判据（问句式）。构建规范（三栏怎么填／权限怎么声明／隔离怎么写）在 `object-build/references/20-expert-role.md`，此处只留指针。**
>
> 出处：E2–E5＝本地约定（席位协作归纳）；「生产方不得兼判定方」＝业界通识（职责分离）；「最小权限」＝业界范式（least privilege）；「description 触发」＝业界范式。

## E1 干净度（复用五测·专家包专用判法）

| 测项 | 判法 |
|---|---|
| 项目实体 | 专家描述/提示词里不得出现项目名、号段、日期、人名、项目路径 |
| 触发描述 | 说明「什么时候该找这个角色」而非「属于哪个项目」；有职责同义词 |
| 出处 | 方法论类条款标三档出处；行业判据（法律/财务/医疗）须带行业标准出处，不得自造 |
| 真源方向 | 专家包＝角色方法论真源；项目参数由项目侧注入 |
| 体量 | 角色提示词主文件＜200 行；长清单进 references/ |

## E2 角色边界三栏（缺一即不合格）

| 栏 | 内容 | 缺栏后果 |
|---|---|---|
| 管什么 | 本角色的判定权/产出物（使命） | 无边界＝什么都管＝什么责任都不担 |
| 不管什么 | 明确禁区（不判定/不写盘/不入回执链） | 无禁区＝越权高发 |
| 对谁 | 上行给谁、下行给谁、能否并行 | 无接口＝消息乱飞或断链 |

**硬检查两条**：
- 生产方不得兼判定方（自证禁止）——同一角色既产出又判定＝阻断。
- **本体层决策权不得授予任何 AI 角色**：什么叫做完／合法值域／评估标准／范围边界，只能人类独占；AI 角色只有提案权。角色定义里出现「自行决定判据/验收标准/阈值放宽」＝阻断。

## E3 加载隔离（按需加载）

| # | 测项 | 判法 |
|---|---|---|
| E3-1 | 不被调用不占上下文 | 角色件只在触发时加载；常驻面只留一行路由 |
| E3-2 | 只加载自己那件 | 角色 A 的件里不得夹带角色 B 的操作细则（只可写「B 负责，见其件」） |
| E3-3 | 信息隔离声明 | 显式写「本角色不需要知道什么」（如执行角色不见讨论过程/未定方案） |

## E4 权限最小化

| # | 测项 | 判法 |
|---|---|---|
| E4-1 | 三类权限显式声明 | 写盘／执行／外发，各自「有/无＋写域」 |
| E4-2 | **单写者**（业界 single-writer principle） | 同一治理盘**有且只有一个**写盘角色（一般为执行席）；其余席位**永无写盘权**——不接受「默认无、项目可改」这类可开的口子。技术出处：多写者并行＝写冲突＋格式漂移＋无唯一责任主体 |
| E4-3 | 越权可被拒 | 有机制层拦截（投递带层级、写域校验、唯一出口），不靠自觉 |
| E4-4 | 落盘姿势自读（写盘角色专有） | 写盘角色的定义里须写明「落盘前自读项目治理规范，据此定归属／命名／路由／修订制」，不得凭印象落盘；缺＝关注（会产出格式对但不合规的件） |

**E4-2 的三个常见违反形态**：①两个角色都写同一目录（"各写各的子目录"也算，闭集被打散）②审计/验证角色以"证据"为由保留写权（证据应由写盘角色誊录，报告正文承载内容）③写权写成"默认无，项目可配"——配置项存在即会被打开。

## E5 自证与升级路径

- 角色产出须有独立判定方（不得自审）。
- 角色发现问题时的升级路径写死：「停手上报给谁」一句话；无升级路径＝角色会自行降标准。
- 角色不得自行扩权/扩范围（范围变更须拍板人）。

## 判定要点

- E2（边界）与 E4-2（单写者）不合格＝**阻断**：角色会越权生产、自证或制造写冲突。
- E1（干净度）不合格＝**关注**（以阻断为高风险，视使用面定级）：脏角色包会污染其所有输出。
- E3-3（信息隔离声明）缺＝**关注**，必带核验动作（下一轮抽检实际投递内容）。
