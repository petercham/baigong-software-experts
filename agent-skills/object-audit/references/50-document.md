# 文档对象审计（治理文档/台账/规范）

> 出处：D1–D6＝本地约定（文档治理归纳）；「append-only 与可精炼两制」＝业界范式（ADR supersede-not-edit／Git 不可变历史）；「指针不复制」＝业界范式（SSOT）；「归属声明」＝业界范式（provenance）。

## D1 归属可溯（缺一即不合格）

| # | 测项 | 判法 |
|---|---|---|
| D1-1 | 归属声明随身 | 文档头部一行：归属＋依据＋判据指针——文件离开目录树仍可溯源 |
| D1-2 | 头部＝内容 | 文件头的版本/状态声明与正文一致（抽验，不只看头） |
| D1-3 | 版本账对齐 | 头部版本＝版本史末条目；机检比对 |

## D2 单一真源

| # | 测项 | 判法 |
|---|---|---|
| D2-1 | 指针只指不搬 | 同一内容只在一处有正文，其余位置只放指针；复制正文＝新债 |
| D2-2 | 退役件注头 | 被取代的件头部写明「已被 X 取代」＋派生回指；正文不改（历史可读） |
| D2-3 | 无第二真源 | 同一规则不得在两份现行件里各写一遍（退役件不算） |

## D3 修订两制

| 制 | 适用 | 规则 |
|---|---|---|
| append-only | 台账/拍板记录/事实流水 | 不改写原句；勘误＝原文后注；正文不回改 |
| 可精炼 | 通用规则/方法论 | 正文可直接改写＋修订注记行留痕；实质变更走否决通道 |

- 勘误≠修订：事实性转录勘误走修订日志；实质变更须异议期。
- 归档件＝禁编辑·可读可链可恢复（业界范式：归档即冻结）。

## D4 准入四判据（防文档增殖）

新文档落盘前四问：①谁会读它（无人读＝不写）？②它驱动什么门/动作（零驱动＝进背景记录不进版本库）？③和既有哪份重叠（重叠＝并入不新开）？④交接物是闭集内哪一项（闭集外＝不产）？

## D5 体量与层

| # | 测项 | 判法 |
|---|---|---|
| D5-1 | 单件体量 | 常驻件＜上限、按需件＜上限（上限由项目 profile 注入） |
| D5-2 | 层级正确 | 方法论与项目值分层：通用方法论在通用层，项目取值在项目层；错层＝可移走性违例 |
| D5-3 | 索引路由 | 每层有索引；索引只路由不复写 |

## D6 引用完整性

- 所有内部指针所指目标存在（机检：指针悬空检查）。
- 引用史实件时标注「史实待核」桶，桶只减不增（shrink-only）。
- **指针 vs 提及（裁-21）**：指针＝意图解析到本仓目标的引用；**提及**＝被讨论的对象本身（泛指产物名、被论证的通用文件名、外部仓路径），不入悬空判定。机检口径：**带目录的完整路径＝指针**（解析不到即悬空，BLOCK）；**裸基名＝提及嫌疑**（降 WATCH，不 BLOCK——裸名歧义天然高，`COPY.state`／`INDEX.md`／`PLANS.md` 皆此类）。外部仓引用应在文中注明「外部仓」，未注明者照报。主观部分（论证语气）不留脚本，留人判。

| # | 测项 | 判法 |
|---|---|---|
| D6-3 | 交付包指针闭集 | 交付物（专家包/技能包/装配面）内一切指针（路径引用/编号引用/spec-provenance spec_file）只准包内闭环；出包指针（仓案面/.collab/*/盘符/家目录/不可解析案卷号）＝违例；`sources/`＝唯一可入料源自包，其内部指针同样不出包。豁免三范式沿用：扫描面收窄（只扫交付包面）／行级豁免标记〔史实锚〕＝EXEMPT／围栏与反引号段内示例＝SUBSTR 不计违规 |
| D6-4 | 交付包内指针可达性 | 交付包内反引号包裹的 `.md`/`.py` 相对指针（带目录段）须以**包根**解析可达，不可达＝违例（与仓内指针域检查不同：本项在包边界内解析——交付态无仓根结构，仓根语义必悬空）；裸基名循裁-21 降提及嫌疑不判 |
| D6-5 | 施工票声明闭集对账 | 票面声明文件闭集＝允许写入集；收口三段对账全链——commit↔回执（git name-only 全等）／回执↔票面声明（listing 全等）／回执↔交付面（文件系统 listing：声明集内路径存在性＋未声明生成件检出）。**基面分段刚性**：commit↔回执段只准 git 面（文件系统 listing 对不了此段），另两段只准文件系统面；全链以票面（`声明闭集：` 行）驱动，缺声明行＝SKIP 并计数、不算绿。豁免＝存量不回扫（事件锚复核挂升档呈拍/开工顺带核，不设日历期限） |

## D7 题目—内容吻合（标题承诺核验）

> 出处：本地约定（决策者 2026-10-22 点名「深入内容查看题目-内容吻合」）；「先盲预测再对照」＝与测试先行同构。

| # | 测项 | 判法 |
|---|---|---|
| D7-1 | 标题承诺兑现 | **先只读标题**写下「正文应有 X/Y/Z」，再读正文对照——承诺物无落点＝**空题**（标题党）。防"读着通顺"污染：不许先读正文再评标题 |
| D7-2 | 正文不越题 | 正文中与标题范围无关的成段内容＝**换题/嫁接**（多轮追加的常见产物：原题目对、正文塞了别的事）。处置＝拆件或改题，二选一写明 |
| D7-3 | 节级同检 | 每个 H2/H3 问一句「本节承诺什么、正文哪行兑现」——至少抽验最关键的三节 |
| D7-4 | 机检信号 | 标题核心名词在正文出现 0 次＝空题强信号（grep 可咬）；命中≠兑现，命中后仍走 D7-1 人验 |

## D8 归位正确（文档在不在对的目录）

| # | 测项 | 判法 |
|---|---|---|
| D8-1 | 内容域 vs 目录职责 | 所在一级子包的 README 边界声明（一句话）＝归位判据；内容域不在其内＝**错归**，处置＝git mv＋指针同步＋检查器复跑 |
| D8-2 | 层判定 | 换一个项目这条还成立吗？成立＝方法论层，不成立＝项目层——方法论件住项目层目录＝可移走性违例（同 D5-2，此处按目录逐件执行） |
| D8-3 | 性质判定 | 拿来照着做（规范件）还是查历史（记录件）——规范件住记录区／记录件混进规范区＝违例（规范区必须干净，记录区脏是职责） |
| D8-4 | 索引对账 | 文档被所在目录索引指到；索引无它＝孤儿（与 D6 悬空互为镜像：一个指空、一个无指） |

## D9 冗余扫描（冗余建档／冗余目录·事后核）

> D4 准入四判据是**事前门**（新件落盘前问）；本节是**事后核**（存量里揪出门立之前漏进来的）。

| # | 测项 | 判法 | 处置 |
|---|---|---|---|
| D9-1 | 空壳件 | 正文近零或纯指针（一个文件只装指针＝该并入指向方或升格为实质内容） | 并入或充实 |
| D9-2 | 无读者件 | 不被任何索引/指针引用＋不驱动任何门 → 删除**候选**。**禁 grep 零命中即删**——可能是人读入口，须指认「谁确认无人读」 | 指认后归档（不物理删） |
| D9-3 | 重复目录 | 两目录职责声明相同/高度重叠（README 边界一句话对撞） | 合并，留一个真源目录 |
| D9-4 | 内容重复 | 两份现行件大段重复（grep 重复段落可机检）＝D2-3 第二真源的机检面 | 留一处正文，其余改指针 |

## 判定要点

- D1-1 归属缺、D2-1 正文复制、D2-3 第二真源 ＝ **阻断**（文档失去可溯性或产生双真源）。
- D3 归档件被编辑＝**阻断**（历史被改写）。
- D5-2 错层＝**关注**（可移走性受损，必带迁移动作）。
- D4 准入未过仍在写＝**可延后**（带「并入/撤销」触发条件）。
- D7-1 空题、D7-2 换题＝**阻断**（读者按标题取用却被误导——比没标题更坏）；D7-3 节级抽验不过＝**关注**（带改题或拆件动作）。
- D8-1 错归＝**关注**（必带 git mv＋指针同步动作）；D8-2 方法论住项目层＝**阻断**（整包移走直接破）。
- D9-3 重复目录、D9-4 内容重复＝**关注**（带合并/改指针动作）；D9-2 无读者件＝**可延后**（须先指认"谁确认无人读"，禁 grep 零命中即删）。
- D6-3 出包指针＝**阻断候选**（交付态引用必悬空）；首挂期按机检表配 advisory，实跑零误报读数入 evidence 后升 block（升档＝改表属治理拍）。
- D6-4 包内指针不可达＝**阻断候选**（同 D6-3 通道：首挂 advisory，实跑零误报后改表升档）。
- D6-5 越集／缺声明不计绿＝**关注**（票面驱动型，首挂 advisory；升 block 同 D6-3 通道）。

> **D7–D9 是内容级测项**：D1–D6 靠 grep/计数大半可机检，D7–D9 必须**读正文**——机检只能给强信号（D7-4），判定仍要人验。治理面全绿而这三项没人做＝票面全绿本体没做的文档版（某票实证：29 项内容缺口全靠人眼逮）。
