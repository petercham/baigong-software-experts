# claim-commitment-governance · 主张—承诺治理

**定位**：本技能只在构建期提供「主张—来源—责任—验证—外发」五段语义契约；不替代调研类技能的调研，不替代审计类技能的审计，不执行任何业务判断，不建完整催办台账（需要完整台账时另案立项）。

**主类型**：D 纪律强制型（一条不许越的线，违反要被咬住）；附 F 参考查表（闭集值表、词表、抽取模式表）。D＋F 为合法混装，按 D 型测；混装合法性判据见 `references/40-provenance-map.md` 条目 2。

**锚的效力边界（不夸大）**：`SKILL.md` 首块 `spec-provenance` 的 `spec_anchor` 指向 `1859aca` 登记件的第 `一` 节标题行。`check-provenance` 只核该锚行存在且哈希现值未被改写，**不核该行以外的条款正文**。因此本技能只据此声明「锚行未被篡改」，不声明「该登记件支持本契约正文」——后者由 `references/40-provenance-map.md` 的逐条出处档与人工复核承担。

## 触发与不触发

**该触发（正路由样例，用户会这样说话）**

1. 「这份 PRD 里哪句话是客户真说过的，哪些是我们自己推的？」→ 触发。
2. 「这张工作票说要在真实环境验，能改成 Mock 吗？」→ 触发。
3. 「这封函发出去之前，谁审过、谁批过？」→ 触发。
4. 「交付汇总里哪些只是 Mock、哪些根本没验？」→ 触发。
5. 「这段是不是我们自己吹的、有没有注水？」→ 触发（判 `evidence_tag`）。
6. 「客户口头改了口径，我们照着改了，这算哪一层？」→ 触发（走来源层判定序；口头未成文的按第 6 步归 `internal_assumption` 并注明「未成文」）。
7. 「这份东西现在能不能发出去、谁批的？」→ 触发（外发门与 `authorization`）。

**不该触发（负路由样例）**

1. 「把这个函数改成异步」→ 不触发。
2. 「把这张表的行距调一下」→ 不触发。
3. 「现在几点」→ 不触发。
4. 「帮我把这份行业报告的证据链补齐」→ 不触发（调研本体不在本技能）。
5. 「这票现在该谁签字」→ 不触发（状态机流程不在本技能）。
6. 「把这段翻成英文」→ 不触发。

注：上组第 7 条「能不能发出去、谁批的」问的是**外发授权**，走本技能外发门；本组第 5 条问的是**票型与状态机节点**，不属本技能。二者不重叠。

## 术语别名（用户怎么说 ↔ 契约怎么叫）

| 这是事实还是猜的 | `evidence_tag` |
| 这话算不算数、能不能压人 | `authority` |
| 这件事定了没有、对外认了没有 | `status` |
| 这话能不能对外说 | `external_effect` |
| 这事谁担、谁拍板 | `accountable_party` / `decision_owner` |

| 少做的那部分谁批的 | `exemption` / `approver` |

## 契约总则

1. 一句一主张，一行一 `claim`。
2. 每行必须填满 17 项必填字段，并按条件填 3 项条件字段。
3. `linked_artifacts` 至少一条来源引用（`source:` 或 `cite:`）；`artifact:` 只能附加，不得单独充当来源。
4. 内部接受不等于外部确认。
5. 内部冻结只限内部、必须带时效与复核人，不得外溢为默认认可。
6. 替代实现、占位、降级必须写明要求环境与检查、实际环境与检查、豁免、回退判据与重开条件。
7. 外发件必须先过事实审查、承诺审查与人类授权；审查人不得为生成方，两名审查人不得为同一人。
8. 数量、时点、标识、完备性断言必须可跨件比对；同键不同值即判违例。
9. 机器只校验结构、闭集、可比对性与引用；不判业务真伪，不作法律或合同解释。
10. 状态只增不改，历史不回写。
